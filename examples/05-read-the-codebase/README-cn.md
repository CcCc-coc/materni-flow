# 从上往下读一遍这个仓库

> 读一个陌生代码库的正确顺序不是从第一个文件开始, 是先画地图, 再挑一条真实路径走一遍.

## 1. 概览

上一篇你把它跑起来了, 但对它的了解还停留在目录名. 这一篇要补上那张地图.

读陌生代码库最常见的错误是从上到下一个文件一个文件地读. 那样做的结果是读了两百个文件,
脑子里一条线都没有, 因为你不知道哪些文件重要, 也不知道它们之间的顺序.

有效的做法是两步. **第一步画地图**: 每个顶层目录归谁管, 它们之间谁依赖谁.
**第二步走一条真实路径**: 挑一个用户真的会做的动作, 从入口跟到出口, 沿途经过哪个文件就
读哪个文件.

这一篇就按这两步走. 走完你不会记住任何一个函数的实现, 但你会知道下次要改某个东西该打开
哪个文件. 那才是这一步该有的产出.

---

## 2. 学习目标

这张地图的价值不只是省时间. 这个仓库的边界划得比一般项目硬, 而
**边界清晰的仓库, 改动的形状本身就是一种检查**:
一次换数据集的 diff 应该只落在三个地方, 落到别处就是信号, 你不用逐行读也知道有东西越界了.

要看得懂这个信号, 前提是你先知道每一层归谁管. 而这件事在你和 AI 一起工作时价值翻倍: 界面
上所有文案都在一个文件里, 任务就是打开这个文件改; 文案散在二十个组件里, 任务就变成全仓库
搜一遍再判断哪些该改哪些不该, 而这件事每次都会漏, 而且漏得不报错.

学完这个 Task, 你将能够:

1. 说出每个顶层目录归谁管, 以及哪几个目录属于教学层
2. 描述前端两个页面各自服务哪种读者, 以及它们为什么不能合并成一个
3. 讲清后端那个 Python 包的分层, 以及 `one` 这个对象在其中的位置
4. 完整复述一次 `/api/chat` 请求经过的九步, 并指出每一步落在哪个文件里
5. 拿一条判据去判断一个新东西该放在哪一层

## 4. 你将学到什么

判据是这一篇最耐用的东西: **换个业务领域, 它要不要改?** 要改就归数据集, 不改就归脚手架.
答案是看情况的, 说明它其实是两个东西粘在一起了, 先拆开再放.

## 5. 地图: 每个目录归谁管

先按**它是应用的一部分, 还是教怎么造这个应用的一部分** 分成两半.

**属于应用的:**

| 目录 | 管什么 | 说明 |
| :--- | :--- | :--- |
| [`app/`](../../app) | Next.js 的路由和两个页面 | 网站上每一个能打开的网址都对应这里的一个目录. Next.js 约定用目录结构表示网址, 所以 [`app/chat/`](../../app/chat) 就是 `/chat` 这个页面. 这里只放页面骨架, 界面元素本身在 [`components/`](../../components) 里 |
| [`components/`](../../components) | React 组件 | 组件就是可以复用的界面积木: 一张卡片, 一个按钮, 一个聊天气泡. 页面负责把积木摆在一起, 组件负责每块积木自己长什么样. 整个对话界面就是这里一堆组件拼出来的 |
| [`lib/`](../../lib) | 前端的工具层 | 不直接画界面, 但界面需要的东西都在这里: 把文案文件读进来, 把图标名换成真正的图标, 生成搜索引擎要看的网页信息. 可以理解成前端的后勤部门 |
| [`data/`](../../data) | **会变的内容** | 这个目录里没有一行代码, 全是人写的字: 网站上每一句话, 首页那个长说明, 以及告诉 AI 这个行业怎么运转的那份文档. 换一个业务领域就是把这个目录重写一遍 |
| [`agent_app/`](../../agent_app) | 后端 Python 包 | 服务器上跑的那半边. 它连数据库, 把库结构讲给模型听, 调模型, 再把模型的回答整理成前端能显示的格式. 名字起得这么通用是一句承诺: 换数据集时这里一行都不用改 |
| [`api/`](../../api) | 部署产物 | 后端对外的那扇门, 只有一个文件. 它自己不做任何业务, 只是按顺序调用 [`agent_app/`](../../agent_app) 里的零件. 放在这里而不是包里面, 是因为 Vercel 规定要在 [`api/`](../../api) 目录下找入口 |
| `.env.defaults` | 非密钥配置 | 一个纯文本配置文件, 装着所有不算秘密的设置, 比如用哪家大模型, 数据库里那组表叫什么名字. 它进 Git, 所以每个人 clone 下来就有. 真正的密码在另一个文件里 |

**属于教学的:**

| 目录 | 管什么 | 说明 |
| :--- | :--- | :--- |
| [`examples/`](../../examples) | 你正在读的这些 Task | 每个编号目录是一课, 里面一份教学正文加一份验收清单. 它们只教你怎么造这个 app, 不参与 app 运行. 学完之后整个目录会被删掉 |
| [`dataset/`](../../dataset) | 源材料和数据生成器 | 四份描述这个行业的文档, 加一个能造出十几万行假数据的 Python 脚本. 数据库文件本身不进 Git, 因为跑一次脚本就能重新造出来 |
| [`scripts/`](../../scripts) | 编号的验证脚本 | 一批一次性的小工具, 按你第一次搭环境的顺序编号: 试试数据库连不连得上, 打印一下库结构, 挨个试试四家大模型的凭据. 出问题时用它们缩小范围 |
| `.claude/skills/` | 给 AI 和维护者看的规范 | AI 助手读的说明书, 讲这个仓库为什么长成这样, 哪条边界不能破. 它不是给终端用户看的文档, 所以交付前和教学材料一起删掉 |
| [`agent_app/dataset.py`](../../agent_app/dataset.py) | 造数据加同步数据库 | 唯一一个住在生产代码包里的教学文件. 它负责跑生成器, 再把造好的数据搬进云端数据库. 生产路径一行都不 import 它, 所以删掉不影响 app 运行 |

**删掉右边这一半, 左边仍然是一个能跑的 app**, 而且一行代码都不用改. 这条边界第 6 篇
(教学层和生产层) 会展开讲, 这里先知道它存在.

### 一条判据

往仓库里加东西之前问一句: **换个业务领域, 它要不要改?**

- 要改 -> 归数据集, 也就是 [`data/`](../../data) 或者 [`dataset/`](../../dataset)
- 不改 -> 归脚手架, 也就是 [`agent_app/`](../../agent_app) 或者前端那几个目录

还有一条正交的轴, 就是上面那个应用与教学的划分. 两条轴一起看, 一个新文件的位置基本就定了.

**最要紧的一条推论: [`agent_app/`](../../agent_app) 这个包名是故意起得通用的.** 它不叫
`smb_lending_anything`, 因为那个名字本身是一句承诺: 换数据集时这个包下面一行都不用改.

## 6. 前端: 两个页面, 两种读者

前端只有两个路由, 但它们服务两种完全不同的人.

| 路由 | 给谁看 | 它要回答的问题 |
| :--- | :--- | :--- |
| `/` | 陌生人: 面试官, 招聘方, 任何点开链接的人 | 这是干什么的, 这个行业有什么值得做的问题 |
| `/chat` | 使用者 | 我能问什么, 问了会得到什么形状的答案 |

这个划分不是网站惯例, 是这个项目的用途决定的. 它最终会被放进作品集里给人看, 而看它的人
**大概率不懂这个数据集所在的行业**. 一个直接把人扔进聊天框的产品, 对他们等于一个空白输入框.

所以首页的职责不是介绍功能, 是**把一个外行带到能提出第一个问题的位置**.

具体到文件:

| 文件 | 干什么 | 说明 |
| :--- | :--- | :--- |
| [`app/layout.tsx`](../../app/layout.tsx) | 根壳 | 包住整个网站的最外层, 每个页面都会经过它. 它定义 html 标签, 加载三种字体, 设置浏览器标签页的标题和分享出去时的预览信息 |
| `app/(marketing)/page.tsx` | 首页入口, 负责读盘 | 带括号的 `(marketing)` 是 Next.js 的路由分组, 只用来给一组页面套同一个外壳, 不会出现在网址里. 这个文件从磁盘读文案, 然后传给下层组件 |
| `app/(marketing)/_components/Hero.tsx` | 首页的全部内容 | 首页你看到的所有东西都在这一个文件里: 大标题, 副标题, 四张能力卡, 技术栈标签, 底部那个大按钮. 下划线开头的目录 Next.js 不会当成网址 |
| [`app/chat/page.tsx`](../../app/chat/page.tsx) | agent 页, 全文三行 | 只做两件事: 读文案, 交给对话组件. 真正复杂的东西都在组件里, 所以这个文件短到可以一眼扫完 |
| [`components/chat/chat.tsx`](../../components/chat/chat.tsx) | 对话界面的状态和布局 | 管着消息列表, 输入框, 加载状态这些会变的东西, 并负责把用户输入发到后端. 对话记录存在浏览器内存里, 刷新就没了 |
| [`components/chat/markdown.tsx`](../../components/chat/markdown.tsx) | 把文本渲染成表格和图 | agent 交回来的只是一段纯文本. 这个文件负责把它翻译成屏幕上的东西: 表格, 流程图, 柱状图, 高亮的 SQL |

`(marketing)` 带括号是 Next.js 的**路由分组**, 只是为了让两个页面各有自己的 layout, 不进 URL.

有一条规矩现在就该记住: **读盘的往上放, 有状态的往下放, 中间用 props 连.** 读
[`data/site.toml`](../../data/site.toml) 的那个函数碰文件系统, 所以只有 server component 能调它; 客户端组件通过
props 接收, 从不自己去读.

## 7. 后端: 一条从叶子到入口的链

[`agent_app/`](../../agent_app) 里的模块不是平摊的, 它们有一条明确的依赖顺序. 从下往上读不会遇到任何前向引用:

| 层 | 模块 | 说明 |
| :--- | :--- | :--- |
| 叶子 | `paths.py` `constants.py` `utils.py` | 谁都不依赖的最底层. 分别管: 所有文件路径集中一处, 几个多处共用的名词表, 两个小工具函数. 叶子的意思是它们不 import 项目里任何别的模块 |
| 叶子 | `sql_utils.py` | 跑 SQL 的一组纯函数. 纯函数指的是它不依赖任何类或全局状态, 数据库连接是当参数传进去的, 所以它单独拿出来也能用, 也好测 |
| 叶子 | `agent_response.py` | 模型说完话之后交回来的是一整串它自己的思考和工具调用记录, 不是一个干净答案. 这个模块负责从里面把思考和最终答案分开挖出来 |
| 第二层 | `config.py` `runtime.py` | 读两个配置文件, 并判断现在跑在你的笔记本上还是跑在 Vercel 上. 所有和环境有关的判断都收在这里, 别处只管取值 |
| 第二层 | `db_schema/` | 把数据库的表结构压成一段模型读得懂的紧凑文字. 直接把建表语句丢给模型太费 token, 压缩之后大约省七成 |
| 第二层 | `ai_sdk_adapter.py` | 前端和模型描述一段对话的格式不一样, 这个模块是唯一同时懂两边的翻译官. 进来的请求翻成模型要的形状, 出去的回答翻成浏览器要的形状 |
| 第三层 | `quota.py` | 月度花费上限. 默认关着, 只有公开部署时才需要, 因为那种场合掏钱的人和打字的人不是同一个 |
| 组装层 | `one/` | 把上面所有零件装成一个对象. 别处只写 `one.agent` 或 `one.engine`, 不需要知道这些东西是怎么一步步建起来的 |
| 入口 | [`api/index.py`](../../api/index.py) | 后端唯一对外的门. 它自己不做任何业务, 只是按顺序把上面那些零件串起来, 所以一百多行就读完了 |

`one/` 值得单独说一句, 因为它是这个后端唯一的**组装点**. 它是一个类, 由四个 mixin 拼成:

| 文件 | 提供什么 | 说明 |
| :--- | :--- | :--- |
| `one_01_config.py` | `self.config` | 提供配置对象. 别处写 `one.config.schema_name` 就能拿到值, 不用自己去读文件, 也不用关心是本地还是线上 |
| `one_02_db.py` | 引擎, 库结构, 查询方法 | 提供连数据库要用的那个对象, 那份压缩过的库结构文字, 以及一个只读地跑 SQL 的方法. agent 能查到数据全靠这一块 |
| `one_03_boto3.py` | AWS session 和 client | 提供连 AWS 的凭据和客户端. 只有选了 Bedrock 当模型后端, 或者打开了月度花费上限时, 才会真的用到 |
| `one_04_agent.py` | 模型, agent, `@tool` 方法 | 提供大模型对象, agent 本身, 和 agent 能调用的那几个工具. 你以后最常改的就是这个文件 |

编号就是加载顺序也是依赖顺序. 所有属性都是懒加载的, 所以 `import` 这个模块是免费的:
它不连数据库, 不建 AWS session, 不读提示词.

**你以后最常改的文件是 `one_04_agent.py`**, 因为给 agent 加一个工具就在那里.

## 8. 走一条路径: 一次提问的九步

前面几节是静态的地图. 这一节让它动起来: 用户在 agent 页打了一句话按下回车, 到屏幕上冒出
回答, 这中间到底发生了什么.

先给你一个心里的画面. **这九步很像一条流水线**: 东西从一头进来, 挨个经过几个工位, 从另一头
出去. 每个工位只干一件很窄的事, 干完就交给下一个, **没有哪个工位知道全局**.

### 先记四段, 别记九步

九步太碎了, 记不住也没必要记. 真正有用的是它们分成的四段:

| 哪一段 | 第几步 | 这一段在干什么 |
| :--- | :--- | :--- |
| **进门** | 1 到 3 | 把浏览器送来的那包东西收下, 拆开, 找出这一轮用户到底问了什么 |
| **准备** | 4 到 5 | 给 agent 装上记忆, 并且在花钱之前先看一眼还有没有预算 |
| **干活** | 6 | 真正调模型. agent 那个想一步, 动一次手, 看结果的循环就在这里 |
| **出门** | 7 到 9 | 记账, 从模型的回复里挖出要的东西, 编码成浏览器认得的格式发回去 |

看出这四段的顺序有多朴素了吗? **收东西, 做准备, 干活, 收尾.** 你安排任何一件事都是这个
顺序. 后端代码在这一点上并不比生活复杂.

### 九步各自落在哪个文件

| 步 | 在哪 | 干什么 |
| :--- | :--- | :--- |
| 1 | `ai_sdk_adapter.py` | 把浏览器发来的那包数据收下来, 顺便记一条日志 |
| 2 | [`agent_app/vendor/vercel_ai_sdk.py`](../../agent_app/vendor/vercel_ai_sdk.py) | 把那包数据解析成 Python 对象 |
| 3 | `ai_sdk_adapter.py` | 从消息列表里取出这一轮用户真正问的那句话 |
| 4 | [`api/index.py`](../../api/index.py) | 把 agent 的记忆清空, 再灌入前端送来的完整历史 |
| 5 | `quota.py` | 在花钱之前检查这个月的用量有没有超上限 |
| 6 | `one_04_agent.py` | 真正调模型 |
| 7 | `quota.py` | 按这一轮真实用掉的 token 数记账 |
| 8 | `agent_response.py` | 从模型交回来的整串消息里, 挖出思考和最终答案两样东西 |
| 9 | `ai_sdk_adapter.py` | 把答案编码成一段事件流发回浏览器 |

有一个细节值得留意: **`ai_sdk_adapter.py` 出现了三次**, 第 1, 3, 9 步. 那是因为它就是这条
流水线的门口 —— 进来要经过它, 出去也要经过它. 第 14 篇
([AI SDK 协议](../14-the-ai-sdk-protocol/README-cn.md)) 会专门讲这个文件.

打开 [`api/index.py`](../../api/index.py) 对着读一遍, 全文只有一百六十行, 而且
**它自己不做任何业务**, 只是把上面这些零件按顺序串起来. 一个把别人串起来而自己不干活的
文件, 通常就是一个系统的主干.

### 第 6 步里面还套着一个循环

那一行表格里写的是真正调模型, 但那一步内部才是 agent 这个词的含义所在:

模型先调一个看库结构的工具, 弄清楚有哪些表; 再调一个跑 SQL 的工具, 把查询发出去; 拿到
结果之后, 它可能发现自己 SQL 写错了, 于是改一下再试一次; 全都顺利了才开口回答.

**想一步, 动一次手, 看结果, 再想.** 这个循环由 strands 这个框架驱动, 第 22 篇
(你的第一个 agent) 会讲.

### 这条路径上有好几个决定是踩出来的

下面这几处, 换个写法程序照样跑, 但会**静默地出错或者多花钱**. 这一栏最值得看的是最右边:

| 哪一步 | 那个决定 | 不这么做会怎样 |
| :--- | :--- | :--- |
| 1 | 日志里 authorization 这类敏感请求头要打码 | 这些日志在线上是留存的, 等于把凭据抄了一份存起来 |
| 2 | 解析故意很宽松, 只对真的要读的字段较真 | 前端库升级多送一个字段, 后端就开始拒绝合法请求 |
| 4 | 每次都把 agent 的记忆清空再灌历史 | agent 对象是跨请求活着的, **第二个用户会读到第一个用户的对话** |
| 6 | 期间把 stdout 临时顶掉 | 线上打到 stdout 的东西会混进发给浏览器的字节里 |
| 7 | 记账要取这一轮的用量, 不是累计量 | 计费会按平方级膨胀 |
| 8 | 最后一条消息不一定就是答案 | 挖错了, 用户看到的是一段内部内容 |

看第 4 行. 每次都清空再重灌, 直觉上是很浪费的 —— 明明上一轮的东西还在, 为什么要扔掉重来?
**因为省下的那点开销, 换来的是两个用户的对话串台.** 这类取舍在后端代码里到处都是, 而它们
共同的特征是: **做错了不会报错.**

第 28 篇 (一次 chat 请求) 会把这几个决定逐个讲清楚. 现在你只需要知道这条路径长什么样,
以及**它上面每一处看起来多余的动作, 背后大概率都有一次事故.**

## 9. 三条贯穿全仓库的规矩

读代码的时候如果发现有些写法很固执, 通常是下面三条之一在起作用.

**一, 组件里不出现业务文案.** 界面上说的每一句话都在 [`data/site.toml`](../../data/site.toml) 里, 组件只负责摆放,
不负责拼句子. 这条被破坏过一次的代价是聊天页的欢迎语在屏幕上印了两遍, 而且测试全绿.

**二, 通用代码里不出现本数据集的表名.** 注释和测试 fixture 一律用虚构领域, 比如 `acme`,
`widget`, `part`. 一个断言真实表名的测试在换数据集之后不会失败, 它只是变成一句谎话.

**三, 代码不引用教学文档.** 这条是单向的: 教学文档可以随便引用代码路径, 代码一律不引用
教学文档. 一条指向教学材料的注释在擦除之后既不报错也不失败, 只是变成一句死链躺在成品里,
而且明明白白写着这个项目是从一门课里长出来的.

## 10. 练习

### 练习 1: 亲手走一遍那九步

**目标:** 把地图变成一条你自己跟过的路径.

**怎么做:**

1. 打开 [`api/index.py`](../../api/index.py), 找到 `handle_chat_data` 这个函数.
2. 从上往下读, 每遇到一个从别的模块 import 来的调用, 就跳到那个文件看一眼函数签名和
   docstring, 然后跳回来. 不要陷进实现细节.
3. 在纸上或者一个临时文件里, 按顺序写下你经过的每个文件名.
4. 和上面第 8 节那张表对一遍, 看有没有漏掉的.

**你会观察到:**

这个入口文件几乎没有任何逻辑, 它只有顺序. 所有真正做事的代码都在别的模块里.

> **关键洞见:** 一个健康的 HTTP 入口文件应该是可以一口气读完的. 一旦它开始知道两个以上
> 模块的内部细节, 那段代码就该搬回它属于的那个模块.

### 练习 2: 用判据给五个东西找位置

**目标:** 把判据用起来, 而不是记住.

**怎么做:**

对下面五样东西, 各回答一句它该放哪个目录, 理由必须是那条判据:

1. agent 页那个输入框的 placeholder 文字
2. 一个把日期格式化成三天前这种说法的辅助函数
3. 这个数据集里隐含违约率这个词的精确定义
4. 一个新的 LLM provider 的接入代码
5. 造假数据时给每个风险等级分配利率区间的那段逻辑

然后去仓库里找到它们真实的位置, 对答案.

**你会观察到:**

第 3 个和第 5 个最容易搞混. 一个是写给模型看的领域知识, 一个是造数据的代码, 它们描述同一
件事但住在两个不同的目录里, 而且换数据集时都要重写.

> **关键洞见:** 换领域要不要改这条判据只能告诉你它属于数据集还是脚手架. 数据集内部还要
> 再分一次: 它是人写的内容, 还是造数据的代码.

## 12. 导师寄语

**为什么这一步不能省:**

很多人接手一个项目的方式是等到要改某个功能时才去找相关文件. 这样做在小项目里没问题, 在
一个分了层的项目里会持续踩坑: 你会把东西加在第一个看起来能放的地方, 而那个地方通常在错
误的一层.

花一个小时先建立地图, 换来的是后面每一次改动都知道手往哪儿放. 这笔账在第三次改动时就回本了.

**关键洞见:**

- 地图的价值不在于记住文件名, 在于知道每一层的边界在哪
- 边界清晰的仓库, 改动的形状本身就是一种检查, 不用逐行读也知道有没有越界
- 一个 HTTP 入口文件应该只有顺序, 没有业务. 它一旦开始知道模块内部, 那段代码就放错了

地图里有一半目录被标成了教学层. 第 6 篇 ([教学层和生产层](../06-teaching-and-production/README-cn.md)) 专门讲那条边界: 为什么擦掉教学
痕迹必须退化成删几个目录, 以及支撑这件事的四条约束分别在防什么.
