# 那一个对象: `one`

## 1. 目标

整个后端只有一个对象. 任何一个文件想要配置, 想要数据库连接, 想要 agent, 都是同一句
`from agent_app.api import one`.

而它的定义短得可以整个抄下来: **一个类声明加一个实例, 两行真正的代码.**

**这一篇的核心是一个模式: 用到才建, 建了就记住.** 它一次解决三个问题 —— 不用每次重建 (慢),
不用启动就全建好 (那样要先配齐凭据), 也不用到处传参数 (那样加一样东西要改一路的签名).

最实际的好处你已经受益很久了: **这个项目 269 个测试一个都不联网**, 不是因为测试写得特别
小心, 是因为**默认什么都不建** —— 一个只要配置的测试, 不会顺手拖出一个数据库连接.

**练习 2 值得认真做.** 你会强行让数据库引擎提前建出来, 然后把数据库地址改坏, 看整个脚本在
第一行就死掉. 那正是如果不用到才建会发生的事: 任何一个 import 了 `one` 的文件都会在导入时
崩溃, 包括那些根本不碰数据库的测试.

这一篇也会讲全局单例的**代价**, 而不是只讲好处. 那三条批评是成立的, 这个项目只是把它挡在了
一层薄壳上.

## 2. 要做的事情

1. 读完 README, 重点是第 2 节那三种做法的问题, 和第 8 节那三条代价.
2. 开一个叫 `29-the-one-object` 的 branch.
3. 跑 `01_what_gets_built.py`, 对着输出回答刚导入时建了几样, 读一次配置之后建了几样.
4. 打开 `agent_app/one/` 下那四个编号文件, 每个花两分钟, 只看它提供了什么.
5. 画一张四个抽屉之间的依赖图.
6. 在每个文件里搜 `self.`, 验证你画的对不对.
7. 确认没有任何一个箭头是从编号大的指向编号小的.
8. 打开 `one_00_main.py`, 数一数真正的代码有几行.
9. 打开 `one_03_boto3.py`, 找出哪个是建一次记住的, 哪些是每次新建的, 读注释里的理由.
10. 在脚本里强行提前碰一次 `one.engine`, 再跑, 看第一份快照有什么不同.
11. 把 `.env` 里的 `DB_HOST` 临时改成一个不存在的地址, 再跑, 看它在哪一步失败.
12. 全部还原 (脚本那一行和 `.env`), 再跑一次确认正常.

**预计用时:** 50 到 80 分钟

## 3. 检查清单

- [ ] **用到才建看到了**: 你跑过脚本, 知道刚导入时一样都没建, 读一次配置之后只建了配置.
- [ ] **它解决了哪三个问题**: 你能说出每次重建, 启动就全建, 到处传参数各自的毛病.
- [ ] **和测试的关系**: 你能说清 269 个测试不联网和默认什么都不建之间的因果.
- [ ] **四个抽屉**: 你画过依赖图, 能说出每个 mixin 管什么, 并确认箭头只从编号大的指向小的.
- [ ] **组装点有多大**: 你数过 `one_00_main.py` 真正的代码行数.
- [ ] **客户端为什么是方法**: 你能说清会话和服务客户端的区别, 判据落在这东西大概率会被用到吗.
- [ ] **提前建的代价见过**: 你强行提前碰过引擎并把地址改坏, 见过脚本在第一行就死掉, 也能说清
      如果导入时就全建好会波及到谁.
- [ ] **三条代价说得出**: 状态共享, 测试要小心, 依赖隐形; 并能说清这个项目分别是怎么处理的.
- [ ] **工作区干净**: 脚本里加的那一行和 `.env` 的改动都还原了.
