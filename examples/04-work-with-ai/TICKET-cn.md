# 学会和 AI 一起改这个仓库

## 1. 目标

这一篇讲的不是 prompt 技巧, 是**仓库这一侧要准备什么**. 同一个模型, 同一句话, 在两个不同的
仓库里效果能差出十倍, 差的不是模型是仓库.

具体要弄明白四件事: 为什么不能让 AI 每次干活前把代码读一遍, 它进门先读到什么, 它被允许碰
什么, 以及你该怎么派活.

中间那件事有一个反直觉的结论: **正确的做法不是把知识推给它, 是让它自己来取.** 这个仓库把
三十多篇项目文档写在一个 skill 的 `ref/` 目录下, 而那个 skill 的入口文件本身几乎没有内容,
只是一张我要做什么就读哪篇的表. 这个形状值得你亲手打开看一眼, 因为它就是 agent 和 chatbot
区别的另一个面孔.

**这一篇排在所有动手内容的最前面.** 后面每一篇都会让你把没看懂的东西交给 AI 去问, 所以那把
工具得先到手.

**它最容易被读成整洁度说教, 那就白读了.** 它给的是一个可以当场用的验收手段: 改完先看改动
落在哪几个文件, 落点不对就不用读内容了. 这个检查在你读一行代码之前就能给出结论.

**这一篇不需要装依赖, 不需要起服务器, 也不需要任何账号.**

练习 2 有一处要特别注意: 让 AI 去读 `.env` 是**为了看它被拦住**, 不是为了拿到里面的值. 如果
它真的读出来了, 那说明权限配置出了问题, 停下来检查, 别继续.

---

## 2. 要做的事情

1. 读完 README, 重点是为什么不能让 AI 把代码库读一遍那一节, 那个 skill 是一张索引那一节,
   和派活三步那一节.
2. 打开 `CLAUDE.md` 扫一遍它的一级标题, 再打开 `AGENTS.md` 对比长度, 想清楚为什么后者这么短.
3. 打开 `.claude/skills/about-bi-agent-app-scaffold-cn/ref/`, 数一数它下面分成哪四块, 每块
   大概有几篇, 随便挑一篇读开头, 确认它讲的是这个仓库为什么长成这样.
4. 回到那个 skill 的 `SKILL.md`, 找到开头那张按任务查的表, 确认它本身是路由而不是内容,
   并在表里挑一行, 顺着它指的路径打开那一篇.
5. 打开 `.claude/settings.json`, 读 deny 名单, 数清它拒绝了哪几个文件的哪几种操作.
6. 确认工作区是干净的 (`git status --short`), 然后加载 `/about-bi-agent-app-scaffold-cn`.
   这一篇的改动改完立刻还原, 所以不用开 branch.
7. 派一个改一句界面文案的小任务, 明确要求它**先出计划再停下来**, 不要直接动手.
8. 读它给的计划, 确认它只打算改一个文件; 如果它提出要改组件, 把它指回那份 skill.
9. 让它动手, 然后跑 `git diff --stat` 看落点, 再跑一次 `git diff` 确认它改的就是那一句文案.
10. 还原改动, 让工作区回到干净状态.
11. 让 AI 去读 `.env` 里的某个值, 看它被拦住; 再让它读 `.env.defaults` 里的 `SCHEMA_NAME`,
    对比两次的差别.

**预计用时:** 60 到 90 分钟

## 3. 检查清单

- [ ] **两笔成本**: 你能说出不让 AI 把代码库读一遍省下的是哪两笔, 并解释为什么第二笔比
      第一笔更麻烦.
- [ ] **skill 的形状**: 你打开过 `ref/` 目录, 能说出它分成哪四块; 也打开过 `SKILL.md`, 能说
      清它开头那张表才是主体, 内容在被指向的那一篇里.
- [ ] **两个 skill 的分工**: 你能说清什么时候加载 about 那个, 什么时候加载 learn 那个.
- [ ] **和 agent 定义的关系**: 你能解释读文件也是调工具这句话, 以及它和第 2 篇里 chatbot
      与 agent 的区别是同一件事.
- [ ] **deny 名单读过**: 你能说出哪几个文件被无条件拒绝, 以及为什么读和写都要拒绝而不是只
      拒绝写.
- [ ] **派活先要计划**: 你派任务时要求过它先出计划, 并且是在看过计划之后才让它动手.
- [ ] **落点验收过一次**: 你跑过 `git diff --stat`, 确认改动只落在 `data/site.toml`, 并且
      能说清落到组件里意味着什么. 这一步全程不用起服务器.
- [ ] **撞过一次权限墙**: 你见过 AI 读不了 `.env`, 也见过它能读 `.env.defaults`, 并能说清
      这条线是配置写死的而不是靠 AI 自觉.
- [ ] **工作区干净**: 练习做完之后 `git status` 没有留下未还原的改动.
