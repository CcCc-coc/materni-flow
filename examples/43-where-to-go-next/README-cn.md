## 1. 概览

你走完了. 一个能用大白话查数据库的 agent, 一个讲清业务的网站, 一条从数据集到公网地址的
完整链路, 而且你亲手把它的业务领域整个换过一次.

**这一篇不复述目录.** 你刚读完四十二篇, 不需要有人再把标题列一遍.

## 5. 这门课其实在讲四件事

四十二个 Task 读下来, 骨架只有四条. 它们和主题的划分不是一一对应的, 而是横穿在里面.

**第一件: 会变的东西要集中在一个地方, 不变的东西要承诺不被碰.**

界面上每一句话在一个文件里, 领域知识在一个提示词里, 数据在一个目录里, 而后端那个包承诺换
数据集一行不改. 你在第 37 篇亲手验过这个承诺 —— 那个 `git diff --stat` 里的零, 是这条主线
唯一的成绩单.

**第二件: 最危险的错误是不报错的那些.**

这句话在这门课里出现了太多次, 你数得过来: 换到一半的数据集会全程撒谎, 渲染契约缺一半图就
不出来, 提示词里一句写错的 SQL 会被模型照抄, 补一套永远渲染不出来的暗色变体, stdout 混进
响应流. **它们的共同点是没有任何东西会红.**

**第三件: 能让错误不可能发生的时候, 就别满足于让它可被发现.**

检查是发现问题, 顺序是消灭问题. 首页那四张能力卡合成一份数据, 而不是写两份加一个比对;
换数据集用一条串行推导链, 而不是并行写完再校验; 三个解析步骤绑成一个函数, 而不是让调用方
自由组合.

**第四件: 判断该写在哪一层, 比写得对更重要.**

只读该靠事务回滚还是关键词黑名单, 校验该在构造那一刻还是第一次用到时, 配额坏了该放行还是
拒绝, 严格校验该用在进来那一侧还是出去那一侧 —— 这些没有一个是语法问题, 全是位置问题.

## 6. 几个忘了别的也不能忘的概念

| 概念 | 一句话 |
| :--- | :--- |
| **agent 和 chatbot** | 差别是有没有工具, 以及模型能不能在回答途中决定去调它们 |
| **工具说明就是接口** | 那段文字的读者是模型, 改一句说明就是改一次接口行为 |
| **只读靠回滚** | 安全边界是那个永远不 commit 的事务, 不是那句开头检查 |
| **三步单向** | 反射, 建模, 编码. 没有任何东西往回流, 所以每一层都能单独测 |
| **模型无状态** | 对话是你自己在存, 所以状态必须有一个明确的家 |
| **用顺序代替检查** | 每一步只从上一步的产物推导, 于是漂移没有机会发生 |
| **跨语言的约定没有编译器** | 渲染契约的三半住在散文, 配置和代码里, 谁也管不着谁 |

**如果只能留一条, 留最后那一条.** 你以后做的任何一个稍微复杂点的系统, 都会长出这种跨边界
的约定, 而那时候你有三条路: 造一个检查, 造一个顺序, 或者写下来指望别人会读.

## 7. 那两个收尾环节各自证明了什么

它们看起来都是收尾, 但证明的是两件完全不同的事, 而且缺一件都不够.

**第 41 篇那五十道题证明的是你真的懂.**

它模拟的是 walkthrough 之后的追问. 判据不是你答得出定义, 是你答得出**为什么不是另一种做法** ——
只读为什么不用黑名单, 工具为什么只给三个, 配置为什么不按环境切.

**第 42 篇那份底稿证明的是你讲得出来.**

懂和讲得出来是两种能力. 很多人东西做得很好, 一开口就散了: 从代码讲起, 讲了十分钟对方还不
知道这玩意儿解决什么问题. 那份底稿里开场五分钟的顺序是固定的, 就是为了防这件事 ——
**先让对方看见结果, 再回头看它为什么成立.**

**这两样合起来才是一个可以拿出去的作品.** 只有前者, 你在面试里是个答题机器; 只有后者,
第一个追问就穿.

## 8. 你现在具体多了什么

不是感觉上的, 是列得出来的:

- 你能从零把一个前后端同仓库的项目部署到公网, 并且说得清哪些配置跟着 git 走, 哪些必须手填
- 你能把一个陌生行业的业务材料整理成一份数据字典, 再蒸馏成一个 agent 的领域知识
- 你能判断一个 agent 的工具该怎么切, 说明该怎么写, 以及安全边界该放在哪一层
- 你能在几个小时之内把这整套东西换成另一个行业, 并且知道那个换得成立是靠什么撑住的
- 你能对着别人把这件事讲清楚, 并且接得住追问

**最后一条最容易被低估**, 而它往往是前面所有东西能不能兑现的唯一通道.

## 9. 这门课刻意没覆盖的六块

下面每一块**这个项目都没有做**, 而且是有意没做的 —— 做了这门课就不止四十二篇了.

它们和第 40 篇 ([从这里往下挖的八条路](../40-go-deeper-by-role/README-cn.md)) 不是一回事:
那一篇讲的是**按你的岗位往哪个方向深挖**, 这一节讲的是**这个脚手架本身缺哪几块**.

**一, 从零造一份数据集和业务背景**

> 这是第 39 篇和第 40 篇反复指过去的那个模块. 你换过数据集, 但那份新数据集是现成的 ——
> 从零造出那五份源文档和一个能跑出合理数据的生成器, 是一门独立的手艺.
>
> **搜索关键字**: `synthetic data generation`, `data dictionary`, `entity relationship modeling`
>
> **喂给 AI 的一句话**: 我要为某个行业从零设计一份十张表左右的合成数据集, 请先帮我列出这门
> 生意的核心业务实体和它们之间的关系, 再告诉我哪些字段需要埋进可学的规律.

**二, 怎么评测一个 agent 答得好不好**

> 这个项目里判断 agent 答得对不对, 靠的是你自己点开看一眼. 那在演示时够用, 在改提示词或者
> 换模型之后就完全不够了 —— 你没有任何办法确认这次改动是变好了还是变差了.
>
> **搜索关键字**: `LLM evaluation`, `eval dataset`, `LLM as a judge`, `regression testing for prompts`
>
> **喂给 AI 的一句话**: 我有一个会写 SQL 的数据分析 agent, 想给它建一套评测, 让我每次改
> 提示词之后能知道有没有变差. 请告诉我评测集该怎么设计, 以及哪些东西是自动判不了的.

**三, 多用户与鉴权**

> 现在这个应用没有登录, 没有用户概念, 所有人看到的是同一个数据库. 一旦要给不同的人看不同
> 的数据, 整个链路都要重新想一遍 —— 包括 agent 能查哪些表.
>
> **搜索关键字**: `row level security postgres`, `multi tenancy`, `OAuth`, `session management`
>
> **喂给 AI 的一句话**: 我有一个让用户用自然语言查数据库的应用, 现在要加多用户, 而且不同
> 用户只能看到自己的数据. 请告诉我权限该卡在哪一层, 以及为什么不能只靠提示词.

**四, 成本与延迟**

> 这个项目只有一道月度花费上限, 那是保险丝, 不是优化. 真正让一个 agent 又快又便宜, 是另
> 一整套东西: 缓存策略, 模型分级, 把简单问题拦在调模型之前.
>
> **搜索关键字**: `LLM cost optimization`, `semantic caching`, `model routing`, `streaming latency`
>
> **喂给 AI 的一句话**: 我的 agent 每次回答都要先取库结构再写 SQL, 又慢又贵. 请给我几种
> 降低成本和延迟的思路, 并说清每一种会牺牲什么.

**五, 结构化之外的数据**

> 这个 agent 只会查表. 而真实业务里一半的信息在合同, 邮件, 会议纪要这些非结构化的东西里,
> 那需要完全不同的一套检索机制.
>
> **搜索关键字**: `RAG`, `vector database`, `embedding`, `hybrid search`, `chunking strategy`
>
> **喂给 AI 的一句话**: 我有一个只会查 SQL 的 agent, 想让它也能回答来自 PDF 合同的问题.
> 请告诉我这两种检索该怎么共存, 以及 agent 怎么决定该用哪一种.

**六, 提示词的版本管理与回归**

> 这个项目的提示词就是一个 Markdown 文件, 改了就是改了, 没有版本, 没有回归. 而提示词是这
> 整个应用里最容易被随手改坏, 又最不会报错的东西.
>
> **搜索关键字**: `prompt versioning`, `prompt registry`, `A/B testing prompts`, `observability for LLM apps`
>
> **喂给 AI 的一句话**: 我的 agent 领域知识全写在一个 Markdown 提示词里. 请告诉我怎么给它
> 加版本管理和回归测试, 让我能对比两个版本的表现而不是凭感觉.

## 11. 练习

### 练习 1: 用四句话把这门课说给别人听

**目标:** 检验你脑子里剩下的是一条线, 还是四十二个标题.

**怎么做:**

1. 不看第 5 节, 自己先写下这门课在讲哪几件事, 有几条写几条
2. 写完再回去对第 5 节那四条
3. 对每一条, 从课里找出**至少两个** 具体的例子撑住它
4. 找不出两个例子的那一条, 回去把对应的篇再扫一遍

**你会观察到:**

第一遍多半写不满四条, 而且写出来的往往是主题的名字 (前端, agent, 部署) 而不是主线.
**那正好说明这个练习有用** —— 主题是内容的分类, 主线是贯穿其中的判断.

第 3 步那个找两个例子的要求是关键: 一条你举不出例子的原则, 在面试里也讲不出来.

> **关键洞见:** 判断自己学没学透, 最快的办法不是复述, 是**举例**. 复述靠记忆, 举例靠理解.

### 练习 2: 挑一块, 把第一步问出来

**目标:** 让六选一这件事落到一个你这周就能做的动作上.

**怎么做:**

1. 从第 9 节那六块里挑一块, 判据用第 10 节那条 (哪一块你下次做东西一定会撞上)
2. 把那一块的搜索关键字扔进搜索引擎, 扫五分钟, 只为确认这个领域大概长什么样
3. 把那一块给的那句话原样喂给 AI, 跟它聊到你能说出**第一步该做什么**
4. 最后回答一句: 这一步做完之后, 有什么东西会变得可以被观察到

**你会观察到:**

第 2 步那五分钟经常会改变你的选择 —— 有些方向听起来很有意思, 扫一眼发现不是你现在需要的.
**这五分钟很值**, 它比一头扎进去三天再放弃便宜得多.

第 4 步答不上来, 说明那一步还不够具体. 这个判据你在第 40 篇见过, 它在这里同样成立.

> **关键洞见:** 一个方向变成一个动作, 中间差的就是那句第一步做什么. 大多数人的往下学止步
> 于收藏了一堆链接, 而不是止步于难.

## 13. 导师寄语

**走到这里, 最想跟你说的一句是:** 你现在手上这个东西, 价值不在它本身.

它是一台机器. 你可以把它放在 GitHub 上从此不动, 那它就是一个作品 —— 挺好的一个, 但仅此
而已. 你也可以每次真的想去一家公司, 就花一个下午让它长出那家公司的样子.
**这两种用法的差别, 比这门课教的任何一项技术都大.**

**关于那六块没覆盖的, 也说一句.** 我把它们单独列出来, 不是为了显得这门课很谦虚, 是因为
**知道自己没做什么, 本身就是一种可以被听出来的专业素养**. 面试里最能唬住人的不是把做过的
吹大, 是被问到边界的时候答得出这一层我没做, 原因是这样.

**最后.** 这门课花了四十二篇讲一个反复出现的句式: 坏了不报错. 如果几年之后你把具体的东西都
忘光了, 只剩下写代码时多问一句它坏的时候会怎样 —— 那这门课的钱就已经赚回来了.

**关键洞见:**

- 主题是内容的分类, 主线是贯穿其中的判断. 记主线, 忘主题没关系
- 懂和讲得出来是两种能力, 而后者往往是前者能不能兑现的唯一通道
- 知道自己没做什么, 和知道自己做了什么一样值钱
- 一个方向变成一个动作, 差的就是那句第一步做什么

**下一步:**

课到这里结束了. 真要说还有一步, 那就是**把教学痕迹擦掉, 让这个仓库变成你自己的作品** ——
`examples/` 这些目录, 还有几份教学文档, 都是为了教你而存在的, 它们的使命到此为止.

擦完之后剩下的那个东西, 是你的.

## 14. 速查

2. 最危险的错误是不报错的那些
3. 能让错误不可能发生时, 别满足于让它可被发现
4. 判断该写在哪一层, 比写得对更重要

**没覆盖的六块, 以及在这个仓库里就能开始的那三块:**

| **提示词版本管理与回归** | **可以, 对着提示词那个文件做** |

**挑方向的判据:** 不是哪一块最重要, 是哪一块你下次做东西的时候一定会撞上.
