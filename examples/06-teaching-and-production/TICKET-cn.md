# 看懂教学层和生产层的那条边界

## 1. 目标

这一篇解释第 5 篇那张地图上的一条线: 为什么这个仓库把教学材料整块关进几个目录里.

答案落在一个具体时刻上: 你把这个仓库当作品交出去, 读它的人变成面试官. 那一刻仓库里的验收
清单和讲什么是 mixin 的 docstring, 会把这个项目从我做的产品降级成我上过的课. 所以要擦, 而
擦得干不干净, 完全取决于两层分得有多开.

**这一篇最容易被当成理论课.** 它不改功能, 不加特性, 读起来像是在讲整洁. 但它讲的其实是一个
很具体的取舍: 让未来那个动作是删几个目录, 还是打开每个文件逐行判断. 前者零风险且可验证,
后者一定会删漏.

它还有一件实际的事要你当场做完: **从这一篇开始, 动手之前先从基线开一个 branch.** 你手上这个
仓库灌完数据就是完整能跑的, 那个能跑的状态就是你的退路. 后面每一篇都默认你在一个自己的
branch 上折腾, 而不是直接在基线上改.

所以这一篇的两个练习都要真的动手, 尤其第一个: ** 不亲手把那条测试弄红一次, 你不会相信它真的
在拦.**

---

## 2. 要做的事情

1. 读完 README, 重点是你手上这个仓库已经是成品那一节, 两种分法那张对比表, 和四条约束那一节.
2. 从这门课住的那个 branch 开一个属于自己的 `dev` branch, 后面所有动手都在它上面做.
3. 跑一次 `git diff` 对比自己的 branch 和基线, 确认现在没有差异.
4. 打开 `tests_python/test_dataset.py`, 翻到最后那个 `TestNotOnTheProductionPath`, 读一遍它
   是怎么用 `ast` 扫 import 的.
5. 跑一次那条测试, 确认现在是绿的.
6. 在 `agent_app/one/one_02_db.py` 的 import 区加一行, 让它 import 教学层那个模块.
7. 再跑一次那条测试, 读失败信息, 确认它报出的正是你刚改的那个文件.
8. 把那一行删掉, 再跑一次确认恢复绿.
9. 在 `agent_app/` 和 `api/` 里搜索提到 `.claude/skills` 的地方, 找出两处, 逐一判断擦除之后
   它会不会变成死链.
10. 打开 `mise.toml` 扫一遍全部 `run =`, 确认没有一条指向 `scripts/`.
11. 打开 `dataset/requirements.txt` 和 `pyproject.toml` 对比一下, 确认生成器那几个依赖只
    出现在前者里.

**预计用时:** 60 到 85 分钟

---

## 3. 检查清单

- [ ] **基线与 branch**: 你能说清 clone 下来的这个仓库为什么已经算成品, 搞砸之后有哪三条
      退路; 而且 `git branch` 看得到你自己那个 branch, 你现在就在它上面.
- [ ] **两种分法说得清**: 你能说出混在一起和分层各自在擦除那一刻要做什么动作, 以及为什么
      只有后者可验证.
- [ ] **教学层清单**: 你能列出至少六条属于教学层的路径, 并说出删掉它们之后剩下的是什么.
- [ ] **四条约束**: 你能复述那四条约束, 并对其中至少三条说出破坏之后会怎样; 其中两条你还
      去验过, 确认了 `mise.toml` 里没有任务指向 `scripts/`, 生成器的依赖也只在
      `dataset/requirements.txt` 里.
- [ ] **测试红过一次**: 你亲手加过那行 import, 见过测试变红, 也见过它报出你改的那个文件,
      然后改回来恢复绿.
- [ ] **为什么用 AST**: 你能说清这条测试为什么解析语法树而不是搜字符串.
- [ ] **两处指针分得清**: 你找到了那两处提到教学路径的地方, 并能说清哪一处属于规范说的例外,
      哪一处会跟着成品交付出去.
- [ ] **判据会用**: 给你一个新加的东西, 你能用它是 app 的一部分还是教怎么造 app 的一部分,
      判断它该放哪儿.
