# 看懂纯文本怎么变成表格和图

## 1. 目标

前面几篇里, 屏幕上的东西都能用三步法搜到源头. 但 agent 的回答搜不到, 因为它
**不在任何文件里**
, 是每次现生成的.

那么一段纯文本怎么变成了带边框的表格, 画好的流程图, 带坐标轴的柱状图? 这一篇讲那个转换,
而它比你想的短: **一行代码**.

**这一篇最值得带走的不是那一行, 是一条反直觉的性质**: agent 的回答是一个字一个字流过来的,
所以在写完之前, 页面上一定存在一个没闭合的代码围栏. 对这一层来说这不是边缘情况, 是每一次
画图的必经状态. **于是解析失败不是异常, 是正常路径.**

理解了这一点, 你才看得懂这几个组件为什么长成那样, 也才知道以后自己做流式功能时该先想什么.

练习 1 要你盯着屏幕看那半秒, **别跳过**. 这件事讲一百遍不如亲眼看一次.

---

## 2. 要做的事情

1. 读完 README, 重点是失败是正常路径那一节, 和加一种新块那三步.
2. 起开发服务器打开 agent 页, 点一个徽章是流程图的按钮, **盯着回答区域**, 看图出现之前那
   半秒显示的是什么.
3. 没看清就再点一个出图表的按钮, 那个通常更明显.
4. 再点一个出表格的按钮, 对比表格的出现过程和图有什么不同, 想清楚为什么.
5. 打开 `components/chat/markdown.tsx`, 找到那个管代码的自定义组件, 认出它是怎么分清行内
   代码和围栏块的.
6. 打开 `components/chat/blocks/index.ts`, 看那张查找表现在有几行.
7. 想清楚那张表为什么不放进 `data/site.toml`, 判据用换个业务领域它要不要改.
8. 对比一下第 11 篇那个按钮上的 `render` 字段和这张查找表, 说清哪一个才真正让块出现.
9. 确认自己在一个属于自己的 branch 上, 加载 `/about-bi-agent-app-scaffold-cn`, 问它加一种
   新的块渲染器要动哪些文件, 明确要求先不要动手.
10. **重点检查它有没有提到 `data/system-prompt.md`.** 没提就追问一句: 只改前端的话这个渲染器
    会被调用到吗.
11. 拿三步法验证它说的每个文件路径真的存在.

**预计用时:** 60 到 90 分钟

---

## 3. 检查清单

- [ ] **亲眼看过降级形态**: 你盯着看过至少一次图出现之前那半秒, 能说出那时候屏幕上是什么.
- [ ] **表格为什么不一样**: 你能说清表格的出现过程和图有什么不同, 以及为什么表格是免费的.
- [ ] **分发点找得到**: 你能指出那段文本变成块的分发点在哪个文件, 以及它靠什么区分行内代码
      和围栏块.
- [ ] **查找表的作用**: 你能说清加一行和删一行各意味着什么, 以及没在表里的语言会怎样.
- [ ] **它为什么归代码**: 你能用换个业务领域它要不要改这条判据, 解释那张表为什么不进文案文件.
- [ ] **徽章和查找表分得清**: 你能说出这两样各自是什么, 以及哪一个才真正让块出现.
- [ ] **失败是正常路径**: 你能解释为什么这一层的解析失败不是异常, 以及为什么失败还必须是
      局部的.
- [ ] **两个渲染器的取舍**: 你能说出一个按需加载第三方库, 一个手写 SVG, 各自的理由是什么.
- [ ] **第三步验过**: 你问过 AI 加一种新块要动哪些文件, 并检查了它有没有提到后端那份提示词;
      你也能说清跳过那一步会怎样.
