# 看懂纯文本怎么变成表格和图

## 1. 目标

前面几篇里, 屏幕上的东西都能用三步法搜到源头. 但 agent 的回答搜不到,
因为它**不在任何文件里**, 是每次现生成的.

那么一段纯文本怎么变成了带边框的表格, 画好的流程图, 带坐标轴的柱状图? 这一篇讲那个转换,
而它比你想的短: **一行代码**.

**这一篇最值得带走的不是那一行, 是一条反直觉的性质**: agent 的回答是一个字一个字流过来的,
所以在写完之前, 页面上一定存在一个没闭合的代码围栏. 对这一层来说这不是边缘情况, 是每一次
画图的必经状态. **于是解析失败不是异常, 是正常路径.**

理解了这一点, 你才看得懂这几个组件为什么长成那样, 也才知道以后自己做流式功能时该先想什么.

练习 2 用一个你完全控制得了的地方来验这件事: **首页那份长说明走的是同一个渲染器**, 而它是
一个你想怎么改就怎么改的文件. 先塞一个合法的图表围栏看到图, 再故意违反一条规则看它退回
原始 JSON. 这件事讲一百遍不如亲手做一次.

---

## 2. 要做的事情

1. 读完 README, 重点是失败是正常路径那一节, 和加一种新块那三步.
2. 打开 `components/chat/markdown.tsx`, 找到那个管代码的自定义组件, 认出它是怎么分清行内
   代码和围栏块的.
3. 打开 `components/chat/blocks/index.ts`, 看那张查找表现在有几行.
4. 想清楚那张表为什么不放进 `data/site.toml`, 判据用换个业务领域它要不要改.
5. 对比一下第 11 篇那个按钮上的 `render` 字段和这张查找表, 说清哪一个才真正让块出现.
6. 加载 `/about-bi-agent-app-scaffold-cn`, 问它加一种新的块渲染器要动哪些文件, 明确要求
   先不要动手.
7. **重点检查它有没有提到 `data/system-prompt.md`.** 没提就追问一句: 只改前端的话这个渲染器
   会被调用到吗.
8. 拿三步法验证它说的每个文件路径真的存在.
9. 开一个叫 `12-render-text-into-blocks` 的 branch, 下面几步都在它上面做.
10. 在 `data/business-context.md` 末尾加一个合法的图表围栏, 重启开发服务器, 在首页那个讲行业
    背景的覆盖层里看到那张图.
11. 把那段 JSON 的 `values` 改成和分类数量对不上, 重启再看; 再把 `type` 改成一个不支持的值,
    重启再看. 两次都应该退回显示原始 JSON, 而页面其它部分完全正常.
12. 把那段整个删掉, 确认覆盖层恢复原样.

**预计用时:** 60 到 90 分钟

---

## 3. 检查清单

- [ ] **亲手触发过退回**: 你在那份长说明里塞过图表围栏, 见过它出图, 也见过两种违规输入各自
      退回显示原始 JSON, 而页面其它部分完全正常.
- [ ] **那条数量规则**: 你能说清为什么值的数量必须等于分类数量, 以及少一格会画出什么.
- [ ] **表格为什么不一样**: 你能说清表格为什么是免费的, 以及它和图在解析上有什么根本区别.
- [ ] **分发点, 查找表与徽章**: 你能指出那段文本变成块的分发点在哪个文件, 它靠什么区分
      行内代码和围栏块; 也能说清查找表和按钮上那个徽章各自是什么, 哪一个才真正让块出现.
- [ ] **它为什么归代码**: 你能用换个业务领域它要不要改这条判据, 解释那张表为什么不进文案文件.
- [ ] **失败是正常路径**: 你能解释为什么这一层的解析失败不是异常, 以及为什么失败还必须是
      局部的.
- [ ] **两个渲染器的取舍**: 你能说出一个按需加载第三方库, 一个手写 SVG, 各自的理由是什么.
- [ ] **第三步验过**: 你问过 AI 加一种新块要动哪些文件, 并检查了它有没有提到后端那份提示词;
      你也能说清跳过那一步会怎样.
- [ ] **工作区干净**: 练习改的每一处都恢复了, `git status` 没有留下改动.
