# 认识这门课要造的东西

## 1. 目标

这是整门课的第一篇正文, 不写代码, 也不装任何东西. 它要让你在动手之前先明白两件事: 我们
要造的是什么, 以及为什么这件事的重心不在技术上.

**这一篇有一条最容易被忽略的红线: 读完不算完.** 它有一个必须交出来的产物, 就是你自己选定
的目标岗位和那三个业务问题. 那份文件会一直跟到这门课的最后, 第 35 篇和第 36 篇那两次换
领域的时候拿它当验收标准. 现在跳过, 到那时候你会卡在一个完全不该卡的地方: 不知道要换成
什么.

选行业这件事没有标准答案, 但有一条判据: 你得说得出这门生意的钱从哪儿进来, 以及做分析的
人每周在为哪几个数字发愁. 说不出来就换一个你更熟的行业, 不要硬撑.

---

## 2. 要做的事情

1. 读完这个 Task 的 README, 重点是讲 chatbot 与 agent 区别的那一节, 和讲脚手架的那一节.
2. 打开 `agent_app/one/one_04_agent.py`, 找到那三个带 `@tool` 的方法, 确认它们和 README
   里那张工具表对得上.
3. 挑一个你真的会申请的岗位, 具体到公司, 写下它靠什么赚钱.
4. 写下这家公司里做分析的人每周真的会问的三个问题, 每个问题都必须跨至少两类数据才回答得了.
5. 把上面这四样存成 `tmp/my-target-domain.md`, 那个目录不进 Git, 所以可以放心写.
6. 扫一遍 `data/site.toml`, `data/business-context.md` 和 `data/system-prompt.md`, 感受一下
   换领域要重写多少内容.
7. 随便打开一个前端组件和一个后端模块, 在里面找一句跟放贷有关的话, 确认找不到.

**预计用时:** 45 到 70 分钟 (只读不做约 25 分钟)

## 3. 检查清单

- [ ] **agent 的定义**: 你能说清 agent 比 chatbot 多出来的那一步是什么, 并能点出这个仓库里
      承载它的那三个 `@tool` 方法.
- [ ] **多表的理由**: 你能举出一个必须跨两张以上的表才回答得了的问题, 并说清为什么它值得
      用 agent 而不是一张现成报表.
- [ ] **产品是什么**: 你能解释为什么这门课真正的产品是脚手架, 而不是它当前长成的样子.
- [ ] **边界的位置**: 你能说出换一个业务领域要改哪几个目录, 以及哪两个目录承诺一行都不改.
- [ ] **目标已选定**: `tmp/my-target-domain.md` 存在, 里面写着一个具体公司, 一句话说清它
      怎么赚钱, 以及三个业务问题.
- [ ] **问题够格**: 那三个问题每一个都跨至少两类数据, 没有一个是单表就能查出来的计数.
- [ ] **教学层的存在**: 你能说清这个仓库里为什么会有一堆和产品无关的教学材料, 以及它们
      最后会怎么消失.
