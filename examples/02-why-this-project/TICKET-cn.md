# 认识这门课要造的东西

## 1. 目标

这是整门课的第一篇正文, 不写代码, 也不装任何东西. 它要让你在动手之前先明白三件事: 我们
要造的是什么, 为什么它每一块都只做一丢丢, 以及为什么这件事的重心不在技术上.

**先记住一句话: 这个项目本身已经够硬了, 但更值钱的是它故意留了很多口子.** 软件工程,
AI, 数据工程, 数据分析, 机器学习, 每一个方向都能在里面找到自己那一块, 而且那一块是可以
一直往下挖的. README 第 1 节那张表就是这五个方向各自的入口, 读的时候**先找到你自己那一行**.

**这一篇有一条最容易被忽略的红线: 读完不算完.** 它有一个必须交出来的产物, 就是你自己选定
的目标岗位和那三个业务问题. 那份文件会一直跟到这门课的最后, 第 35 篇和第 36 篇那两次换
领域的时候拿它当验收标准. 现在跳过, 到那时候你会卡在一个完全不该卡的地方: 不知道要换成
什么.

选行业这件事没有标准答案, 但有一条判据: 你得说得出这门生意的钱从哪儿进来, 以及做分析的
人每周在为哪几个数字发愁. 说不出来就换一个你更熟的行业, 不要硬撑.

---

## 2. 要做的事情

1. 读完这个 Task 的 README. 第 1 节和第 2 节是这一篇的重头, 慢慢读; 第 4 节回答的是为什么
   偏偏选了报表 agent 这个形态.
2. 对照第 1 节那张表, 找出你自己属于哪一类人, 以及那一块现在做到了什么程度.
3. 打开 `agent_app/one/one_04_agent.py`, 找到那三个带 `@tool` 的方法, 确认它们和 README
   里那张工具表对得上.
4. 挑一个你真的会申请的岗位, 具体到公司, 写下它靠什么赚钱.
5. 写下这家公司里做分析的人每周真的会问的三个问题, 每个问题都必须跨至少两类数据才回答得了.
6. 再写一句你自己属于哪一类人, 以及打算往哪个方向挖.
7. 把上面这五样存成 `tmp/my-target-domain.md`, 那个目录不进 Git, 所以可以放心写.
8. 扫一遍 `data/site.toml`, `data/business-context.md` 和 `data/system-prompt.md`, 感受一下
   换领域要重写多少内容.
9. 随便打开一个前端组件和一个后端模块, 在里面找一句跟放贷有关的话, 确认找不到.

**预计用时:** 50 到 80 分钟 (只读不做约 30 分钟)

---

## 3. 检查清单

- [ ] **五个方向找得到自己**: 你能指出自己属于哪一类人, 那一块在这个项目里现在是什么样,
      以及往下挖大概要动什么, 不用动什么.
- [ ] **为什么是报表 agent**: 你能说清一个项目跟一个行业绑定得最紧的东西是数据, 以及这个
      形态为什么搞不了虚的.
- [ ] **agent 的定义**: 你能说清 agent 比 chatbot 多出来的那一步是什么, 并能点出这个仓库里
      承载它的那三个 `@tool` 方法.
- [ ] **产品是什么**: 你能解释为什么这门课真正的产品是脚手架, 而不是它当前长成的样子,
      并能说清一个只在自己电脑上躺着的项目为什么在面试里等于不存在.
- [ ] **边界的位置**: 你能说出换一个业务领域要改哪几个目录, 以及哪两个目录承诺一行都不改.
- [ ] **目标已选定**: `tmp/my-target-domain.md` 存在, 里面写着一个具体公司, 一句话说清它
      怎么赚钱, 三个业务问题, 以及你打算往哪个方向挖.
- [ ] **问题够格**: 那三个问题每一个都跨至少两类数据, 没有一个是单表就能查出来的计数.
- [ ] **教学层的存在**: 你能说清这个仓库里为什么会有一堆和产品无关的教学材料, 以及它们
      最后会怎么消失.
