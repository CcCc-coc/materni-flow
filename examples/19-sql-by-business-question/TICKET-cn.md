# 用业务问题学 SQL

## 1. 目标

上一篇你知道了有哪些表. 这一篇换方向: **不从表出发, 从一个人真的会问的问题出发.**

`dataset/` 里那份 SQL 文档有二十个查询, 但它不是语法教程 —— 它更像一份工作交接, 每一道题
都以一个真实业务问题开头, 而且在给出 SQL 之前先有一整段**解题思路**.

**那一段是这份文档最值钱的地方**, 因为看懂答案不等于写得出来. 你缺的从来不是语法, 是从
模糊问题走到具体查询中间那一步翻译.

**所以这一篇只有一条方法论, 而且它很硬: 读到解题思路结束就停, 把 SQL 盖住, 自己先写一遍.**
写不出来就写到卡住为止, 那个卡住的位置才是你真正要学的东西.

练习 2 要你**亲手把违约率算错三次**. 一定要做, 因为三种错法里有一种特别值得记住: 它算出
来的数字看起来完全正常. 这一篇最重要的直觉就是 **错得离谱是运气好, 错得刚好合理才要命**.

最后还有一个伏笔要记住: **这二十个查询是对着 SQLite 写的, 而 agent 查的是 PostgreSQL.**
第 15 篇会讲这个项目怎么从根上解决它.

---

## 2. 要做的事情

1. 读完 README, 重点是五段式那一节和两个不报错的坑.
2. 开一个叫 `19-sql-by-business-question` 的 branch.
3. 打开 `dataset/` 里那份 SQL 文档, 先看查询索引那张表, 找出四道基础题.
4. 挑一道基础题, 读到解题思路结束就停, 盖住 SQL 自己写一遍.
5. 把你写的粘进 `02_run_any_sql.py` 的 `QUERY` 里跑一次, 再和文档的答案对比.
6. 换一道中等难度的, 重复第 4 到 5 步.
7. 挑一道进阶的, 允许写不出来, 但要写下你卡在哪一步.
8. 跑 `01_pricing_gap.py`, 记下每个等级的实际违约率和定价缺口.
9. 把那个查询里的 `LEFT JOIN default_event` 改成 `JOIN`, 再跑, 看违约率变成什么.
10. 改回去, 把两处 `100.0` 都改成 `100`, 再跑, 仔细看 Grade C 那一行.
11. 再改成先除后乘的整数写法, 跑第四次.
12. 全部还原, 确认结果和第 8 步一致.
13. 打开那份文档最后的备注, 找出它列的那几个 SQLite 专属函数.

**预计用时:** 70 到 110 分钟

## 3. 检查清单

- [ ] **盖住答案写过三次**: 你至少自己写过一道基础题, 一道中等题, 并试过一道进阶题.
- [ ] **卡点写下来了**: 那道进阶题你写下了自己卡在哪一步, 而不是直接看答案过去.
- [ ] **翻译三问**: 面对一个业务问题, 你能说出碰哪些表, 聚合到什么粒度, join 往哪个方向.
- [ ] **招牌问题跑通了**: 你跑过 `01_pricing_gap.py`, 记得 Grade C 的实际违约率和定价缺口
      大概是多少.
- [ ] **INNER JOIN 的后果**: 你亲手改过并见过违约率变成 100%, 能说清分母被换成了什么.
- [ ] **整数除法的三种结果**: 你跑过那两种整数写法, 能说出为什么先乘后除只砍小数而先除后乘
      全变成零, 也能说清为什么砍掉小数那一种比另外两种危险得多.
- [ ] **CTE 什么时候用**: 你能说清那道进阶题为什么用 CTE, 理由要落在给中间结果起名字上.
- [ ] **方言问题**: 你能说出至少两个 SQLite 专属函数, 并说清它们进了系统提示词会怎样.
- [ ] **工作区干净**: 练习里改过的脚本都还原了.
