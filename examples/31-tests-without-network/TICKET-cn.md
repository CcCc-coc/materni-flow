# 看懂一套不连网的测试

## 1. 目标

这个仓库连着一个云上的 PostgreSQL, 调 AWS 的 DynamoDB, 还要跟一个大模型说话. 而它全部
Python 测试跑完只要两秒多, **一个网络请求都不发**.

这一篇讲这是怎么做到的. 但它教的**不是怎么写测试**, 是一个更前面的问题:
**被测的东西依赖一个你控制不了的外部世界时, 你怎么办.**

**练习 1 的重点不是跑通, 是那个证明方式.** 你会把整个进程的网络掐断再跑全套, 因为读代码
只能证明你没看见连网的地方, 掐断网络才能证明确实没有. 这个思路以后你想确认任何一件我以为
没发生的事都用得上.

**这一篇有两条判据要带走**, 它们比手段本身耐用:

- 一行代码够不够格打上不计入覆盖率的标记:
  **需要一台这里没有的机器, 或者根本写不出有意义的断言.** 懒得测不算
- 一条规矩值不值得写成测试: **能被机械判断, 而且破了会静默地坏**

**这一篇的脚本不需要任何凭据, 不需要数据库, 也不需要联网**, 那正是它要证明的事.

**卡住了别硬扛.** 把三样东西一起给 AI: 你在读哪一篇的路径, 你敲的那条命令, 以及
**终端打出来的原文** (整段复制, 不要截图, 不要只说一句报错了).

---

## 2. 要做的事情

1. 读完 README, 重点是第 6 节三类依赖三种手段, 和第 9 节那条打标记的判据.
2. 跑 `mise run test-python`, 记下用例数和耗时.
3. 跑 `.venv/bin/python examples/31-tests-without-network/01_cut_the_network.py`, 确认在网络
   被掐断的情况下同样全绿.
4. 打开那个脚本, 找到它掐网络的那几行, 说清它换掉了什么.
5. 跑 `mise run cov`, 看最后那张覆盖率表, 找出唯一一个不到 100% 的模块, 想清楚它为什么是
   例外.
6. 打开 `tests_python/db_schema/` 下的测试, 找出它是怎么在不连任何数据库的情况下拿到一份
   库结构的.
7. 打开 `tests_python/test_quota.py`, 找到它用 moto 的那几行, 说清用真实现比手写假对象多
   验到了什么.
8. 跑 `grep -rn "pragma: no cover" agent_app/`, 挑三处出来, 各判断它属于哪一类.
9. 按 README 练习 2 那张表, 对六个假想情况各判断一次该不该打这个标记.
10. 找到那条用语法树扫 import 的测试, 说清它守的是哪条规矩, 以及为什么这条规矩靠人自觉
    守不住.

**预计用时:** 50 到 80 分钟

---

## 3. 检查清单

- [ ] **亲手证明过**: 你在网络被掐断的情况下跑完了全套测试并看到全绿, 也能说清这个证明方式
      为什么比读一遍测试代码有说服力.
- [ ] **三类依赖三种手段**: 你能说出数据库, AWS, 大模型分别被换成了什么, 以及每一种选择的
      依据是什么.
- [ ] **真实现和假对象**: 你能说清手写的假对象为什么可能和代码一起错, 以及用真实现白捡的
      那两件事分别是什么.
- [ ] **需要真外部世界的事**: 你能说出这个仓库把它们放在哪儿, 并解释为什么不塞进 pytest.
- [ ] **覆盖率读得对**: 你能说清覆盖率只统计执行过没有, 以及一个 100% 的模块为什么仍然可能
      没被真正测到.
- [ ] **打标记的判据会用**: 对那六个假想情况你都给出了判断, 并能说清第二条和第五条长得很像
      但答案不同, 差在删掉它会不会让代码更危险.
- [ ] **那条守边界的测试**: 你找到了它, 能说清它守的是哪条规矩, 以及它为什么用语法树扫
      import 而不是跑任何业务代码.
- [ ] **什么规矩该写成测试**: 你能复述那条判据, 并举出这个仓库里除了它以外的另一个例子.
