# 首页要把一个外行带到能提第一个问题的位置

> 首页的职责不是介绍功能. 它要解决一个很具体的问题: 一个完全不懂这行的人, 怎么从零走到
> 能提出第一个问题.

## 1. 概览

先说这一篇为什么值得认真读.

回到第 2 篇 (这个项目是什么) 那个场景: 你把这个仓库换成自己那个行业的样子, 部署上线, 把
链接发给面试官. **他点开之后看到的第一屏, 就是首页.**

而他有很大概率**不懂这个行业**. 他可能是个招聘的, 可能是个后端工程师, 可能只是随手点开
链接看一眼. 对这些人来说, 一个直接把人扔进聊天框的产品, 等于一个空白输入框: 他不知道能问
什么, 也不知道问出来的答案有什么用, 于是三秒钟就关掉了.

所以首页有一份很硬的活: **把一个外行带到能提出第一个问题的位置.**

这一篇讲它是怎么做到的. 和第 8 篇 (从看得见的东西找到看不见的代码) 一样, 它不教你写 React,
教的是**这几块东西为什么长成这样**, 以及换领域时你要重写哪几段.

---

## 2. 学习目标

首页最难的部分不是好看, 是**让外行看懂**, 而这件事有一个具体的障碍.

这个 app 的四条业务主线叫这些名字: Risk Pricing, Portfolio Concentration, Early Warning
Signals, Customer Lifecycle Value.

这四个名字**对做放贷的人极其精确, 对其他所有人等于没写**. 这就是所有专业领域的通病: 越是
准确的术语, 越是只有已经懂的人才读得懂. 而首页的读者恰恰是不懂的那些人.

**这个矛盾不能靠把术语改成大白话来解决**, 因为术语本身是有价值的: 它准确, 而且面试官如果
正好是这行的, 他要看到的就是那个词. 所以真正的解法是**分层**, 而这一篇一半的篇幅在讲那个
分层怎么设计.

学完这个 Task, 你将能够:

1. 说出首页必须做到的四件事, 以及每一件对应屏幕上哪一块
2. 解释能力卡为什么是三层结构, 以及每一层写给谁看
3. 说清那个解释气泡为什么必须有三种打开方式, 以及它在手机上会遇到什么问题
4. 解释为什么那四张卡在两个页面上必须用同一个组件同一份数据
5. 为你自己那个目标行业写出四条合格的能力卡

## 4. 你将学到什么

一张首页的设计说明, 加一份你自己那个行业的四条能力卡.

带走的那个理念是: **对内行精确的词, 对外行等于没写.** 解法不是删掉术语, 是在它后面接一层
白话, 再接一层解释.

---

## 5. 首页必须做到的四件事

这四件不是网站惯例, 是这个项目的用途倒推出来的.

**一, 用一句话说清这是什么.** 大标题, 副标题, 一段介绍, 三层递进. 三层都是文案文件里的字段,
组件只负责摆.

**二, 把四条业务主线讲成外行能懂的话.** 这是首页最难的部分, 下一节整节在讲.

**三, 留一个入口讲完整的行业背景.** 一段话装不下一门生意. 但它也不值得占一个网址, 更不能
把底下那个行动召唤挤到屏幕外面去, 所以做成了一个覆盖层.

**四, 让人知道背后是真数据.** 表数和行数写在页面底部那一行. 这一句摆在读者判断这个 demo
有多真的位置, 所以它必须是**数出来的**, 不能是估的. 一个差着一倍的行数比不写更糟.

对着屏幕核对一遍, 你会发现首页上每一块都在服务这四件事里的某一件. 没有纯装饰的东西.

---

## 6. 能力卡的三层结构

四张卡, 每张三层, 每一层写给不同的人.

| 层 | 字段 | 写给谁 | 说明 |
| :--- | :--- | :--- | :--- |
| 概念名 | `title` | 内行 | 比如 Risk Pricing. 准确, 而且如果面试官正好是这行的, 他要看到的就是这个词 |
| 一句白话 | `subtitle` | **陌生人先读到的是这句** | 比如每个风险等级的定价, 有没有覆盖住它真实产生的损失. 不用行话, 一句话说清这个概念买到了什么 |
| 两三句解释 | `tooltip` | 想再往里一层的人 | 鼠标停上去, 键盘聚焦, 或者手机上点一下才出现. 把这个概念的来龙去脉讲完 |

**关键在第二层.** 一个陌生人的视线路径是: 先看到那个他不认识的词, 眼睛往下一行, 然后要么
懂了继续看, 要么放弃关掉. 所以 `subtitle` 这一句是**唯一有机会留住他的东西**.

### tooltip 里不许再有黑话

这是这三层唯一的一条硬规矩, 也是最容易破的一条.

用一个内行词去解释另一个内行词, 是这个字段存在的意义所反对的那件事. 写完之后拿去问一个
完全不懂这行的人, 他读完还是不懂, 那这段就白写了.

对照一下现在这四条里的一条, 讲组合集中度的那条大意是: 集中度就是放出去的钱有多少压在同一个
行业上. 它要紧, 是因为同一行的贷款会一起坏, 所以餐饮业过一个坏年头, 每一笔餐饮贷款同时中招.
**没有人会决定要变得集中, 它是一次次审批累积出来的.**

注意它没有用任何一个需要另外解释的词, 而且最后那句话是一个外行也能记住的洞察.

### 卡片底下那条虚线短横不是装饰

它是**唯一在告诉读者这里有东西可以看** 的东西. 去掉它, 那个提示就变成隐形的, 而一个没人知道
可以打开的解释等于不存在.

## 7. 那个解释气泡

`ConceptTooltip` 这个组件不大, 但它解决了两个真问题.

### 三种打开方式, 缺一不可

| 入口 | 谁在用 |
| :--- | :--- |
| 鼠标悬停 | 桌面用户. 这是最显而易见的那种 |
| 键盘聚焦 | 用键盘导航的人, 以及读屏软件的用户 |
| 点一下 | **手机用户** |

**只做悬停的话, 手机用户和键盘用户一个都用不了.** 而手机用户很可能占一半以上.

另外它还监听了退出键关闭, 并且用 `aria-describedby` 把气泡和卡片关联起来, 这样读屏软件会
把解释**和它解释的东西一起读出来**, 而不是把它孤零零地留在阅读顺序的后面某处.

### 手机上气泡会跑出屏幕

这是一个只有真的在手机上打开才会发现的问题.

手机上四张卡排成两列, 而气泡比一张卡宽. 居中对齐在宽屏上是对的, 在手机上会让外侧那一列的
气泡**跑出屏幕边缘**. 所以外侧的卡片让气泡贴着自己的外边缘挂, 屏幕宽到能排四列时两种对齐
都回退成居中.

还有一个细节: 气泡设了不接收鼠标事件. 它绝不能挡在指针和卡片之间, 否则鼠标穿过气泡离开卡片
时, 气泡会闪烁着关掉又打开.

**这两处都属于那种不亲手在手机上试一次就想不到的问题.** 这也是为什么换完领域之后, 手机上
过一遍是必须的.

---

## 8. 那个覆盖层: 一段话装不下一门生意

首页能承载一个标题和一段话. 它承载不了一整个行业.

而一个不懂这行的读者**没有办法判断 agent 的答案是干什么用的**. 他看到一张表格, 上面写着
各个风险等级的实际违约率, 然后呢? 这个数字高了低了意味着什么, 谁会为它睡不着觉?

那个覆盖层放的就是补上这个缺口的两三屏, 正文来自 `data/business-context.md`.

### 三个值得注意的决定

**关闭方式给得很宽**: 关闭按钮, 点背景, 退出键, 三个都行. 但**点面板内部不关闭**. 后者听
起来像个显然的想法, 直到你在滚一份长文档时它从你手底下消失.

**打开时锁住背后页面的滚动**, 并把焦点移进面板. 这样退出键和方向键落在这里, 而不是落在下面
那一页上.

**正文走的是 chat 页那同一个 Markdown 渲染器.** 所以在那份文档里写一个 mermaid 围栏, 覆盖层
里就真的会画出一张图, 而这个覆盖层组件**完全不知道图这个概念存在**. 那个渲染器怎么工作,
第 12 篇 (一段文本怎么变成表格和图) 会讲.

## 9. 一份数据, 两处渲染

这一节讲的是这一篇里最值得带走的一个工程判断.

**首页那四张卡, 和 agent 页欢迎卡里那四张, 是同一个组件读同一份数据.** 只差一个紧凑模式的
开关, 因为 agent 页地方小.

这不是省事, 是**防漂移**.

它以前不是这样的. 以前是两份配置各自描述这四条主线, 而它们**已经漂了**: 第二条主线在首页
上叫组合集中度, 在 agent 页上叫组合健康度, 配的图标不一样, 而且解释气泡只有一边有.

关键在于这种漂移**不会有任何测试失败**, 因为两边各自都是合法的配置. 只有同时打开两个页面
对着看的人才会发现, 而没有人会这么干.

> **一份数据两处渲染, 漂移在结构上就不可能发生. 一份数据两份配置, 漂移是迟早的事.**

这条判断在这个仓库里反复出现. 你以后设计任何东西, 只要发现两个地方在描述同一件事, 就该停
下来问一句: 它们能不能合成一份.

## 10. 换领域时首页要重写什么

落回主线. 换一个业务领域, 首页要动的全部在 `data/site.toml` 里:

| 段 | 屏幕上是什么 | 重写的难度 |
| :--- | :--- | :--- |
| `[home.headline]` `[home] tagline` `description` | 大标题, 副标题, 一段介绍 | 容易 |
| `[[capabilities]]` 四条 | 四张能力卡, 每条三层 | **最难的一块**, 见下 |
| `[home] techStack` | 技术栈标签 | 通常不用改 |
| `[home.cta]` | 底部行动召唤 | 容易 |
| `[home] blurb` | 数据规模那一行 | 容易, 但**数字必须现场数出来** |
| `[home.businessContext]` 加 `business-context.md` | 覆盖层的标题和正文 | 长, 但结构固定 |

**四张能力卡是最难的一块**, 因为它要求你真的理解那门生意: 你得说得出那个行业的四条主线各是
什么, 还得把每一条翻译成外行能懂的话.

写不出来通常不是文案能力问题, 是对那个行业的理解还停在它是做什么的这一层. 这一点第 2 篇
已经预告过, 而这一篇的练习 2 就是那件事的第一次正式交付.

**组件一行都不用改.**

## 11. 练习

### 练习 1: 改一次, 看两个页面一起变

**目标:** 亲眼确认一份数据两处渲染这件事.

**怎么做:**

1. 确认你在自己的 branch 上, 起开发服务器
2. 打开 `data/site.toml`, 找到 `[[capabilities]]` 的第一条, 把它的 `title` 改成一个一眼能
   认出来的词, 比如 `AAA Test`
3. 打开首页, 找到那张卡, 确认它变了
4. **不要改任何别的东西**, 直接进 agent 页, 看那张欢迎卡里的四张卡
5. 再把那条的 `tooltip` 改一句话, 两个页面各自悬停一次
6. 还原

**你会观察到:**

改一处, 两个页面同时变了, 而你没有碰任何一个组件文件. 顺手在手机尺寸下 (浏览器开发者工具
里切一下) 看看那个气泡, 注意外侧那一列的气泡是贴着卡片外边缘挂的.

> **关键洞见:** 两个地方描述同一件事的时候, 合成一份数据比写两份加一个检查便宜得多, 而且
> 前者让漂移在结构上不可能发生, 后者只是让漂移能被发现.

### 练习 2: 为你自己那个行业写四条能力卡

**目标:** 交出换领域时最难的那一块, 而且现在就交.

**怎么做:**

1. 翻出你在第 2 篇存的 `tmp/my-target-domain.md`, 里面有你选的公司和那三个业务问题
2. 为那个行业写**四条业务主线**, 每条三层:
   - `title`: 那一行真的会用的概念名, 不要自己发明
   - `subtitle`: 一句白话, 不许出现任何需要另外解释的词
   - `tooltip`: 两三句, 讲清这个概念是什么, 以及**为什么它值得被盯着**
3. 写完做一次检验: 把四条 `tooltip` 拿给一个完全不懂那个行业的人 (或者一个不知道你在做什么
   的 AI 对话) 读, 问他读完能不能复述出来
4. 存进 `tmp/my-target-domain.md`

**你会观察到:**

`title` 和 `subtitle` 大多数人半小时能写完, `tooltip` 会卡住. 卡住的地方通常是你发现自己
只知道那个词, 说不出它背后那件事为什么要紧.

> **关键洞见:** 能不能把一个概念讲给外行听, 是你到底懂不懂它的最好检验. 这四条卡片以后会
> 出现在你的作品集首页上, 而面试官读的正是它们.

## 13. 导师寄语

**为什么首页比你想的重要:**

做技术的人容易低估首页, 觉得那只是包装, 真本事在后面的 agent 里. 但你的项目大概率不会被
逐行读, 它会被**扫一眼**.

那一眼里, 读的人要判断三件事: 这是干什么的, 这个人懂不懂他在做的行业, 这东西是不是真的.
首页那四张卡回答第二件, 底部那行数据规模回答第三件.

而第二件是最难伪装的. 一个只会调 API 的人写不出一句能让外行听懂的业务解释, 因为他自己就
停在那个术语上.

**关键洞见:**

- 对内行精确的词, 对外行等于没写. 解法是分层, 不是删掉术语
- 能不能把一个概念讲给外行听, 是你懂不懂它的最好检验
- 两个地方描述同一件事, 就该合成一份. 漂移不会有任何测试失败

**下一步:**

首页把人带到了门口. 第 11 篇 (agent 页) 讲他推门进去之后看到什么: 一个空输入框会把人劝退,
所以那一页的空状态里塞了不少东西.

## 14. 速查

**首页四件事:**

1. 一句话说清这是什么
2. 四条业务主线讲成外行能懂的话
3. 一个讲完整行业背景的入口
4. 让人知道背后是真数据, 数字要数出来

**能力卡三层:**

```toml
[[capabilities]]
icon = "BarChart3"
title = "概念名, 给内行"
subtitle = "一句白话, 陌生人先读到的是这句"
tooltip = "两三句解释, 里面不许再有黑话"
```

**关键文件:**

- `data/site.toml` 的 `[home]` 与 `[[capabilities]]`: 首页说的每一句话
- `data/business-context.md`: 覆盖层的正文
- `app/(marketing)/_components/Hero.tsx`: 首页的全部内容
- `components/CapabilityCard.tsx`: 四张卡, 两个页面共用
- `components/ConceptTooltip.tsx`: 解释气泡
- `components/BusinessContextModal.tsx`: 覆盖层

**换领域时首页动哪儿:**

只动 `data/site.toml` 和 `data/business-context.md`. 组件一行不改.
