# 看懂首页怎么把外行带进门

## 1. 目标

回到第 2 篇那个场景: 你把项目发给面试官, 他点开链接. ** 第一屏就是首页, 而他大概率不懂这个
行业.**

首页要解决的就是这件事: 把一个外行带到能提出第一个问题的位置. 这一篇讲它靠什么做到, 重点是
那四张能力卡的三层结构.

**这一篇有一个必须交出来的产物, 而且它比读懂正文重要**: 为你自己那个目标行业写出四条能力卡.
这不是练笔, 是第 36 篇换数据集时你要用的真材料, 也是第 2 篇那份 `tmp/my-target-domain.md`
的续集.

**最容易糊弄过去的是 tooltip 那一层.** 前两层大多数人半小时能写完, 到 tooltip 会卡住, 然后
很多人的做法是塞几个行业术语进去凑数. 那样等于没写. 判据只有一条: ** 拿给一个完全不懂那行的
人读, 他读完能不能复述出来.**

---

## 2. 要做的事情

1. 读完 README, 重点是能力卡三层那一节和一份数据两处渲染那一节.
2. 打开首页, 对着 README 第 5 节那四件事, 在屏幕上逐一指出它们分别是哪一块.
3. 悬停在四张能力卡上各看一次气泡, 再用键盘 Tab 过去一次, 再在浏览器开发者工具里切到手机
   尺寸点一次, 确认三种打开方式都 work.
4. 在手机尺寸下注意外侧那一列的气泡贴着哪一边, 想清楚为什么不是居中.
5. 点开那个讲行业背景的覆盖层, 试三种关闭方式, 再试着点面板内部, 确认它不关.
6. 确认自己在一个属于自己的 branch 上, 改一条能力卡的 `title`, 在首页和 agent 页各看一次,
   确认两处同时变了, 然后还原.
7. 翻出第 2 篇存的 `tmp/my-target-domain.md`.
8. 为那个行业写四条业务主线, 每条三层: 概念名, 一句白话, 两三句解释.
9. 把四条 `tooltip` 拿给一个不懂那个行业的人或者一次全新的 AI 对话读, 问他能不能复述出来;
   复述不出来就重写.
10. 把四条存进 `tmp/my-target-domain.md`, 确认工作区里没有留下未还原的代码改动.

**预计用时:** 90 到 150 分钟 (读正文约 30 分钟, 剩下都在写那四条卡)

---

## 3. 检查清单

- [ ] **四件事指得出**: 你能在首页上逐一指出那四件必须做到的事分别对应哪一块.
- [ ] **三层的分工**: 你能说出概念名, 一句白话, 两三句解释各写给谁看, 以及为什么中间那句是
      唯一有机会留住陌生人的东西.
- [ ] **气泡三种入口验过**: 悬停, 键盘, 手机点按你都试过, 并能说清只做悬停会漏掉谁.
- [ ] **手机上的定位**: 你在窄屏下看过外侧那列的气泡, 能说清为什么不能居中.
- [ ] **一份数据两处渲染**: 你改过一条卡片, 亲眼看到两个页面同时变; 并且能说清两份配置描述
      同一件事时, 漂移为什么不会有任何测试失败.
- [ ] **四条卡写出来了**: `tmp/my-target-domain.md` 里有四条业务主线, 每条三层齐全.
- [ ] **tooltip 过了外行检验**: 那四条解释你拿给不懂那行的人读过, 他能复述出来, 而且里面没有
      任何需要另外解释的术语.
- [ ] **换领域改哪儿**: 你能说出换一个业务领域时首页要动哪几段, 以及组件要不要改.
- [ ] **工作区干净**: 练习改的代码都还原了, `git status` 里只剩 `tmp/` 下那份文件.
