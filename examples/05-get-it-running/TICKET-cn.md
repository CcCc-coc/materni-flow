# 在自己的机器上把它跑起来

## 1. 目标

这是这门课第一次动手. 走完三步, 你的机器上会有两个开发服务器在跑, 浏览器里的首页能打开.

三步是装依赖, 复制一份配置, 起服务.

**这一篇的门槛被刻意压到了最低: 不注册任何账号, 不填任何真值, 不碰数据库.** 那份 `.env`
你复制出来就不用管了, 里面每一行都还是注释掉的占位符.

**所以 agent 页这时候用不了.** 你点 kickstart 一定会拿到一条报错, 因为这台机器上既没有模型
的凭据也没有数据. 那是**预期结果**, 不是你哪儿做错了. 补上它是第 13 篇的事.

为什么这么切? 两个理由. 第一, 第一次在陌生项目上动手, 最重要的是尽快拿到一个能回头对照的
正常状态, 一口气全配完卡在哪一步都很难判断. 第二, 注册账号绑卡这些成本, 是在你还没看见
任何东西之前就要付出的, 把它们推到后面更合理.

真正要用心的是那条判据: **一个配置值该放哪个文件, 只问它是不是密钥.** 配置的错误几乎都
不报错, 从模板抄一行忘了注释掉, 或者把值填进错的那个文件, 程序照跑, 只是读到的不是你以为
的那个值.

还有一条现在就该记住的红线: **API key 不要贴进任何聊天窗口, 包括跟 AI 的对话.** 这一篇你
还没有 key, 但习惯要从现在养.


**卡住了别硬扛.** 把三样东西一起给 AI: 你在读哪一篇的路径, 你敲的那条命令, 以及
**终端打出来的原文** (整段复制, 不要截图, 不要只说一句报错了).
粘贴前先把连接串和 key 的片段打码.

## 2. 要做的事情

1. 读 README 第 1 节末尾那条 branch 纪律, 记住 `git switch -c NN-xxx 01-showcase` 这个写法.
   **这一篇不改任何文件, 所以先不用真开.**
2. 装好 mise, 然后跑 `mise run inst` 装齐 Python 和 Node 两套依赖.
3. 打开 `mise.toml`, 找到顶上那个 tools 段和下面那一堆 tasks, 说清这个文件同时管哪两件事.
4. 复制 `.env.example` 成 `.env`, **一个值都不要填**, 然后打开它扫一遍, 看清这个项目一共
   需要哪几类外部东西.
5. 打开 `.env.defaults` 对照着读, 找出 `SCHEMA_NAME` 和 `LLM_PROVIDER` 两行.
6. 跑 `mise run dev`, 等两个服务器都打出就绪日志 (Next.js 打 `Ready in`, uvicorn 打
   `Application startup complete.`).
7. 打开浏览器访问本地 3000 端口, 确认首页完整渲染, 四张能力卡都在, 解释气泡能弹出来.
8. 点右上角进 agent 页, 确认空状态那四张卡和 12 个按钮都在.
9. 点一个 kickstart 按钮, 看它怎么失败, 回终端把后端打的那几行抄下来存着, **不要去修**.
10. 拿正文那七个配置值做一遍分家判断, 再打开 `.env.example` 和 `.env.defaults` 对答案.

**预计用时:** 35 到 60 分钟 (装依赖本身要等几分钟)

## 3. 检查清单

- [ ] **branch 纪律知道了**: 你知道从下一次要改文件起, 该怎么从基线开一个以那一篇命名的
      branch, 以及为什么基线要保持随时能跑.
- [ ] **依赖装齐**: `mise run inst` 跑完没有报错, `.venv` 和 `node_modules` 都在.
- [ ] **一个真值都没填**: 你的 `.env` 是从 `.env.example` 原样复制来的, 没有任何一行被填上
      真实的地址或密钥.
- [ ] **服务器起来了**: 两个就绪日志都出现过, 浏览器能打开首页, 页面完整渲染, 能力卡和解释
      气泡都正常.
- [ ] **知道自己停在哪**: 你点过 kickstart 并看到它失败, 抄下了那几行, 能说清这是因为缺凭据
      和数据而不是环境配错了, 也知道补上它是第 13 篇的事.
- [ ] **解释得了为什么能跑**: 你能说清首页为什么完全不碰配置, 以及后端为什么在什么都没配的
      情况下照样启动得起来.
- [ ] **分家判据会用**: 那七个值你判断过一遍并对过答案, 能说清端口和主机名为什么分在两个
      文件里.
- [ ] **配置的错不报错**: 你能举出至少一种填错了程序照跑的情况, 比如从模板抄来忘了注释掉
      的那一行.
