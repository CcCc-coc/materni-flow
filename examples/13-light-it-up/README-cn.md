# 接上真数据和真模型

> 前面八篇一个账号都没让你注册. 这一篇要花钱了, 而这是整门课唯一一次真正的门槛.

## 1. 概览

第 5 篇 ([把它跑起来](../05-get-it-running/README-cn.md)) 你把界面跑起来了, 然后点 kickstart
按钮, 看着它失败. 从那以后的七篇, 你把前端翻了个遍: 路由怎么变成网址, 文案住在哪个文件,
首页那四张卡怎么来的, agent 页那 12 个按钮是什么, 一段文本怎么变成表格和图.

**这七篇你一分钱没花, 一个账号没注册.** 现在到时候了.

这一篇要补三样东西, 补完那个按钮就真的会给你答案:

| 补什么 | 为什么缺了不行 |
| :--- | :--- |
| 一把模型的 API key | agent 的脑子. 没有它, 后端第一次要建模型就失败, 也就是你在第 5 篇看到的那条报错 |
| 一个云端 PostgreSQL | agent 要查的东西住的地方. 这个项目在任何环境下都读同一个云库, 本地也一样 |
| 数据本身 | 库开出来是空的. 数据要在本地造出来, 再发布上去 |

**这一篇是纯操作篇.** 每一样东西背后的原理都不在这里: 数据集是什么在第 14 篇, 同步为什么
这么做在第 15 篇, 配置系统怎么设计的在第 30 篇. 这里只管把它点亮.

### 读不懂的地方, 别跳过去

这一篇涉及两个外部平台, 而它们的界面每隔几个月就改一次版. 所以正文只讲**要发生什么**, 不讲
点哪个按钮.

卡在某个界面上的时候, 正确的动作是把那一屏截图丢给 AI:

1. 敲 `/showcase-learn-cn` 把助教叫起来
2. 把截图和你要达成的目标一起给它, 比如我要在这个页面上拿到数据库的连接字符串
3. 要求它**一步一步** 说, 每一步等你做完再说下一步

这是第 4 篇 ([和 AI 一起改这个仓库](../04-work-with-ai/README-cn.md)) 那套方法的第一次真实
应用. 后面第 36 篇绑域名的时候你还要再用一次.

## 2. 学习目标

先解释一件事: 为什么这道门槛被推到这么后面.

技术上, 这一篇完全可以排在第 5 篇后面, 一口气把环境全配好. 很多教程就是这么写的. 但那样做
有一个隐性代价: **它要求你在还没看见任何东西之前, 就先注册两个账号, 绑一张卡.**

那一刻你对这个项目的了解是零. 你不知道那把 key 会被谁用, 不知道那个数据库里会装什么, 也
不知道这一切最后会长成什么样. 一个理性的人在这个位置上犹豫是正常的, 而犹豫的结果通常是
标签页一关, 再也不回来.

现在不一样. 你已经亲手翻过这个项目的每一层界面, 知道那 12 个按钮各自承诺什么, 知道 agent
的回答会被渲染成表格和图. **你清楚自己在给什么东西付钱.**

顺带说一句钱: 这门课全程的模型调用成本大概是几美分到一美元的量级, Neon 的免费额度完全够
用. 真正需要防的不是这门课花光你的钱, 是一把泄漏出去的 key 被别人跑满 —— 所以下面第 5 节
那个花费上限不是可选项.

学完这个 Task, 你将能够:

1. 在三家供应商里选一家拿到 API key, 分清月费订阅和 API 额度是两回事
2. 给那把 key 设一个花费上限, 并说清这一步防的是什么
3. 从自己的 Neon 项目里取出四个连接值, 填进正确的那个文件
4. 跑完造种子, 发布, 核对这三条命令, 并说清它们为什么不是 mise 任务
5. 让 agent 真的回答一次, 并确认第 5 篇那条报错消失了

## 5. 一把 LLM 的 API key

这个 app 的核心是一个大模型, 所以你得给它一把钥匙. 这一节讲的是**你需要做什么判断**, 不是
点哪个按钮, 因为三家厂商的控制台每隔几个月就改一次版, 写死步骤只会过期.

### 三选一

| 厂商 | 环境变量 | 说明 |
| :--- | :--- | :--- |
| OpenAI | `OPENAI_API_KEY` | **推荐**, 注册和拿 key 这条路最顺 |
| Anthropic | `ANTHROPIC_API_KEY` | Claude 系列 |
| Google | `GOOGLE_API_KEY` | Gemini 系列 |

**只填一家.** 每个进程只跟一个 LLM 后端说话, 由 [`.env.defaults`](../../.env.defaults) 里的
`LLM_PROVIDER` 决定, 而只有被选中那家的凭证是必需的. 三把 key 都填不会更好, 只是多两个要
保管的东西.

选好之后, 把 [`.env.defaults`](../../.env.defaults) 里那行改成对应的值, 或者在自己的 `.env`
里写一行同名的盖掉它. `.env` 先读, 所以它赢.

还有第四家 AWS Bedrock, 它不走 API key 而走 AWS 凭据, 配起来多几道手续. 第一次跑先别选它.

### 订阅和 API key 是两回事

这一点每年都要坑掉一批人.
**ChatGPT Plus, Claude Pro 这类月费订阅买的是网页版和客户端的使用权, 不带 API 额度.**
你已经付过订阅费, 不代表你的 API key 能用. API 是单独计费的另一条路, 在各家的开发者控制台
里, 通常叫 API keys 或者 Developer platform.

### 给它设一个花费上限

拿到 key 之后, **在控制台里给这个账号设一个消费上限, 5 美元或者 10 美元**. 这门课大概率
用不完, 一次对话的成本是零点几美分的量级.

这一步不是为了省那几美元, 是**防呆**:

- 一把不小心提交进公开仓库的 key, 会在几小时内被爬到并跑满
- 一段写错的循环可能在你去泡咖啡的时候调用几千次

设了上限, 这两件事的代价就是上限本身, 用完为止. 不设上限, 它是一张空白支票.

### 安全保管

- **存进密码管理器** (LastPass, 1Password, Bitwarden 这类), 不要存在便签或者聊天记录里
- **不要贴进任何聊天窗口**, 包括跟 AI 的对话
- **不要提交进 Git.** 这个仓库把它放在 `.env` 里, 那个文件被 `.gitignore` 排除, 而且
  `.claude/settings.json` 里 deny 了 AI 对它的读和写, 所以你让 AI 帮忙改配置时它碰不到这
  个文件
- **发现泄漏就当场吊销重发一把.** 不要试图评估影响, 吊销是几秒钟的事

## 6. 一个云端 PostgreSQL

第 3 篇那门 Neon 前置课已经教过怎么开一个 Postgres 项目并连上去.
这里只说**这个仓库要从它那儿拿哪几个值**.

打开你的 Neon 项目, 找到连接信息那一屏, 把四个值填进 `.env`:

| 变量 | 从 Neon 的连接信息里取哪一段 |
| :--- | :--- |
| `DB_HOST` | 主机名. **用带 `-pooler` 的那个** |
| `DB_USER` | 用户名, 通常是 `neondb_owner` |
| `DB_PASS` | 密码 |
| `DB_NAME` | 数据库名, 通常是 `neondb` |

端口不用填, 它是 `5432`, 而且已经写在 [`.env.defaults`](../../.env.defaults) 里了 —— 端口
不是密钥, 这正是第 5 篇那条分家判据的一个例子.

**为什么要用带 `-pooler` 的主机名**: Neon 给每个项目两个地址, 一个直连, 一个走连接池.
serverless 应用每次冷启动都要新建连接, 走连接池那个能撑住这种模式. 这条现在知道就行,
第 15 篇会讲它带来的一个真正的坑.

**不用自己建库, 也不用建表.** 这个项目只占你那个实例里的一个 schema, 名字写在
[`.env.defaults`](../../.env.defaults) 的 `SCHEMA_NAME` 里, 下面那条发布命令会自己把它建
出来. 你在前置课里建的那些表不会被碰到.

填完之后先验一下通不通:

```bash
mise run cli-test-db-conn
```

这条命令**不查任何表, 也不查 schema**, 它只回答一个问题: 这台机器连不连得上那个库. 这样
设计是有意的 —— 后面万一 agent 不工作, 你需要能把连不上和连上了但库是空的这两件事分开.

## 7. 把数据造出来

数据库现在是空的. 这个项目的数据不在 Git 里, **它是用一个生成器现造的**.

```bash
CLI=.claude/skills/about-bi-agent-app-scaffold-cn/scripts/teaching_cli.py
.venv/bin/python $CLI gen-data
```

它会先装生成器自己的依赖, 然后跑那个脚本, 几分钟之后在 [`dataset/`](../../dataset) 下面留下
一个 `.sqlite` 文件, 里面是十来张表, 十几万行.

两件现在就该知道的事:

- **数据库已经在的话它什么都不做**, 直接退出. 生成要跑几分钟, 而绝大多数时候它已经在那儿了
- **它不是 mise 任务.** `mise.toml` 跑的是这个 app 本身, 而造数据不是 app 的一部分

这两条背后的完整理由在第 14 篇 ([一个数据集里装着什么](../14-what-a-dataset-is/README-cn.md)),
下一篇就是.

**为什么本地造出来的是 SQLite, 而线上是 PostgreSQL**: 一句话是 SQLite 只当**种子**, 不是
任何人查询的对象. 这个选择背后有一整套理由, 第 15 篇
([把种子发布到 PostgreSQL](../15-seed-to-postgres/README-cn.md)) 专门讲. 下一步先把它搬上去.

## 8. 发布上去, 然后核对

```bash
CLI=.claude/skills/about-bi-agent-app-scaffold-cn/scripts/teaching_cli.py
.venv/bin/python $CLI sync-db      # 把本地种子发布进云端那个 schema
.venv/bin/python $CLI verify-db    # 逐表核对行数, 不一致就 exit 1
```

(那行 `CLI=` 上一节定义过. 这里重复一遍, 是因为你很可能隔一天回来或者开了个新终端,
那时候它是空的.)

**先跑第一条, 看完输出再跑第二条.** 第一条会一张表一张表地报进度, 那个顺序不是随便排的,
第 15 篇会讲它是算出来的.

**别跳过 `verify-db`.** 一条命令没报错, 不等于每一行都过去了. 为什么这两件事必须分开验,
第 15 篇 ([把种子发布到 PostgreSQL](../15-seed-to-postgres/README-cn.md)) 会讲.

这两条同样不是 mise 任务, 同样属于教学层.

## 9. 验收: 让它真的回答一次

三样东西都到位了, 现在重启开发服务器:

```bash
mise run kill
mise run dev
```

**必须重启.** 配置是进程启动时读进去的, 你改完 `.env` 不重启, 跑着的那个进程手里还是旧的.

然后打开 agent 页, 点一个 kickstart 按钮.

这次它应该:

1. 先出现一个可以展开的思考块
2. 然后正文一段段流出来
3. 里面有**来自数据库的真实数字**, 而不是一段泛泛而谈
4. 如果那个按钮的徽章是表格, 你应该同时看到一张表和一段 SQL

**把第 5 篇你抄下来的那条报错找出来, 确认它不再出现了.** 那是这一篇的验收标准.

### 如果还是不行

按这个顺序排查, 每一步都能把范围切掉一半:

| 现象 | 先查什么 |
| :--- | :--- |
| 报的还是凭据相关的错 | `.env` 里那把 key 填对了吗, `LLM_PROVIDER` 指的是不是同一家 |
| 报连不上数据库 | 跑 `mise run cli-test-db-conn`, 它绿不绿 |
| 说库里没有表 | `verify-db` 跑过吗, 绿的吗 |
| 什么都对但答案很怪 | 重启过服务器吗 |

排不出来就把报错原样贴给助教, 别自己猜.

## 10. 练习

### 练习 1: 点亮它, 然后校验它

**目标:** 让第 5 篇那个半成品变成完整的, 并且当场校验一次它给的数字.

**怎么做:**

1. 开一个叫 `13-light-it-up` 的 branch
2. 拿到一把 API key, **在控制台里设好花费上限**, 填进 `.env`, 并确认
   [`.env.defaults`](../../.env.defaults) 里 `LLM_PROVIDER` 指的是同一家
3. 从 Neon 取四个值填进 `.env`, 跑 `mise run cli-test-db-conn` 确认绿
4. 跑 `gen-data`, 等它跑完, 记下它最后打印的文件名和大小
5. 跑 `sync-db`, **看它一张表一张表报进度**, 把那个顺序抄下来
6. 跑 `verify-db`, 确认每张表行数都一致
7. `mise run kill` 然后 `mise run dev`, 打开 agent 页
8. 点那个关于风险等级定价的 kickstart 按钮, 等它答完
9. 把第 5 篇抄下来的那条报错拿出来对一眼, 确认它没了

**你会观察到:**

第 5 步那个顺序里, 几张查找表一定在最前面, 几张流水表一定在最后. 现在先记着这个观察,
第 15 篇会解释它是怎么算出来的.

第 8 步是这一篇最值得停一下的时刻: 屏幕上那些数字, 是模型自己写了一条 SQL, 发给你刚刚建
起来的那个库, 拿回结果之后整理出来的. 这条链路上的每一环都是你亲手接上的.

> **关键洞见:** 一个 app 从半死到活着, 中间隔的往往不是代码, 是凭据和数据. 这两样东西不
> 在仓库里, 也不该在.

### 练习 2: 把三样东西分别拿掉一个, 看它怎么坏

**目标:** 建立一张故障与症状的对照表, 这样以后出问题你能一眼定位.

**怎么做:**

对下面三种情况, 各做一次, 每次只改一样东西, 看完就还原:

1. **拿掉模型**: 把 `.env` 里那把 API key 那一行注释掉, 重启, 问一个问题.
   看完取消注释, **重启, 确认 agent 又能答**
2. **拿掉数据库**: 把 `.env` 里 `DB_HOST` 那一行**整行复制一份**, 把原来那行注释掉, 在副本
   上把主机名改成一个不存在的地址. 重启, 问一个问题. 看完删掉副本, 取消注释,
   **重启, 确认 agent 又能答**

(为什么要复制一份再改: 那串主机名是你从 Neon 抄来的, 直接覆盖掉就得回控制台再翻一次.)

每一次都记下来: **报错出现在哪儿** (浏览器上还是终端里), 以及**它说得清缺什么吗**.

**还有第三种坏法: 拿掉数据.** 那一种留给第 15 篇
([把种子发布到 PostgreSQL](../15-seed-to-postgres/README-cn.md)) 的练习, 因为它的失败方式
最有意思, 而且要先讲完同步是怎么回事才讲得透.

**你会观察到:**

两条报错的清晰程度不一样. 拿掉模型那条会直接点出哪个环境变量没设, 因为那句话是这个项目
自己写的; 拿掉数据库那条通常含糊得多, 因为它来自数据库驱动, 而驱动不知道你在做什么.

**这个差别本身就是教材**: 一个项目能控制的只有自己写的那几条报错, 而它们值不值得写, 取决于
那个失败常不常见, 以及不写的话人要花多久才猜得到.

> **关键洞见:** 排查的本质是把可能性切成两半. `mise run cli-test-db-conn` 之所以不查表也
> 不查 schema, 就是为了让它能干净地切这一刀.

## 11. 回顾: 我们学到了什么

| 东西 | 一句话 |
| :--- | :--- |
| 三样缺一不可 | 模型的凭据, 一个云端库, 库里的数据. 少任何一样 agent 都不工作, 但坏法不一样 |
| 报错的清晰度不一样 | 自己写的报错说得清缺什么, 第三方库抛出来的通常只说它自己那一层 |
| 订阅不等于 API 额度 | 月费买的是网页版的使用权, API 是单独计费的另一条路 |
| 花费上限 | 防的不是这门课花光你的钱, 是一把泄漏的 key 被别人跑满 |
| 端口和主机名分家 | 端口不是密钥所以进 `.env.defaults`, 主机名是所以进 `.env` |
| 造数据不是 app 的一部分 | 所以那三条命令不在 `mise.toml` 里, 它们属于教学层 |
| 同步成功不等于数据到齐 | 所以有一条单独的 `verify-db`. 为什么必须分开验, 第 15 篇讲 |
| 改完配置要重启 | 配置在进程启动时读进去, 不重启改了也不算 |
| 校验比结果重要 | 拿一个你自己能算出来的数字去对模型给的数字 |

## 12. 导师寄语

**为什么这一篇被排在这么后面:**

绝大多数项目的 README 第一节就是安装与配置, 里面躺着注册这个账号, 申请那个 key. 那种顺序
对已经决定要用它的人是最优的, 对还在观望的人是最劝退的.

这门课把顺序倒过来: 先让你看见东西, 翻遍界面, 明白这是个什么玩意儿, 再要求你掏出信用卡.
到这一刻你已经投入了几个小时, 而且清楚知道那把 key 会被用来干什么.

**这个思路你以后自己做产品的时候也用得上**: 尽可能把要用户付出成本的那一步, 推到他已经
看见价值之后.

**关键洞见:**

- 一个 app 从半死到活着, 中间隔的常常不是代码, 是凭据和数据
- 排查的本质是把可能性切成两半, 所以要有一条只验一件事的命令
- 一个你无法校验的 AI 系统, 是不能拿去给别人用的
- 要用户付出成本的那一步, 越晚越好
