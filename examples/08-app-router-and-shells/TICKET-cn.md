# 看懂路由, 三层壳与那条渲染边界

## 1. 目标

这是前端那一组的第一篇, 从最外面讲起: 一个网址怎么找到对应的文件, 每个页面外面套着什么,
以及哪些代码跑在服务器上, 哪些跑在浏览器里.

**这一篇讲的几乎全是约定, 不是代码逻辑.** App Router 里很多行为是由目录名和文件名决定的,
而不是由某一行代码声明的: 一个带括号的目录和一个不带括号的目录行为完全不同, 但没有任何地方
写着这件事. 所以这一篇的读法和读普通代码不一样, **目录名本身就是要读的信息**.

最要紧的一条是 server 和 client 那条线. 判错了的后果不是报一个清楚的错, 而是构建失败在一个
看起来和你改动无关的地方, 或者一个功能在开发时好好的到线上就没了.

练习 1 会往 `app/` 里加一个目录, 记得做完删掉, 别把它留在工作区里.

---

## 2. 要做的事情

1. 读完 README, 重点是路由约定那两个特殊符号, 和 server 与 client 那一节.
2. 打开 `app/` 从上往下扫一遍目录结构, 对着 README 那张表确认每个目录对应哪个网址, 哪些
   不进网址.
3. 打开 `app/layout.tsx`, `app/(marketing)/layout.tsx`, `app/chat/layout.tsx` 三个文件,
   对比它们各自做了什么.
4. 在 `app/chat/layout.tsx` 里找到那个提示条容器, 读它上面的注释, 弄清楚少了它会怎样.
5. 打开 `app/chat/page.tsx`, 确认它只有三行, 并说清这三行分别在干什么.
6. 新建 `app/(marketing)/about/page.tsx`, 内容三行, 随便渲染一句话.
7. 跑 `mise run build-web`, 在输出的路由表里找到 `/about`, 注意它前面那个表示静态的标记.
8. 起开发服务器打开 `/about`, 确认顶部导航条也在, 并想清楚它为什么在.
9. 删掉整个 `about` 目录, 再跑一次构建确认它消失了, 工作区回到干净.
10. 对 README 练习 2 里那五样东西各判断一次该放 server 还是 client, 然后去仓库里对答案.

**预计用时:** 60 到 90 分钟

---

## 3. 检查清单

- [ ] **路由约定说得清**: 你能说出 `app/` 下的目录怎么对应网址, 以及带括号和下划线开头的
      目录各自意味着什么.
- [ ] **加过一个路由**: 你新建过一个页面文件, 在构建输出的路由表里看到过它, 也在浏览器里
      打开过, 然后删掉了.
- [ ] **导航条为什么在**: 你能解释新加的那个页面为什么自带顶部导航条.
- [ ] **三层壳分得清**: 你能说出根壳, 分组壳, 页面三层各管什么, 并指出这个 app 里对应的文件.
- [ ] **那行提示条容器**: 你能说清少了它会发生什么, 以及为什么这类问题特别难查.
- [ ] **那条线会判**: 五样东西你都判断过该放 server 还是 client, 理由用的是读盘的往上放
      有状态的往下放这条规矩, 并且和仓库里的实际情况对过答案.
- [ ] **props 的限制**: 你能说清为什么跨过那条线的 props 必须能被序列化.
- [ ] **静态生成的推论**: 你能说清两个页面都是构建期生成的, 对读文案的那段代码意味着什么.
- [ ] **工作区干净**: 练习加的目录已经删掉, `git status` 没有留下多余文件.
