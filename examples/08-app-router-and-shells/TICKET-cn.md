# 学会从界面倒推到代码

## 1. 目标

**这一篇不教前端, 也不教框架.** 你不需要会写 React, 不需要看懂任何一行代码的语法. 这门课的
学生背景差得很远, 而这门课的终点也不是把你变成前端工程师.

它教的是一个更耐用的东西:
**面对一个你完全不懂的系统, 怎么从你能看见的那一点点东西出发, 摸清它的组织方式.**
在这里那个出发点特别友好, 就是你已经在浏览器里看了好几遍的那个界面.

产出是方位感, 不是知识. 你以后要改这个界面 (换文案, 换配色, 换整个业务领域), 那时候你需要
的不是写代码的能力, 是**知道东西在哪儿** 的能力, 加上一个能替你写的 AI.

**最容易走偏的地方是钻进代码里.** 搜到一个文件之后打开一看两百行, 然后开始逐行读. 别这么
干. 这一篇要你做的只有两件事: 确认这块东西住在哪个文件, 以及那个文件属于哪一层. 剩下的交给
第 11 节那三种问法.

---

## 2. 要做的事情

1. 读完 README, 重点是三步法那一节, 和最后那三种问 AI 的问法.
2. 起开发服务器, 在浏览器里把首页和 agent 页各看一遍, 有意识地数一数屏幕上分成哪几块.
3. 对 agent 页输入框里那句灰色提示文字走一遍三步法, 写下它的文字来自哪个文件, 由哪个文件
   画出来.
4. 对首页导航栏右边那个按钮上的字走一遍三步法, 注意它落在哪个目录, 和上一样有什么不同.
5. 对 agent 页那 12 个建议问题里的任意一个走一遍三步法.
6. 对照 README 第 6 节和第 7 节那两张表核对你的三个答案.
7. 打开三个 layout 文件扫一眼, 说清为什么两个页面都带着同一条导航栏, 而你没在任何页面里
   写过它.
8. 跑一次 `mise run build-web`, 在输出的路由表里找到两个路由, 确认里面没有 marketing 这个词.
9. 随便打开三个组件文件, 看它们顶部有没有 `"use client"`, 感受一下这条看不见的线.
10. 开一个叫 `08-app-router-and-shells` 的 branch, 加载
    `/about-bi-agent-app-scaffold-cn`, 问它把首页四张能力卡改成三张要动哪些文件, 明确要求
    它先不要动手.
11. **拿三步法逐个验证它说的每个文件**, 特别留意它有没有提到那四张卡在两个页面上都被渲染.

**预计用时:** 60 到 90 分钟

---

## 3. 检查清单

- [ ] **三步法说得出**: 你能复述那三步, 并解释为什么第二步搜文字这么有效.
- [ ] **倒推做过三次**: 三样东西你都写下了它的文字来自哪个文件, 由哪个文件画出来, 并和
      README 里那两张表核对过.
- [ ] **落点的含义**: 你能说出搜到的文件落在 `data/`, `app/`, `components/`, `lib/` 各自
      意味着什么, 并解释第 2 样和另外两样为什么落点不同.
- [ ] **三层壳**: 你能说清这个界面套了哪三层, 以及为什么两个页面不用自己写就带着导航栏.
- [ ] **网址约定**: 你能说出目录和网址怎么对应, 以及带括号和下划线开头的目录各自意味着什么,
      并在构建输出的路由表里验证过.
- [ ] **看不见的东西**: 你能举出至少两样肉眼看不见的东西, 并说出怎么发现它们的存在.
- [ ] **问法会用**: 你能说出那三种问法各自限定了答案的什么形状, 以及不限定会收到什么.
- [ ] **验证过 AI 的回答**: 你拿三步法核对过 AI 给的文件清单, 并且能说出它有没有漏掉那四张
      卡被渲染两次这件事.
- [ ] **工作区干净**: 这一篇不需要改任何代码, `git status` 应该没有任何改动.
