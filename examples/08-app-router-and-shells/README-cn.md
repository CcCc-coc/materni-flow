# 路由, 三层壳, 和 server 与 client 那条线

> 前端只有两个页面, 但它们被三层壳裹着, 而且有一条看不见的线把代码分成跑在服务器上的和跑
> 在浏览器里的.

## 1. 概览

这是前端那一组的第一篇. 从最外面开始: 一个网址是怎么找到对应文件的, 每个页面外面套着什么,
以及哪些代码在服务器上跑, 哪些在浏览器里跑.

这一组一共五篇, 顺序是从外往里: 先是路由和壳, 然后是文案从哪来, 然后是两个页面各自的内容,
最后是 agent 那段纯文本怎么变成表格和图.

**这一组把 agent 当黑盒.** 你只需要知道它会吐出一段 Markdown, 至于那段文字是怎么来的, 那是
后面几组的事.

---

## 2. 学习目标

Next.js 的 App Router 有一个对新手很不友好的特点:
**它的很多规则是靠目录名和文件名约定的, 而不是靠代码声明的.**
一个带括号的目录名和一个不带括号的目录名, 行为完全不同, 但没有任何一行代码写着这件事.

结果是这样: 你能看懂每个文件里的代码, 却说不清它们为什么摆成这个形状. 而一旦要加一个页面,
或者要判断某个东西该放哪一层, 就只能靠试.

这一篇要做的就是把那些约定摊开写清楚. 它们不多, 一次记住就够用很久.

学完这个 Task, 你将能够:

1. 说清 `app/` 下的目录结构怎么对应到网址, 以及哪些目录不进网址
2. 说出这个 app 的三层壳各管什么, 以及为什么两个页面要分成两个分组
3. 判断一段代码该跑在服务器上还是浏览器里, 理由用那条规矩
4. 说清页面级 SEO 为什么只需要传两个字段
5. 确认两个路由都是构建期静态生成的, 并说清这对读文件的代码意味着什么

## 5. 目录结构就是路由表

App Router 的核心约定只有一句: **`app/` 下面的目录层级就是网址的层级, 目录里那个
`page.tsx` 就是这个网址渲染的东西.**

这个 app 的目录长这样:

| 路径 | 对应网址 | 说明 |
| :--- | :--- | :--- |
| `app/layout.tsx` | 无 | 不是页面, 是包住所有页面的最外层壳. 名字叫 `layout` 就是这个意思 |
| `app/(marketing)/page.tsx` | `/` | 首页. 带括号的 `(marketing)` **不进网址**, 所以这个文件对应的是根路径 |
| `app/chat/page.tsx` | `/chat` | agent 页. 目录名不带括号, 所以它进网址 |
| `app/(marketing)/loading.tsx` | 无 | 也不是页面. 页面还在加载时先显示它, 是另一个约定文件名 |
| `app/_components/` | 无 | 下划线开头, Next.js 完全不当路由看. 放这一层共用的组件 |
| `app/globals.css` | 无 | 全站样式, 由根壳 import 一次 |

### 两个特殊符号

**带括号的目录是路由分组.** `(marketing)` 存在的唯一理由是让首页能有一个属于自己的 layout,
而不影响它的网址. 你可以把一组页面装进一个括号目录, 给它们套同一层壳, 网址上看不出任何痕迹.

**下划线开头的目录是私有目录.** Next.js 不会把它当路由. 这个 app 用它放两处组件:
`app/_components/` 是两个分组共用的, `app/(marketing)/_components/` 是首页专用的.

没有这两个符号也能做同样的事, 只是要么牺牲网址 (把 marketing 写进 URL), 要么牺牲就近原则
(把首页专用的组件挪到 `components/` 里跟通用组件混在一起).

## 6. 三层壳各管什么

一个页面被渲染出来之前, 要先经过两层 layout. 三层从外到内是:

| 层 | 文件 | 说明 |
| :--- | :--- | :--- |
| 根壳 | `app/layout.tsx` | 定义 `<html>` 和 `<body>` 标签, 加载三种 Google 字体并把它们变成 CSS 变量, 设置全站默认的浏览器标签标题和分享预览, 指定 favicon. 每个页面都会经过它 |
| 分组壳 | `app/(marketing)/layout.tsx` `app/chat/layout.tsx` | 各自那一组页面共用的东西. 这两层现在都只挂了顶部导航条, chat 那层还多挂了一个提示条容器 |
| 页面 | `app/(marketing)/page.tsx` `app/chat/page.tsx` | 真正的内容入口. 它们负责**读盘** 拿到文案, 然后把结果当 props 传给下层组件 |

### chat 那层多出来的那一行不能省

```tsx
<Toaster position="top-center" richColors />
```

它是那种一闪而过的提示条的容器. 少了它, chat 界面里每一次弹提示的调用都会
**静默地什么都不做**, 包括上一条还在跑的时候你又按了回车那条提示. 不报错, 只是提示永远
不出现.

这类东西有个共同特征: **它们是别人的功能依赖的一个前置条件, 缺了不报错只是功能消失.** 这个
仓库里这种坑不止一处, 后面还会遇到.

## 7. server 和 client 那条线

这是这一篇最要紧的一节.

Next.js 里的组件默认跑在**服务器** 上. 一个组件只有在文件顶部写了 `"use client"` 之后, 才会
被打包送到浏览器里去跑.

两边能做的事不一样:

| | server component | client component |
| :--- | :--- | :--- |
| 能读文件系统吗 | **能** | 不能 |
| 能用 `useState` 这类状态吗 | 不能 | **能** |
| 能响应点击这类交互吗 | 不能 | **能** |
| 代码会被下载到浏览器吗 | 不会 | 会 |

于是规矩是一句话: **读盘的往上放, 有状态的往下放, 中间用 props 连.**

具体到这个 app:

```text
page.tsx            server    读盘, 生成页面标题这类信息
   │  props
   ▼
HomePageContent     client    因为首页有入场动画和展开的覆盖层
Chat                client    因为对话状态要存在浏览器内存里
```

`app/chat/page.tsx` 全文就三行, 它的全部工作就是读一次文案然后传下去:

```tsx
export default function Page() {
  return <Chat site={loadSite()} />;
}
```

**客户端组件不许自己去读配置**, 因为读文案那个函数碰文件系统. 这不是麻烦, 是边界: 页面负责
读, 组件只负责接收和渲染.

还有一个容易忽略的推论: props 要能跨过这条线, 就必须**能被序列化**. 从 TOML 解析出来的是
纯粹的字符串, 数字和列表, 所以传得过去. 哪天你想往文案文件里加一个 TOML 支持但 JSON 不支持
的类型 (比如日期), 先想一下这件事.

## 8. SEO 只在一处定义

页面标题, 描述, 分享出去时的预览卡片, 这些统称页面元信息. 它们的规则住在 `lib/seo/`:

| 文件 | 说明 |
| :--- | :--- |
| `lib/seo/config.ts` | 全站默认值, 它自己从文案文件里读 |
| `lib/seo/generateMetadata.ts` | 一个合并函数: 把页面自己给的值盖在全站默认值上面 |

关键在于那个合并函数做了一件事: **分享预览的标题和描述会自动回退到普通标题和描述.** 所以
一个页面只需要传 `title` 和 `description` 两个字段, 剩下五六个字段自动就位.

**不要把它们再手填一遍.** 显式重复只是多出五个可以和标题不一致的地方, 而它们不一致的时候
没有任何东西会提醒你. 首页那个文件的注释里就写着这件事曾经发生过.

还有两处刻意的缺席: **没有作者字段, 也没有社交预览图.** 这个站点展示的是产品不是人, 这条
和第 2 篇里那句陌生人看不到任何这是一份作业的痕迹是同一条.

## 9. 两个页面都是构建期静态生成的

跑一次 `mise run build-web`, 输出里两个路由都会带一个表示静态的标记.

意思是: **文案和业务说明是在构建的时候从磁盘读进来烘进产物的, 请求时不再读盘.** 一个访客
打开首页, 服务器只是把一份已经生成好的 HTML 发出去.

这解释了两件事:

- 为什么读 `data/` 的代码必须是 server only. 它在构建时跑一次, 浏览器里根本不存在这段代码
- 为什么改完文案要重新构建才看得到. 开发服务器会帮你自动重跑, 但线上不会

顺带一提, 这也意味着**任何运行时改文案的想法在这套结构里都不成立**. 那个字符串在构建结束
的那一刻就冻住了.

## 10. 练习

### 练习 1: 加一个路由, 看它自己出现

**目标:** 亲手验证目录结构就是路由表这句话.

**怎么做:**

1. 新建目录 `app/(marketing)/about/`, 在里面建一个 `page.tsx`, 内容三行:

```tsx
export default function AboutPage() {
  return <main className="p-24">Hello from about.</main>
}
```

2. 跑 `mise run build-web`, 在输出的路由表里找 `/about`
3. 注意它前面那个表示静态的标记
4. 跑 `mise run dev`, 打开本地 3000 端口的 `/about` 看一眼. 注意顶部导航条也在, 因为你把它
   放进了 `(marketing)` 那个分组
5. 把整个 `about` 目录删掉, 再跑一次构建确认它消失了

**你会观察到:**

你没有在任何地方注册过这个路由, 它自己出现了. 网址里也没有 marketing 这个词, 因为那个括号
目录不进网址. 而导航条不请自来, 因为分组壳套在它外面.

> **关键洞见:** App Router 里很多行为是目录名约定出来的, 不是代码声明的. 所以读这一层代码
> 时, 目录名和文件名本身就是要读的信息.

### 练习 2: 判断这五样东西该放哪一侧

**目标:** 把那条规矩用起来.

**怎么做:**

对下面五样东西, 各回答一句该放 server 还是 client, 理由必须用这条规矩:
**读盘的往上放, 有状态的往下放.**

1. 一个从磁盘读文案文件的函数
2. 一个记录着覆盖层现在是开着还是关着的组件
3. 一个生成页面标题的函数
4. 顶部那个导航条组件
5. 一个把 agent 回答渲染成表格的组件

然后去仓库里找到它们真实的位置, 看有没有 `"use client"`, 对答案.

**你会观察到:**

第 4 个最容易判断错. 导航条看起来只是几个链接, 像是不需要状态的, 但它在窄屏上有一个能展开
收起的菜单, 所以它是 client. 而它需要的品牌文案是**由分组壳读好之后当 props 传进去的**, 它
自己不去读.

> **关键洞见:** 一个组件是 server 还是 client, 看的不是它复杂不复杂, 是它要不要碰文件系统,
> 要不要记住东西, 要不要响应点击.

## 11. 回顾: 我们学到了什么

| 东西 | 一句话 |
| :--- | :--- |
| 路由怎么来的 | `app/` 下的目录层级就是网址层级, 目录里的 `page.tsx` 就是渲染的内容 |
| 带括号的目录 | 路由分组, 不进网址. 用来给一组页面套同一层壳 |
| 下划线开头的目录 | 私有目录, 不当路由. 用来把组件放在离用它的页面近的地方 |
| 三层壳 | 根壳管 html 字体和全站元信息, 分组壳管导航条, 页面负责读盘 |
| server 和 client 的线 | 读盘的往上放, 有状态的往下放, 中间用 props 连 |
| props 要能序列化 | 跨过那条线的东西必须是纯数据, 所以 TOML 解析出来的对象传得过去 |
| SEO | 页面只传标题和描述, 分享预览的字段自动回退, 手填一遍只会多出不一致的地方 |
| 静态生成 | 文案在构建时读进来烘死, 请求时不读盘. 所以读盘的代码必须是 server only |

## 12. 导师寄语

**为什么先讲壳再讲内容:**

大多数人学一个前端框架是从组件开始的: 怎么写一个按钮, 怎么传 props, 怎么管状态. 那些东西
搜一下就有, 而且各家框架大同小异.

真正让人卡住的是**框架自己的那些约定**: 为什么这个目录带括号, 为什么这个文件必须叫这个名字,
为什么这段代码放这里能跑放那里就不行. 这些东西不写下来看不见, 而且每个框架都不一样.

所以这一篇讲的全是约定, 不讲组件. 组件在后面三篇里.

**关键洞见:**

- 目录名和文件名本身就是代码. 读这一层的时候不要只读文件内容
- 一个组件是 server 还是 client, 判据是它要不要碰文件系统, 要不要记东西, 要不要响应点击
- 缺了不报错只是功能消失的东西最难查. 那一行提示条容器就是一个例子

**下一步:**

这一篇里页面反复在做一个动作: 读盘拿文案. 第 9 篇 (文案住在一个文件里) 讲那条路径的全貌,
以及为什么界面上每一句话都不许写在组件里.

## 13. 速查

**约定速记:**

```text
app/xxx/page.tsx        ->  /xxx
app/(xxx)/page.tsx      ->  /        括号目录不进网址
app/_xxx/               ->  不是路由  下划线目录不当路由
layout.tsx              ->  壳, 包住这一层下面所有页面
loading.tsx             ->  加载中显示的东西
```

**server 和 client:**

- 默认是 server. 写了 `"use client"` 才到浏览器
- 读盘的往上放, 有状态的往下放, 中间用 props 连
- 跨过这条线的 props 必须能被序列化

**关键文件:**

- `app/layout.tsx`: 根壳, html 标签, 字体, 全站元信息
- `app/(marketing)/layout.tsx` 与 `app/chat/layout.tsx`: 各自的导航条
- `lib/seo/generateMetadata.ts`: 页面元信息的合并函数

**看路由表:**

```bash
mise run build-web
```
