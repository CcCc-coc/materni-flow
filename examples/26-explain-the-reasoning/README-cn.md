# 最后一条消息不一定是答案

> 你以为 agent 跑完会给你一句回答. 它给的是一叠草稿纸, 而答案不一定在最后一张上.

## 1. 概览

前四篇拆完了 agent 本身: 眼睛, 手, 那只最要紧的手, 脑子. 这一篇转向**它说完话之后**.

先说一件和直觉不符的事. 你在第 20 篇 ([直接调模型](../20-call-the-model-directly/README-cn.md))
调模型时, 拿到的是**一个回答**, 挖出来就一行代码.

**agent 不是这样.** 它跑完之后交回来的是**一整串消息** —— 它想了一步, 调了个工具, 又想一步,
又调一个, 最后才说答案. 每一步都在那串消息里.

而你要从里面挖出两样东西给界面用:

| 要挖出什么 | 给谁看 |
| :--- | :--- |
| **思考** | 那个默认折叠的块 (第 11 篇讲过) |
| **答案** | 正文 |

这件事有多难? 代码只有一百一十行. 但它里面有**三个坑**, 而且三个都不报错.

### 卡住了怎么办

这一篇每一步都可能出错: 脚本跑不起来, 或者输出和这里贴的不一样.
**这些都很正常** —— 你的机器, 你的账号, 你的网络, 和写这一篇时用的那一套不可能完全一样.

**别自己硬猜, 也别只把报错扫一眼就跳过去.** 把下面三样东西一起给 AI, 一样都别少:

| 给什么 | 怎么给 |
| :--- | :--- |
| **你在读哪一篇** | 原样给路径: `examples/26-explain-the-reasoning/README-cn.md` |
| **你敲了哪条命令** | 原样复制那一行, 不要凭记忆转述 |
| **终端打了什么** | **把终端里的文字整段复制粘贴给它**, 不要截图, 也不要只说了一句报错了 |

第三样最重要, 也最常被省掉. 一句报错了对 AI 来说和没说一样; 而那几十行原始输出里, 通常有
一行直接写着缺什么.

一段可以照抄的开场白:

```text
我在读 examples/26-explain-the-reasoning/README-cn.md 这一篇.
我敲的命令是:
(把命令粘在这里)
终端打出来的是:
(把完整输出粘在这里)
帮我判断是哪一步出了问题. 一步一步来, 每一步等我做完再往下.
```

**粘贴之前先打码.** 报错信息里有时会带上完整的数据库连接串, 或者一把 key 的片段. 那些东西
不该出现在任何聊天窗口里, 包括跟 AI 的对话.

## 2. 学习目标

先看那串消息长什么样, 否则后面都是抽象的.

一次典型的回答, agent 交回来的是这样三条:

```text
第 1 条  <thinking> 先看一下 risk_grade 这张表</thinking>
第 2 条  Grade C 的实际违约率是 9.89%, 而定价时假设的是 6.0%
第 3 条  <thinking> 接下来我把调试报告写出来</thinking>
```

**答案在第 2 条, 不在最后一条.**

为什么会这样? 因为系统提示词让 agent 答完之后**再调一次写调试报告的工具**. 于是它最后那条
消息只剩一句思考, 正文是空的.

### 如果你无条件读最后一条

那你拿到的答案是**空字符串**. 而空字符串在界面上是什么样?

**是一个思考块, 下面什么都没有.**

用户看到的是: 转了几秒, 冒出一个可以展开的思考块, 然后就没了. 他会以为**卡住了**, 于是刷新
页面重问一遍.

| | 程序层面 | 用户看到 |
| :--- | :--- | :--- |
| 有没有报错 | **没有** | |
| 状态码 | 200 | |
| 日志 | 一切正常 | |
| 界面 | 流正常结束了 | **像死了** |

这就是这门课从第 5 篇讲到现在的那个模式, 在这一层的样子.

学完这个 Task, 你将能够:

1. 说清 agent 交回来的东西和一次普通模型调用有什么不同
2. 解释为什么最后一条消息常常不是答案, 以及无条件读它会怎样
3. 说出这一步的三小步各自干什么, 以及为什么它们被绑成一个函数
4. 解释为什么要把 `<chart>` 这样的标签机械改写成围栏, 而不是靠提示词说服模型
5. 说清一个空答案为什么要用一句话兜底, 而不是让它空着

## 6. 三小步, 绑成一个函数

代码在 [`agent_app/agent_response.py`](../../agent_app/agent_response.py), 一共三步:

| 步 | 干什么 | 用大白话说 |
| :--- | :--- | :--- |
| 1 **收集** | 走一遍所有消息, 把每一段思考都攒起来, 同时记住**最后一条有正文的** | 从一叠草稿纸里, 把所有旁批抄下来, 再找出最后一张写了正文的 |
| 2 **拆开** | 把思考标签从文本里摘出来, 剩下的是答案 | 把旁批和正文分成两摞 |
| 3 **改写** | 把 `<chart>` 这类标签对改成围栏 | 把写歪了的格式扶正 |

### 第一步那个判断是全篇的重点

那一步里有一句很不起眼的判断: **只有当一条消息去掉思考之后还剩下东西, 才把它记成答案.**

就这一句, 挡掉了第 2 节那个空答案.

如果没有它 —— 也就是无条件记住最后一条 —— 那第 3 条消息 (只剩思考) 会把前面那个真答案覆盖掉,
于是答案变成空的.

**一句判断和一个看起来卡死的界面, 中间就差这么点距离.**

### 为什么三步要绑成一个函数

代码里三步没有分开对外提供, 而是包在一个函数里一次做完. 注释说得很直白:
**免得调用方跑了两步忘了第三步.**

而漏掉第三步的后果特别典型: **答案照样到达**, 只是里面那张图没了.

> **一条通用的判断**: 几个步骤如果必须一起做, 就别把它们分开暴露出去. 分开的方便, 换来的是
> 某一天有人只用了其中两步 —— 而且通常不报错.

这条你在第 21 篇 ([多轮对话和缓存](../21-multi-turn-and-caching/README-cn.md)) 见过一次:
那个 `ChatSession` 把三步收进一个方法, 理由一模一样.

## 7. 第三步在防什么: 模型把习惯用错了地方

第三步看起来最像多余的一步, 它其实防的是一个很有意思的现象.

**提示词里要求模型用围栏输出图表**, 也就是这样:

````text
```chart
{ ... }
```
````

但模型 (尤其是小一点的那些) 已经习惯了用 `<thinking>` 这种标签, 于是它会
**把这个习惯推广出去**, 写成:

```text
<chart>
{ ... }
</chart>
```

### 后果是什么

Markdown 遇到一个它不认识的标签, 处理方式是**直接丢掉**.

于是用户看到的是: **这是各等级的违约率对比** —— 然后下面什么都没有. 图整个消失了, 而且
一句话都没报.

### 为什么不去改提示词

这是这一节最值得学的判断. 两条路:

| 做法 | 靠不靠谱 |
| :--- | :--- |
| 在提示词里再强调一遍要用围栏 | **靠不住**. 你在劝一个模型改掉它训练里养成的习惯, 而小模型尤其劝不动 |
| **机械地改写** | 靠谱. `<chart>` 和 ```` ```chart ```` 的对应关系**毫无歧义**, 那就直接换 |

> **判据: 一个转换如果毫无歧义, 就用代码做, 别用提示词求.** 提示词是概率性的 (第 23 篇讲过),
> 而这类转换需要的是确定性.

而且改写只动**单独占一行** 的标签, 所以已经在围栏里面的内容不会被误伤 —— 这类细节是这个仓库
一贯的风格: 一个机械转换必须说清它不碰什么.

## 8. 万一答案真的是空的

上面那些都做完了, 还是可能拿到一个空答案 —— 比如模型这一轮就是没说正文.

这时候 [`api/index.py`](../../api/index.py) 里有一句兜底, 它会把答案换成一句话:

> 我把这个问题想了一遍, 但没有产出最终回复. 上面的推理里有我找到的东西, 你可以让我复述一遍.

### 为什么不让它空着

因为**空着和坏了长得一模一样**.

| 用户看到 | 他会怎么想 | 他会怎么做 |
| :--- | :--- | :--- |
| 一个思考块, 下面空的 | 卡住了 / 坏了 | 刷新, 重问, 或者关掉不用了 |
| 一句我没产出最终回复 | 这一轮没答好 | **展开思考块看看**, 或者换个问法 |

第二种里, 用户手上有下一步动作. 第一种里他只有困惑.

> **关键洞见:** **一个看得见的非答案, 比沉默好调试.** 这条不只对用户成立, 对你自己也成立 ——
> 你在日志里看到那句兜底, 立刻知道发生了什么; 看到一个空字符串, 你得从头查起.

## 9. 练习

### 练习 1: 跑那三组消息, 然后在代码里找到那句判断

**目标:** 看清那串消息的形状, 并找到挡住空答案的那一句.

**怎么做:**

1. 开一个叫 `26-explain-the-reasoning` 的 branch
2. 跑一次那个脚本:

```bash
.venv/bin/python examples/26-explain-the-reasoning/01_parse_three_replies.py
```

3. 对着第 2 组的输出回答: 思考是从**几条** 消息里攒起来的? 答案来自**第几条**?
4. 打开 [`01_parse_three_replies.py`](01_parse_three_replies.py), 读那三组手写的消息, 确认
   第 2 组最后一条**确实只有思考**
5. 打开 [`agent_app/agent_response.py`](../../agent_app/agent_response.py), 在收集那一步里
   **找到那句只有还剩下东西才记成答案的判断**
6. 再找出第三步那个改写函数, 看它的匹配要求标签**单独占一行** —— 想清楚这个要求在防什么
7. 最后跑一次真实的: 起开发服务器, 在 agent 页问一个问题, 答完之后打开
   `tmp/debug_report.md`, 看 agent 自己写的那份报告

**你会观察到:**

第 3 步的答案是: 思考来自第 1 和第 3 条, 答案来自**第 2 条**. 第 7 步那份调试报告的存在,
正是最后一条消息常常只剩思考的原因 —— **写报告是 agent 答完之后才做的事**.

> **关键洞见:** 一个功能 (让 agent 写下自己的推理) 顺手制造了另一处的坑 (最后一条消息不是
> 答案). 这类跨功能的相互作用, 是真实系统里最难提前想到的东西.

### 练习 2: 把那句判断去掉, 看答案怎么变空

**目标:** 亲眼看到那一句判断在承重, 因为去掉它不报错.

**怎么做:**

1. 打开 [`agent_app/agent_response.py`](../../agent_app/agent_response.py), 找到练习 1 第 5 步
   那句判断
2. 把它改成**无条件** 记录, 也就是不管去掉思考之后还剩不剩东西, 都记成答案
3. 再跑一次那个脚本, **只看第 2 组的 answer**
4. 观察: 有没有任何报错? 脚本是正常跑完的吗?
5. 改回去, 再跑一次确认恢复

**你会观察到:**

第 2 组的 answer 变成了 `<empty>`, 而**脚本一切正常, 没有任何报错, 退出码也是 0**.

想象一下这个状态上线之后: 有思考块, 没答案, 日志干净, 监控全绿, 而用户以为你的产品坏了.

> **关键洞见:** 你刚刚改的是**一个判断条件**, 不是删了一个函数. 这类改动最危险的地方在于,
> 它在代码审查里看起来只是简化了一下, 而后果要到用户那边才显形.

## 11. 导师寄语

**为什么这一百一十行值得单独一篇:**

因为它是这门课那条主线最干净的一个标本.

这个文件里三处设计 —— 那句判断, 三步绑一起, 机械改写 —— 每一处防的都是**同一类事故**: 程序
正常跑完, 状态码 200, 日志干净, 而用户面前是一片空白或者一张不见了的图.

你写普通代码的时候, 出错通常会喊一声. 而这一层不会, 因为**这一层的输出是给人看的**, 而
程序判断不了一段文字对人来说算不算一个回答.

**所以这一层的正确性只能靠人提前想到.** 那三处设计每一处背后都是一次真实的事故, 有人盯着
一个空白界面查了半天才明白.

**顺带说一件事.** 你注意到那个空答案的兜底文案了吗 —— 它不只是说出错了, 它告诉用户
**推理还在上面, 可以让我复述一遍**. 那句话把一个死路变成了一个下一步.

写错误提示的时候多想一句: 读到它的人, 接下来能干什么? 这条你在第 17, 20, 22 篇都见过一遍了.

**关键洞见:**

- agent 交回来的是一串消息, 答案不一定在最后一条
- 必须一起做的几步别分开暴露
- 毫无歧义的转换用代码做, 别用提示词求
- 看得见的非答案比沉默好调试
- 一个功能顺手制造另一处的坑, 是真实系统里最难提前想到的东西

**下一步:**

到这里 agent 一直是**只读** 的 —— 它只会查, 不会改. 第 27 篇
([写操作](../27-write-operations/README-cn.md)) 讲为什么默认一个写工具都不带, 以及真要加的
时候, 需要先想清楚哪几件事.

## 12. 速查

**跑那三组消息:**

```bash
.venv/bin/python examples/26-explain-the-reasoning/01_parse_three_replies.py
```

**三小步:**

```text
收集  走一遍所有消息, 攒起全部思考 + 记住最后一条 [还剩正文的]
拆开  把思考标签摘出去, 剩下的是答案
改写  <chart> ... </chart>  ->  ```chart ... ```
```

**三个不报错的坑:**

| 坑 | 症状 |
| :--- | :--- |
| 无条件读最后一条消息 | 答案空了, 界面像卡死 |
| 只跑了三步里的两步 | 答案到了, 图没了 |
| 让空答案就那么空着 | 用户以为坏了, 刷新重问 |

**两条判据:**

- 必须一起做的几步, 别分开暴露
- 毫无歧义的转换用代码做, 别用提示词求
