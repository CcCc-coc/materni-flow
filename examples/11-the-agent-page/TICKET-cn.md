# 看懂 agent 页的空状态设计

## 1. 目标

第 5 篇你在这一页点过按钮, 看着它失败了. 这一篇换个身份,
**看看这一页为什么摆成这个样子.**

核心问题只有一个: 一个聊天界面, 在用户还没打第一个字的时候该显示什么? 大多数人的答案是一个
输入框加一句请输入你的问题, 而那个答案在这里不及格. 面对一个无所不能的输入框, 绝大多数人
打出的第一句是你好, 第二句是你能干什么, 然后就关掉了.

**这一篇的重心在那 12 个按钮上.** 它们不是常见问题列表, 是橱窗. 一个面试官打开你的链接停留
一到两分钟, 他不会自己想一个好问题来考你的 agent, 他会点一个按钮看看会发生什么. 所以那 12
条基本决定了他对这个项目的判断.

**这一篇不需要 agent 能回答.** 两个练习都只看空状态那一屏和几个文件, 一把 API key 都用不上.
真的去点开看它答得对不对, 是第 34 篇 (渲染契约) 的事, 那时候你已经有凭据了.

---

## 2. 要做的事情

1. 读完 README, 重点是 12 个按钮是橱窗那一节和选题判据那张表.
2. 起开发服务器打开 agent 页, 先不打字也不点按钮, 把空状态上有哪几块数清楚.
3. 数一数 12 个按钮上的小图标各类各有几个, 记下来.
4. 打开 `data/site.toml` 找到那 12 条, 数一数每个 `render` 值各出现几次, 和上一步的数字
   对一遍.
5. 打开 `components/chat/RenderBadge.tsx`, 找出三个 `render` 值各自画哪个图标, 以及第四个
   值为什么什么都不画.
6. 挑一条 `render` 是表格的, 读它的 `action` 那句话, 在里面找出两句触发短语.
7. 用一句话说清 `render` 和触发短语分别决定了什么, 以及只对一个会怎样.
8. 试几个输入框周围的防呆: 打一段长文字看框会不会自适应, 打半句话不发直接刷新看草稿还在
   不在.
9. 挑三条 `render` 不同的, 各说清它为什么适合那种形状.
10. 挑一条你觉得最弱的, 说清它弱在选题还是弱在问得太大.
11. 把 `render` 是流程图的那几条挑出来, 读它们的措辞, 归纳出一条判据: 什么样的业务问题适合
    用流程图回答.
12. 拿那条判据去检验剩下几条, 说清它们为什么被分给了表格或者图表.

**预计用时:** 50 到 80 分钟

---

## 3. 检查清单

- [ ] **空状态的问题**: 你能说清一个只有输入框的聊天页为什么等于什么都没给.
- [ ] **三边对过账**: 屏幕上的图标分布, `site.toml` 里的 `render` 分布, 和 `RenderBadge.tsx`
      里那张映射表, 你三样都数过并且对得上.
- [ ] **两件事不是一件事**: 你能说清 `render` 决定按钮上画什么, 触发短语决定实际出什么, 以及
      只对一个的后果是徽章撒谎.
- [ ] **配额在防什么**: 你能说出四类各三条这个配额在防什么, 也能说清脚本验的是问法而不是
      模型照没照做.
- [ ] **徽章的含义**: 你能说出那个小图标在向读者承诺什么, 以及 `free` 为什么故意不画.
- [ ] **选题判据会用**: 你对三条 kickstart 说清了它为什么适合那种形状, 也挑出了最弱的一条并
      说清它弱在哪.
- [ ] **消息气泡三种内容**: 你能说出思考, 正文, 其它类型各怎么处理, 以及思考为什么默认折叠
      但要留一段预览.
- [ ] **对话状态**: 你能说清对话存在哪儿, 刷新之后什么没了, 什么还在.
