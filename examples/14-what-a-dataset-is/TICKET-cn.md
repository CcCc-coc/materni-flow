# 认识一个数据集, 并把数据造出来

## 1. 目标

上一篇你三条命令一路敲下来 app 就活了, 但那三条命令做了什么你还不知道. 接下来四篇回头把它
讲清楚, 而这是第一篇: 拆开其中的 `gen-data`.

它要纠正一个几乎所有人都有的直觉. 你以为数据集是一个数据库文件或者一堆 CSV, 拿到就能用.
**这个项目里的数据集是四份人写的文档加一个生成器, 数据库是跑出来的**, 所以它根本不在 Git 里.

**这一篇最值得带走的是一条判据: 能确定性生成出来的东西, 就不该被保存.** 它管的不只是数据库,
编译产物, 打包结果, 缓存都是同一类东西. 保存冗余的代价不是占地方, 是它会和源头不同步,
而且不同步的时候**没有任何东西会报错**.

练习 1 里有一步是**故意在目录里放两个数据库文件**. 一定要做, 因为它让你亲眼看到这个项目
在面对含糊状态时的选择: 宁可当场报错, 也不肯挑一个凑合用. 挑一个的后果是错的数据集被安静
地端上桌, 而你要到某个答案明显不对时才会发现.

这一篇还埋了一条线通向第 37 篇 (换数据集): **那时候你要整体换掉的, 正是这五个文件.**

---

## 2. 要做的事情

1. 读完 README, 重点是为什么不进 Git 那三层理由, 和文件名为什么是找出来的那一节.
2. 开一个叫 `14-what-a-dataset-is` 的 branch.
3. 打开 `dataset/` 目录, 对着 README 第 5 节那张表认一遍那五个文件.
4. 各花两分钟扫一眼 `01-` 那份业务背景和 `02-` 那份 ER 文档的目录, 不用细读.
5. 再跑一次 `gen-data` (上一篇已经跑过一次了), **这次你会看到它什么都不做**, 想清楚为什么.
6. 对照上一篇记下的文件名和大小, 确认那个文件一个字节都没变.
7. 把生成出来的文件复制一份改个名, 制造出目录里有两个 `.sqlite` 的状态.
8. 跑 `.venv/bin/python examples/14-what-a-dataset-is/01_find_the_seed.py`, 读那条报错.
9. 删掉复制出来的那个, 再跑一次确认恢复正常.
10. 打开生成器, 找到那个被钉死的参考日常量, 想清楚为什么不用系统时间.
11. 对五个文件各找两句话: 一句只有放贷才会说的, 一句换个行业照样成立的.
12. 数出哪一份几乎找不出通用的句子, 并回答换个行业时哪一份最难写.

**预计用时:** 50 到 80 分钟 (生成器本身要跑几分钟)

## 3. 检查清单

- [ ] **五个文件说得出**: 你能说出 `dataset/` 里那五个带编号的文件各自是什么, 以及这个编号
      顺序为什么是从人到机器.
- [ ] **数据库造出来了**: `dataset/` 下面有了一个 `.sqlite`, 你知道它多大, 也知道它不在 Git 里.
- [ ] **那条判据**: 你能解释为什么可再生的东西不该保存, 并能再举出一个同类的例子.
- [ ] **跑第二次的行为**: 你亲眼看到重复跑什么都不做, 并能说清 `--force` 为什么要先删光所有
      `.sqlite` 而不只是覆盖.
- [ ] **见过拒绝选择那条报错**: 你制造过两个数据库文件的状态, 读过那条报错, 并能说清为什么
      取第一个是更坏的做法.
- [ ] **钉死日期的理由**: 你能说清生成器为什么不用系统时间, 并能说出这条习惯管的是哪一类东西.
- [ ] **文件名为什么找出来**: 你能把这件事和 `agent_app/` 一行不改那句承诺连起来.
- [ ] **依赖为什么分开**: 你能说清生成器的依赖为什么不写进 `pyproject.toml`, 理由要落在会不会
      一起被删掉这条判据上.
- [ ] **工作区干净**: 练习里复制出来的那个文件删掉了.
