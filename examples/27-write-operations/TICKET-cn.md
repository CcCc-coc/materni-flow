# 写操作: 为什么默认一个都没有

## 1. 目标

到这一篇为止 agent 做过的每一件事都是**只读** 的. 它一个改数据的工具都没有, 而
**这是一个决定, 不是一个遗漏**.

理由不是笼统的写操作危险, 而是很具体的一条: **写操作天然跟数据集绑定.** 放贷的库该有什么写
操作, 和物流的库完全不同. 而 `agent_app/` 的核心承诺是换数据集时一行都不改 —— 带一个默认写
工具, 就等于把某个数据集的痕迹刻进那个包里.

所以代码里留的是**一个位置加一句注释**, 不是一个通用实现.

**这一篇没有代码可读**, 它读的是留白. 也是这门课里唯一一篇读完之后**正确的行动是什么都不做**
的: 练习 2 那三个问题在这个项目上答不上来 (它是公开网站, 没有登录), 而
**答不上来就是停下来的信号**.

顺带你会撞到这门课的老朋友: `api/index.py` 的模块说明写着这个后端连的是带写操作能力的
agent —— 那是一句过期的话. **散文没有编译器**, 这个仓库自己也一样会中招.

---

## 2. 要做的事情

1. 读完 README, 重点是第 5 节为什么默认不带, 和第 8 节那三个问题.
2. 开一个叫 `27-write-operations` 的 branch.
3. 打开 `agent_app/one/one_04_agent.py` 的工具清单, 读三个工具下面那句注释.
4. 数清楚清单里有几个工具, 确认它们全都是只读的.
5. 打开 `agent_app/sql_utils.py`, 看那几个函数的签名, 确认第一个参数都是数据库连接.
6. 严格搜一次写语句 (`UPDATE `, `INSERT INTO`, `DELETE FROM`), 确认零结果.
7. 把范围放宽到建表删表 (`drop table`, `drop_all`, `.insert(`), 看这次搜到什么.
8. 确认搜到的全在同一个文件里, 想清楚那个文件为什么可以写, 以及它什么时候会消失.
9. 打开 `api/index.py`, 读最上面那段模块说明的第二句, 和你第 4 步数出来的结果对照.
10. 对那个标记申请为已复核的提议, 逐条回答第 8 节那三个问题.
11. 特别想清楚第三个: 这个 app 有登录吗, 那么谁能触发它.
12. 给那个提议写一段工具说明, 必须答上它会改什么, 以及可不可逆.
13. 让 AI 说清按这个仓库的约定, 底层 helper 该是什么形状, 放哪个文件, 检查它答得对不对.

**预计用时:** 50 到 75 分钟

## 3. 检查清单

- [ ] **为什么默认不带**: 你能说清理由落在写操作天然跟数据集绑定上, 而不是笼统的危险.
- [ ] **留白找到了**: 你在工具清单里找到了那句注释, 也能说清为什么留一句话比留一个通用实现好.
- [ ] **搜索做过两次**: 严格搜零结果, 放宽之后全在一个文件里, 你能说出那是哪个文件, 以及它
      为什么可以写.
- [ ] **那句过期的说明**: 你找到了 `api/index.py` 里那句带写操作能力, 并能说清它为什么没被
      任何检查抓住.
- [ ] **能写之后什么变了**: 你能说清 agent 自己试错这个优点, 为什么在能写之后变成最危险的部分.
- [ ] **三条约束说得出**: 形状 (纯函数), 说明 (改什么 / 可不可逆), 场景 (怎么发现 / 怎么回退 /
      谁能触发).
- [ ] **第三个问题的答案**: 你能说清这个 app 没有登录, 所以任何知道链接的人都能触发写操作.
- [ ] **协议那道闸门**: 你能说出那对批准事件是干什么的, 以及它为什么在这个 app 里还没用上.
- [ ] **结论是不加**: 你能说清为什么现在正确的行动是什么都不做.
