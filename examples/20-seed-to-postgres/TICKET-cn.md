# 把种子发布到 PostgreSQL

## 1. 目标

数据在你硬盘上, 但 **agent 从来不读那个文件**. 这一篇把它搬到 agent 真正读的地方, 搬完之后
第 4 篇那个一点就报错的 agent 页就能用了.

命令只有两条, 但这一篇一多半在讲**三个当初都选错过的决定**: 本地开发读哪个库, 多项目共用
一个实例怎么隔离, 以及怎么让连接认准我们那个 schema.

**三个决定有一个共同点, 也是这一篇最想让你带走的: 它们选错的时候全都不报错.**

第一个决定顺便收掉上一篇留的悬念. 那二十个查询是 SQLite 方言, 而 agent 查 PostgreSQL,
所以直觉的做法是按环境切换引擎. 这个做法行不通, 理由只有一条: **查库的不是人, 是模型**,
而模型照抄的那份提示词**只有一份**, 没办法两个环境两个样.

**练习 1 的第 9 步是这一组四篇真正的收尾**: 把 agent 给出的违约率, 和你上一篇自己跑
`01_pricing_gap.py` 得到的数字对一下. 一个你无法校验的 AI 系统, 是不能拿去给别人用的.

---

## 2. 要做的事情

1. 读完 README, 重点是那三个决定, 尤其是 `search_path` 那三种写法.
2. 开一个叫 `20-seed-to-postgres` 的 branch.
3. 先确认连得上: `.venv/bin/python scripts/test_05_connect_remote_database.py`.
4. 跑 `sync-db`, 把它报出来的那个建表顺序抄下来.
5. 对照第 18 篇你画的主线图, 确认那个顺序真的是先父后子, 查找表在最前, 流水表在最后.
6. 跑 `verify-db`, 确认每张表行数都一致, 没有 exit 1.
7. 跑 `.venv/bin/python scripts/test_04_print_database_schema.py`, 这次应该打印出十张表.
8. 重启开发服务器 (Ctrl+C 退出再 `mise run dev`), 打开 agent 页.
9. 点那个关于风险等级定价的 kickstart 按钮, 等它答完.
10. **把它给出的违约率和你上一篇跑出来的数字对一下**, 确认对得上.
11. 在 `.env` 里加一行把 `SCHEMA_NAME` 指到一个不存在的名字, 重启后再问一次, 读那条报错.
12. 做一个思想实验: 如果没有那个检查, agent 会回答什么.
13. 删掉那一行, 重启, 确认恢复正常.

**预计用时:** 50 到 80 分钟 (同步本身要跑几分钟)

---

## 3. 检查清单

- [ ] **数据到位**: `verify-db` 输出的逐表行数全部一致, 没有 exit 1.
- [ ] **agent 通了**: 你在 agent 页点 kickstart 拿到了带真实数字的回答.
- [ ] **自己校验过一次**: 你把 agent 给的违约率和自己写 SQL 查出来的对上了, 也明白为什么
      这个动作比 agent 本身更重要.
- [ ] **为什么两边都读 PostgreSQL**: 你能说清这个项目为什么不按环境切换引擎, 理由要落在
      提示词只有一份这件事上; 也能说清方言不对时的症状为什么是答案变差而不是报错.
- [ ] **schema 不是前缀**: 你能用文件夹这个比方解释 schema, 并说清加表名前缀会让提示词在
      哪个环境错.
- [ ] **`search_path` 三种写法**: 你能说出三种分别会怎样, 特别是第二种为什么是间歇性失效,
      以及为什么事务是对的粒度.
- [ ] **校验为什么比行数**: 你能说清只问一句远程有没有数据的检查, 会漏掉哪种失败.
- [ ] **不同步的后果**: 你亲眼见过那条异常, 也能说清如果没有它 agent 会编出什么.
- [ ] **工作区干净**: `.env` 里临时加的那一行删掉了.
