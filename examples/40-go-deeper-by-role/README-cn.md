# 从这里往下挖的八条路

## 1. 概览

第 2 篇 ([这个项目是什么](../02-why-this-project/README-cn.md)) 开头讲过一句话, 当时你大概
听过就算了:

> **这个项目每一块都只做了一丢丢, 但每一块都留了往下挖的口子.**

那时候你还没见过任何一块. 现在你全部见过了, 所以这句话可以兑现了.

上一篇讲的是**横着用**: 换一个行业, 再换一个行业. **这一篇讲竖着挖**: 在某一层上做深.

### 先说清楚这一篇不做什么

**这一篇只告诉你可以怎么深挖, 不教你怎么做.**

八个方向, 随便哪一条认真做都够写一门课 —— 训一个真能用的模型, 搭一条幂等的数据管道, 给
一个 agent 加上完整的护栏和追踪, 每一件都是独立的手艺. **那些统统不是这个模块的事情.**

这一篇要做的只有三件:

| 它做 | 它不做 |
| :--- | :--- |
| 告诉你**门在哪** —— 具体到文件 | 不带你走进去 |
| 告诉你**什么完全不用动** —— 省下的那部分 | 不教你动的那部分该怎么写 |
| 告诉你**那扇门后面是谁** —— 这条路上资深的人在做什么 | 不告诉你怎么变成那个人 |

**所以读完这一篇你不会多一项技能, 你会多一个判断**: 你那个方向, 下一步该往哪儿走, 以及
第一步该从哪个文件开始. **具体怎么走, 是你自己或者别的模块的事.**

这不是偷懒, 是这一篇唯一诚实的写法 —— 八条路的深度不可能对等, 而每个人只走其中一条.

### 这一篇的机制

**先把它一句话说完**, 因为它是全部内容:

> **这个项目大约九成是可复用的展示层, 一成是你的专业.**
> 你想往哪个方向深挖, 就只做那一成; 剩下九成改个名字就是你的.

具体一点: 一个讲清业务的网站, 一个会调工具会解释推理的 agent, 一条从数据库到浏览器的完整
链路, 一次部署, 一个自己的域名 —— 这些**八个方向的人用的是同一套**.

**而你的那一成里, 最重要的往往不是代码, 是一份为你这个方向重新设计的数据集和业务背景.**
这一点第一版没说清楚, 值得提前打个招呼: 现在仓库里这份放贷数据是**为业务分析设计的**, 它
撑不起机器学习, 也撑不起数据管道 —— 想往那两个方向挖, 你要先造一份撑得起的数据.

**这就是为什么这个脚手架能支撑八个完全不同的方向**, 而且每一个都能挖到很深: 它不替你决定
往哪走, 它只是把每个方向都必须付的那笔过路费, 一次性替你付了.

这一篇的写法因此和前面所有篇都不一样:

- **它不教怎么做.** 八条路里随便哪一条, 认真做都够写一门课
- **它告诉你门在哪.** 每一条路都挂在这个仓库里一个具体的文件上, 并且说清**什么完全不用动**
- **它还告诉你那扇门后面是谁.** 每一条路通向的, 都是那个岗位上**资深的人真正在做的事**

**你不需要全读.** 找到你那一条, 认真读; 其余的扫一眼, 知道它们存在就行 —— 因为你三年后可能
就在另一条上了.

## 5. 机制: 九成白送, 你只深挖那一成

这一节先讲清楚这一篇凭什么成立, 不然下面八节读起来会像八段没头没尾的建议.

**把这个项目拆成两块看:**

| 这一块 | 谁做的 |
| :--- | :--- |
| **展示层**: 一个讲清业务的网站, 一个会调工具会解释推理的 agent, 一条从数据库到浏览器的完整链路, 一次部署, 一个你自己的域名 | **已经做完了.** 八个方向共用同一套, 你改个名字就行 |
| **数据集和业务背景**: 有哪些表, 数据怎么产生, 这门生意怎么运转 | **多数方向要重新设计.** 见下面那张表 |
| **你那一层的深度**: 模型, 管道, 运维, agent 能力, 交互 | **只有你能做.** 这正好是你的专业 |

**代码那一侧, 九成是白送的.** 而你要投入的那一成, 里面**最重的往往不是代码, 是数据**.

### 先说一件容易被误解的事: 现在这份数据撑不起所有方向

仓库里这份放贷数据集是**为业务分析设计的**. 它有十张表, 有像样的外键, 有能问出好问题的业务
逻辑 —— 但它是一次性生成的一份静态快照, 而且里面的因果关系是造数脚本编出来的.

**这意味着两件事:**

- **想做机器学习, 你不能直接拿它训模型.** 训出来的东西学到的是造数脚本的规则, 不是真实
  世界的规律. 你需要一份**为建模设计** 的数据: 有一个值得预测的标签, 有真的存在的信号,
  有类别不均衡, 有按时间切开的训练和测试
- **想做数据管道, 你不能直接拿它做增量.** 它是一份不会变的快照, 而管道的全部难度来自
  **数据会变**: 新数据陆续到达, 事实迟到, 记录被修正

所以八个方向对数据的要求差别很大:

| 方向 | 要不要重新设计数据集 |
| :--- | :--- |
| Business Analyst | **要.** 要更多表, 更长的时间跨度, 更真实的脏 |
| Data Scientist | **要, 而且是重点.** 数据里得真的有个可学的信号 |
| Data Engineer | **要, 而且是重点.** 数据得会随时间增长和变化 |
| Machine Learning Engineer | **要, 上面两条都要.** 数据会变, 而且变了模型该跟着变 |
| SDE | **不用.** 你做的是运行时那一层, 库里躺着什么无所谓 |
| AI Engineer | **基本不用.** 更难的数据能让你的工作更有意思, 但不是前提 |
| Finance Engineer | **要.** 组合, 头寸, 净值, 风险因子, 和现在这份完全不同 |
| UX Design | **不用.** 你做的是结果拿到之后那一步 |

**要重新设计数据集的那五条, 都要先学会手搓数据和业务背景, 那是另一个模块的内容.** 这一篇
只负责告诉你: 你那条路上, 数据是不是你要先解决的问题.

**而不用重新设计的那三条 (SDE, AI Engineer, UX), 是这八条里起步最快的** —— 你今天就能动手.

### 为什么这件事值这么多

想一下你要向别人证明你某方面很强, 传统上要做什么.

假设你是数据科学家, 想让人看到你会建模. 你得: 找一份数据, 清洗它, 训一个模型,
**然后做一个能让人看见这个模型的东西** —— 一个界面, 一个后端, 一次部署. 前后两三个月, 而
**其中只有训模型那一小段是你的专业**, 剩下全是为了让人看得见而付的过路费.

**大多数人就是卡在这个过路费上.** 不是不会建模, 是建完之后没有一个地方能把它摆出来, 于是
它躺在一个 notebook 里, 谁也不会点开.

**用这个脚手架, 那笔过路费你已经付过了.** 你要做的只剩两件:

1. 把你那一层往深里做 —— 这本来就是你想做的事
2. 加一个把它接进来的口子, 通常是一个 `@tool` 方法, 或者一份新的数据集

**界面不用改, 部署不用重来, 域名不用重买, agent 那套工具调用和解释推理的逻辑一行不动.**

### 而且展示这件事本身也在替你说话

还有一层容易被忽略的收益.

你交出去的不只是你那一层的深度. 你同时交出去的是
**一个部署在自己域名上, 接着真数据库, 会调工具的 AI 应用** —— 这本身就在证明第 39 篇说的
那件事: 你用 AI 把东西交付出去的能力很强.

**所以每一条路都是双份的**: 上面证明你的专业, 下面证明你的交付能力. 而下面那一半, 八个方向
用的是同一套代码.

### 所以这一篇怎么读

下面八节, 一个方向一节. 每一节都是同一个结构:

| 三段 | 回答什么 |
| :--- | :--- |
| **现在到哪儿了** | 这个项目在你这一层做到了什么程度, 也就是你的起点 |
| **可以怎么做** | 往下挖具体动哪个文件, 以及什么完全不用动 |
| **为什么这是资深的人在做的事** | 这条路的终点是什么, 而它和初级的差别在哪 |

**找到你那一节认真读**, 其余的扫一眼就行 —— 但值得扫一眼, 因为你三年后可能就在另一条上了.

> **这个脚手架不限制你往哪个方向挖.** 它只是把每个方向都必须付的那笔过路费, 一次性替你付了.

## 6. Business Analyst: 把问题问得更难

**如果你是做业务分析的**, 你要深挖的是**业务本身的复杂度**: 一门更绕的生意, 更多的表, 更长
的时间跨度, 以及更接近真实的脏.

**所以你要重新设计一份数据集**, 而不是在现在这份上加问题. 现在这十张表能问出来的东西是有
上限的, 你想问同比环比, 想问留存, 想问一个主体在不同时期的不同身份, 数据里得先有那些东西.

**但你写的不是应用代码**, 是那份数据集的文档和造数脚本, 加上
[`data/system-prompt.md`](../../data/system-prompt.md) 里的领域知识. 网站, agent, 工具调用,
部署, 域名, 全部原样复用.

**这条路的门槛在于设计而不在于工程** —— 而设计一门生意怎么运转, 正好是你本来就会的事.

**现在到哪儿了.** 十张表, 中等规模, 一份写了 20 条业务查询的文档. 那 20 条覆盖的大多是单表
聚合和两三张表的关联.

**可以怎么做.**

往上加难度, 而难度不来自表更多, 来自**问题更难**:

- 把 [`dataset/`](../../dataset) 里那份业务查询文档从 20 条扩到 50 条, 而且新增的那些要用到
  窗口函数, 同比环比, 留存分析这类东西
- 引入时间维度上的脏: 迟到的事实, 被修正过的历史记录, 同一个主体在不同时期的不同标识
- 每加一条难查询, 就在提示词的 `## Derived Business Concepts` 里补一条**外行会算错的公式**

**你会立刻撞上一件事**: 提示词那一节会膨胀得很快, 而且你会发现自己在反复回答同一个问题 ——
这个指标在什么口径下成立.

**为什么这是资深的人在做的事.**

初级的分析师**回答被问的问题**. 资深的分析师**定义该问什么问题**, 并且知道一个指标在什么
口径下会骗人.

这个项目里有一个地方专门装着后者: 提示词里那一节写的全是外行会算错的东西. 它存在的理由不是
模型算不来除法, 是**因为一个业务口径里的坑, 只有懂这一行的人才知道**.

**第一步可以是**: 从那 20 条里挑一条, 想出三个它答不了但业务上很自然的追问, 然后把其中一个
补进去.

## 7. Data Scientist: 从描述过去到预测未来

**如果你是做数据科学的**, 你要深挖的是**模型**: 特征, 训练, 评估, 以及一个模型该怎么被用.

**但第一件事不是训模型, 是造一份值得训的数据.** 现在这份放贷数据是为业务分析设计的, 里面
的因果关系是造数脚本编出来的 —— **在它上面训模型, 学到的是那个脚本的规则**, 而且指标会好得
可疑. 那种东西拿去面试, 一个懂行的人问两句就会露馅.

**所以你的第一步是重新设计数据集**, 而且要为建模而设计: 一个值得预测的标签, 一批真的和它
有关系的特征, 一点噪声, 一个不均衡的类别分布, 以及一条能按时间切开训练和测试的时间轴.

**做完这一步之后, 代码就只剩两处了**: 你的模型模块本身, 和一个把它接进来的 `@tool` 方法.
前端一行不改, agent 那套逻辑一行不改, 部署不用重来.

**而那正好是第 5 节说的那笔过路费.** 你的模型不再躺在一个 notebook 里, 它变成了一个别人能
在浏览器里用一句话问出来的东西.

**现在到哪儿了.** 这个 agent 全部的能力都是**描述已经发生的事**: 上个月的通过率, 各风险等级
的违约率, 定价缺口. 它不预测任何东西.

**可以怎么做.**

用库里已有的数据训一个模型, 然后让 agent 能查它:

- 模型本身在 `agent_app/` 之外单独一个模块, 它只做一件事: 给一个主体, 返回一个预测
- 在 [`one_04_agent.py`](../../agent_app/one/one_04_agent.py) 里加一个 `@tool` 方法, 让 agent
  能调它. 第 23 篇 ([第一个 agent](../23-your-first-agent/README-cn.md)) 讲过怎么加
- 前端**一行都不用改**. 模型的输出还是文字和表格, 走的还是原来那套渲染

**这里有一个真正的设计题, 而且它不是技术问题**: 预测结果应该**作为一个工具返回给 agent**,
还是**作为一列写回数据库**?

两种做法的可解释性和可回滚性完全不同. 写回数据库的那种, agent 可以在 SQL 里直接用它做筛选
和分组, 很强大 —— 但用户看到一个数字的时候, 分不清那是观测到的还是算出来的. 而模型换了一版
之后, 库里那一列是旧的.

**为什么这是资深的人在做的事.**

初级的数据科学家**调指标**: 让 AUC 高一点, 让特征多一点. 资深的** 决定这个模型该不该上线, 以及
它错的时候谁承担**.

上面那个设计题正是这个判断的一个具体形态. 它没有标准答案, 但一个想清楚了的人和一个没想的人,
做出来的系统在一年后差别巨大.

**第一步可以是**: 先不训模型, 只回答那个设计题, 并写下你的理由.

## 8. Data Engineer: 让数据自己流进来

**如果你是做数据工程的**, 你要深挖的是**管道**: 增量, 调度, 幂等, 可重放.

**而管道的全部难度来自一件事: 数据会变.** 现在这份数据集给不了你这个 —— 它是造数脚本跑
一次产出的一份静态快照, 你把它同步一百遍结果都一样, 于是增量, 迟到, 修正这些真正的问题
一个都不会出现.

**所以你的第一步是重新设计数据的产生方式**: 让造数脚本按时间片产出批次, 让一部分事实迟到,
让一部分记录事后被修正, 让主键偶尔重复. **有了会变的数据, 你要做的那些事才成立.**

**之后你动的全在数据那一侧**: 同步逻辑, 一个定时任务, 一个水位线. 网站不用管, agent 不用
管 —— 它们只管从库里读, 库怎么被填满是你的事.

**而这条路有一个别的方向没有的好处**: 你的成果天然是可演示的. 管道跑一次, 网站上的数字就
变一次, 而那是别人肉眼可见的.

**现在到哪儿了.** 这个项目的数据管道是: 跑一次生成器造出 SQLite, 再跑一次同步把它整个推到
PostgreSQL. **一次性的, 全量的, 手动的.**

对一个教学项目这完全够用. 对任何真实系统这三条都不成立.

**可以怎么做.**

一条一条把它们换掉:

- **从全量到增量.** 现在的同步是删掉重建. 换成按主键的更新插入, 只动变化了的行
- **从手动到调度.** [`vercel.json`](../../vercel.json) 里那个空着的定时任务配置就是入口 ——
  它现在是一个空数组, 那是一扇明摆着的门
- **从一次性到可重放.** 加一个水位线, 记住上次同步到哪儿了, 断了能接着来
- **从能跑到幂等.** 同一批数据同步两遍, 结果必须和一遍一样

**有一样东西不用你操心, 而且值得注意**: 建表顺序. 这个项目从来没有一份手写的表顺序清单,
它是从外键关系**推导** 出来的 —— 第 15 篇 ([把种子发布上去](../15-seed-to-postgres/README-cn.md))
讲过这件事. 加一张表不需要改任何配置.

**为什么这是资深的人在做的事.**

初级的数据工程师**把数据搬过去**. 资深的**保证搬第二遍和第一遍结果一样**, 并且能说出上游坏了
之后下游多久会发现.

那个幂等要求听起来像洁癖, 直到你第一次遇到同步跑到一半失败. 那时候你只有两个选择: 重跑, 或者
手工修. 而只有幂等的管道敢重跑.

**第一步可以是**: 把现在那个同步跑两遍, 观察它第二遍做了什么, 然后回答一句它是不是幂等的.

---

## 9. Machine Learning Engineer: 让模型跟着数据一起变旧

**如果你是做机器学习工程的**, 你要深挖的是**那条链**: 数据刷新怎么触发重训, 重训怎么评估,
评估怎么决定上不上线.

**这条路的数据要求是八条里最高的, 因为它把上面两条叠在了一起**: 数据既要有一个可学的信号
(不然重训没意义), 又要会随时间变化 (不然没有东西触发重训).
**一份不会变的数据上, 这条链的每一环都退化成一次性脚本.**

**所以你的第一步同样是设计数据**, 而且要设计出一个会随时间**漂移** 的世界: 某个特征的分布
在第六个月悄悄变了, 于是旧模型开始变差 —— 那一刻正是这条路全部价值所在.

**上一节那条数据管道和上上节那个模型, 是你这条路的两个端点**, 你做的是把它们连起来的那
一段. 展示层同样一行不动.

**这条路最能体现第 5 节那个双份收益**: 一条自动化的流水线本身很难展示, 而挂在这个项目上,
它的产出立刻变成一个网页上会自己更新的数字.

**现在到哪儿了.** 上面第 6 节那条路是训一个模型. **这一条是让那个模型不会烂掉.**

这两件事经常被混为一谈, 而它们是完全不同的工作.

**可以怎么做.**

把四件事串成一条能自动跑的链:

| 环节 | 要回答的问题 |
| :--- | :--- |
| 数据刷新 | 新数据什么时候到, 怎么知道到了 |
| 重新训练 | 用多长的窗口, 旧数据要不要衰减 |
| 评估 | 拿什么当基准, 用哪个指标, 阈值是多少 |
| 上线决策 | 新的不如旧的时候, 怎么办 |

**最后一行是这条路真正的难点**, 而且它经常被漏掉. 大多数人做出来的流水线只会往前走: 数据来
了就重训, 训完就换上. 那种流水线在数据出问题的那一天, 会用一个更差的模型悄悄替掉一个好的.

**为什么这是资深的人在做的事.**

初级的机器学习工程师**让流水线跑通**. 资深的**让它敢于不上线**.

那道闸门比流水线本身难写得多, 因为它要回答一个统计问题 (这次的下降是波动还是真的变差),
而不是一个工程问题.

**这个项目里有一个现成的类比可以借**: 第 33 篇 ([那道花费闸门](../33-the-spend-cap/README-cn.md))
里那个配额, 它的核心也是一道**拦在动作之前** 的闸门, 而且它想清楚了自己坏掉的时候该放行还是
该拒绝. 那个思路可以直接搬过来.

**第一步可以是**: 先不写流水线, 只写那道闸门的判据 —— 什么情况下不换.

---

## 10. SDE: 让它坏的时候你知道

**如果你是做软件工程的**, 你要深挖的是**这套东西怎么在没人盯着的时候还活着**: 日志, 探活,
错误上报, 连接管理, 高可用.

**你动的是运行时那一层**, 而业务逻辑, 数据, 提示词, 界面全都不用碰. 换句话说,
**你可以完全不懂放贷这门生意, 照样把这条路走得很深**.

**这也让它成为八条里起步最快的一条.** 上面四条都要先重新设计一份数据集, 而你不用 —— 现在
仓库里这份数据对你来说完全够用, 因为你关心的是请求怎么进来, 出错怎么被发现, 而不是库里
躺着什么.

**这条路的展示方式和别的不一样**: 别人展示的是页面上多了什么, 你展示的是一份日志能把一次
请求从头串到尾, 或者一次故障如何被自动发现. 这个东西在面试里非常好讲.

**现在到哪儿了.** 一个 Vercel 项目, 一个 Neon 数据库, 出问题只能去翻函数日志. 而日志里现在
只有零星几行, 都是 `debug` 打出来的.

**可以怎么做.**

- **把日志做成结构化的.** 现在 [`utils.py`](../../agent_app/utils.py) 里那个 `debug` 只是往
  标准错误打一行字. 换成带请求标识, 时间, 耗时的结构化输出, 你就能按一次会话把整条链路串起来
- **加一个真正的探活.** 现在的 `/api/hello` 只证明函数活着. 一个真探活要顺带确认数据库连得上
- **把错误报出去.** 现在一次失败的表现是用户看到一段错误文字, 而你什么都不知道
- **想清楚连接的行为.** 无服务器环境里每个函数实例都可能自己开一条数据库连接, 而数据库的
  连接数是有上限的. 这个项目用带连接池的那个主机名就是在处理这件事

**这个仓库里已经有一个很小但很典型的样本**: `debug` 走标准错误而不是标准输出. 第 35 篇
([把它送上公网](../35-deploy-to-vercel/README-cn.md)) 讲过为什么 —— 那是一个纯粹的运维判断,
它不改变任何功能, 只是让一类静默的错误不会发生.

**为什么这是资深的人在做的事.**

初级的工程师**让它跑起来**. 资深的**让它坏的时候你知道**.

这句话听起来平淡, 但它区分了两种系统: 一种是出了事你从用户投诉里得知, 另一种是出了事你先
知道. 后者贵得多, 而且它的成本几乎全在上线之前.

**第一步可以是**: 给 `debug` 加一个请求标识, 然后在函数日志里试着把一次完整的对话串起来.

## 11. AI Engineer: 让 agent 可复用, 可约束, 可观测

**如果你是做 AI 工程的**, 这个项目已经是你的主场了, 所以你的起点比别人高 —— 你要深挖的是
**agent 从能用到可靠之间那一段**: 工具复用, 护栏, 可观测.

**你动的是 `agent_app/` 里那几个文件**, 而数据那一侧和界面那一侧基本不用管. 库里躺着什么,
页面长什么样, 跟你要做的事关系不大 —— 所以你也是**不用先重新设计数据集** 的那三条之一,
今天就能动手.

**不过数据换成更难的一份, 会让这条路更有意思**: 表越多越绕, agent 选错表, 写出跑不动的
查询, 或者一本正经地编一个结论的概率就越高 —— 而那些正是护栏和可观测要对付的东西.
**这是加分项, 不是前提.**

**这条路要注意一件事**: 它是八条里唯一一条会真的改到 `agent_app/` 的. 那条换数据集一行不改的
承诺讲的是**内容变化时不改**, 不是永远不改 —— 你在这里加的东西对所有数据集都成立, 所以它
属于那个包.

**现在到哪儿了.** 三个工具, 一份提示词, 没有任何护栏, 没有任何追踪.

它能用, 但它是一个**黑盒**: 你不知道一次回答用了多少 token, 调了几次工具, 中间试错了几次.

**可以怎么做.**

三个方向, 而且它们互相独立:

**一, 让工具可复用.** 现在那个 SQL 工具是这个应用私有的. 把它做成一个标准的工具服务
(现在通行的做法叫 MCP), 别的 agent 就能直接接上. 这件事的价值不在技术上,
在于**它把工具从应用里解耦了出来** —— 你以后每写一个 agent 不用再重写一遍查数据库.

**二, 加护栏.** 这个项目已经有一个最原始的:
[`sql_utils.py`](../../agent_app/sql_utils.py) 里那个只允许查询的校验, 加上事务回滚那层保底 ——
第 24 篇 ([那只最要紧的手](../24-the-sql-tool/README-cn.md)) 讲过它为什么靠回滚而不是靠
关键词黑名单. 往上加: 输入侧挡掉提示注入, 输出侧挡掉不该出现的字段.

**三, 加可观测.** 每一轮记下用了多少 token, 花了多久, 调了哪几个工具, 顺序是什么. 这个项目
埋了两个种子: 那个能把自己的推理写成报告的工具, 和
[`agent_response.py`](../../agent_app/agent_response.py) 那套对返回内容的解析.

**为什么这是资深的人在做的事.**

初级的 AI 工程师**让 agent 答对**. 资深的**让你知道它为什么答对**, 以及它下次会不会还对.

这个差别在演示的时候完全看不出来 —— 两个系统都能在台上答对那三个问题. 它在系统跑了三个月,
换了一次模型, 换了一次提示词之后, 变成天壤之别.

**第一步可以是**: 在一次回答里, 把 agent 调了几次工具, 每次查了什么, 完整地打印出来.

## 12. Finance Engineer: 换成金融数据, 把口径写进定义

**如果你是做金融工程的**, 你要深挖的是**定义的精确度**: 一个数字在什么口径下才是对的.

**你和业务分析那条路做的是同一类事** (重新设计一份数据集, 再重写提示词里的领域知识),
只是重心完全不同 —— 那条路是把问题问得更难, 这条路是把每一个词的歧义都消掉.

**代码那一侧同样零改动.** 这一点在金融方向上尤其值钱, 因为这一行的深度从来不在代码里.

**现在到哪儿了.** 现在这份数据是小微企业放贷, 它已经沾了金融的边, 但它的指标都还比较朴素:
通过率, 违约率, 定价缺口.

**可以怎么做.**

按第 37 篇那套流程换一份真正的金融数据集: 组合, 头寸, 净值曲线, 风险因子, 业绩归因.

**这条路和别的路有一个明显的不同**: 它最吃的不是代码, 是**定义**.

年化怎么算? 用哪种收益率? 加权用市值还是用久期? 一个业绩数字扣没扣费用? 计的是哪个时区的
收盘?

**这些问题在金融里每一个都有多个正确答案**, 而选错的后果不是报错, 是一个看起来很合理的错误
数字. 于是提示词里那一节讲外行会算错的公式, 会从现在的几条膨胀到几十条 —— 而那一节膨胀,
正是这个领域被认真对待的标志.

**为什么这是资深的人在做的事.**

初级的人**把公式写对**. 资深的**知道这个公式在什么口径下不成立, 并且把口径写进定义里**.

这个项目里那一节存在的全部理由就是这件事. 它不是一个知识点列表, 它是一份**歧义清单**:
每一条都在说, 这个词有多种理解, 我们采用的是这一种.

**第一步可以是**: 挑现在提示词里的一条派生指标, 找出它至少两种合理的算法, 并说清这里为什么
选了那一种.

## 13. UX Design: 让人能把东西带走

**如果你是做设计或者产品体验的**, 你要深挖的是**用户拿到答案之后那一步**: 导出, 保存, 继续
操作, 变成一份能发出去的东西.

**你动的是前端那几个渲染组件**, 而 agent, 数据, 部署全都不用碰. 你甚至不需要理解那个 SQL
工具是怎么工作的 —— 你只需要知道它最后吐出来的是一段结构化文本.

**你也是不用重新设计数据集的那三条之一.** 现在这份数据能问出表, 能问出图, 能问出流程, 而
那三种就是你要做导出和继续操作的全部素材. **今天就能动手.**

**这条路有一个别的方向都没有的优势**: 你的成果是唯一一种**别人一秒钟就能看见** 的. 其余七条
路都需要你讲一段才讲得清.

**现在到哪儿了.** agent 吐出一段结构化的文本, 前端把它画成表格, 流程图和图表. 到此为止.

**你看到了一张表, 但你带不走它.**

**可以怎么做.**

- **给每一种块加导出.** 表格导出成表格文件, 图表导出成图片. 这一步的入口很清楚:
  [`components/chat/blocks/`](../../components/chat/blocks) 里每一种块都是一个独立的渲染器,
  第 12 篇 ([把文本画成块](../12-render-text-into-blocks/README-cn.md)) 讲过那张查找表
- **把整段对话导成一份报告.** 一个人问了六个问题, 得到六段分析 —— 那其实已经是一份报告的
  素材了, 只是它现在散在一个滚动的对话里
- **让那 12 个 kickstart 按钮可以被重排**, 甚至让用户存下自己常问的那几个
- **让一张表可以被继续操作**: 排序, 筛选, 选中几行再追问

**动手之前先读第 38 篇第 8 节.** 那里说了这一层有三样东西改外观可以, 重写会不报错地坏掉.
导出按钮属于加东西, 不属于重写, 所以是安全的.

**为什么这是资深的人在做的事.**

初级的设计师**让界面好看**. 资深的问**用户看完这个之后要干什么**.

而在一个分析工具里, 那个问题的答案几乎总是同一个: **拿给别人看.** 一个分析师查完数据不是
为了自己知道, 是为了发给老板, 放进周报, 贴到群里.

**知道了这一点, 优先级就完全变了**: 一个导出按钮的价值, 高过一次配色的重新调整. 而这件事只有
真的想过用户在做什么的人才排得出来.

**第一步可以是**: 打开这个应用, 完整地问三个问题, 然后诚实地记下你自己想对那些结果做的每一个
动作.

## 14. 练习

**这一篇只有一个练习, 而且很轻.** 前面十三节已经把该给的都给了, 剩下的是你自己选一条路 ——
而选路这件事不需要练, 需要的只是真的去看一眼.

### 练习: 挑一条你感兴趣的, 去看一眼它的门

**目标:** 把上面某一节从一段读过的文字, 变成你亲眼打开过的几个文件.

**怎么做:**

1. 从那八条里挑**一条你自己感兴趣的**. 可以是你现在做的方向, 也可以是你想转过去的那个 ——
   **凭兴趣挑就行**, 这里没有对错
2. 把那一节从头读一遍, 三段都读: 现在到哪儿了, 可以怎么做, 为什么这是资深的人在做的事
3. 把那一节点名的**每一个文件** 都打开, **扫一眼就行, 不要求读懂**
4. 挑其中一个文件, 用一句话写下**它现在做到哪儿了**
5. 回答两个问题:

| 问题 | |
| :--- | :--- |
| 你这条路**要不要先重新设计一份数据集** | 对着第 5 节那张表确认 |
| 你这条路上**什么完全不用动** | 对着那一节开头那段确认 |

**你会观察到:**

**第 3 步打开的文件, 大多数会比你想的小.** 一个空数组, 一个只返回固定内容的接口, 一个三行
的函数 —— 而那些正是入口. **一条深化路径的起点通常就是这么小**, 因为它们是被刻意留成最简单
的样子的, 而不是被做错了.

**第 4 步比想象中难写.** 写不出来说明那个文件你还需要再看一会儿 —— 而这正是这个练习想让你
发生的唯一一件事.

**第 5 步那两个答案值得记下来.** 它们合起来就是你那条路的起跑线: 一边是你得先解决的问题,
一边是你可以直接拿走不管的东西.

> **关键洞见:** 一个项目留没留口子, 看的不是它有没有写扩展点这种词, 是** 那些没做的地方是不是
> 被留成了一个最简单的完整形态**. 一个空数组比一个复杂的插件框架更好扩展.

## 15. 回顾: 我们学到了什么

**这一篇的机制**: 代码那一侧九成可复用, 你投入的是数据加你那一层的深度. 而你交出去的是双份
的 —— 上面证明你的专业, 下面证明你用 AI 把东西交付出去的能力.

**八条里有五条要先重新设计数据集** (业务分析, 数据科学, 数据工程, 机器学习工程, 金融工程),
另外三条不用 (软件工程, AI 工程, 用户体验) —— **后三条今天就能动手**.

| 方向 | 入口在哪 | 初级做什么, 资深做什么 |
| :--- | :--- | :--- |
| Business Analyst | 那份业务查询文档, 和提示词里讲外行会算错的那一节 | 回答被问的问题, 对定义该问什么问题 |
| Data Scientist | 一个新模块加一个 `@tool` | 调指标, 对决定该不该上线以及错了谁承担 |
| Data Engineer | 那个空着的定时任务配置, 和现在那个全量同步 | 把数据搬过去, 对保证搬两遍结果一样 |
| ML Engineer | 一条把刷新, 重训, 评估, 上线串起来的链 | 让流水线跑通, 对让它敢于不上线 |
| SDE | `debug`, 探活接口, 连接行为 | 让它跑起来, 对让它坏的时候你知道 |
| AI Engineer | 那三个工具, 那个只读校验, 那份推理报告 | 让 agent 答对, 对让你知道它为什么答对 |
| Finance Engineer | 提示词里那份歧义清单 | 把公式写对, 对知道它在什么口径下不成立 |
| UX Design | 那张块渲染的查找表 | 让界面好看, 对问用户看完要干什么 |

**八条路的那条分界线是同一条**: 初级的人让一件事**发生**, 资深的人让它在** 没人盯着的时候
依然成立**.

## 16. 导师寄语

**为什么这一篇值得认真读:**

因为它是这门课对第 2 篇那个承诺的兑现, 而且它兑现的方式可能和你预期的不一样.

第 2 篇说这个项目每一块都留了口子. 你当时可能以为那意味着代码里有一堆预留的接口和配置项.
**恰恰相反**: 那些口子全都是**空的, 小的, 简单的** —— 一个空数组, 一个三行的函数, 一个返回
固定内容的接口.

**而更重要的那一半是第 5 节那个拆法.** 大多数人不是不会做自己专业里的深活, 是做完之后没有
一个地方能把它摆出来 —— 于是那个模型躺在 notebook 里, 那条管道躺在一个没人跑的脚本里, 那份
分析躺在一个 Excel 里. **展示这件事的成本, 才是真正拦住人的东西**, 而它已经被付掉了.

**但也别把这件事说得太轻.** 第 5 节那张表说得很直白: 八条里有五条, 你得先重新设计一份数据
集, 而那本身是一门要单独学的手艺. **省掉的是展示那一段, 不是你专业里的那一段** —— 后者本来
也不该被省掉, 它才是你要拿出去给人看的东西.

**这是这一篇最想让你带走的一条**: 一个东西好不好扩展, 不取决于它预留了多少扩展点, 取决于
**它没做的那些地方有没有被做成一个诚实的最简形态**. 一个空数组谁都能填; 一个半成品的插件
框架, 你得先把它读懂, 然后往往发现它预留的方向恰好不是你要的那个.

**关于那八条分界线, 还想说一句.** 你可能注意到了, 八个方向的初级和资深, 说的其实是同一件事:
初级关心**这次能不能成**, 资深关心**下次还成不成, 以及不成的时候会怎样**.

这不是因为资深的人更谨慎, 是因为他们见过那个不成的时候. 而你现在可以走一条捷径:
**不必等到见过, 先照着这个问题去想.**
你每写一个东西, 多问一句它坏的时候会怎样 —— 这一个习惯, 比这
八条路上任何一项具体技术都值钱.

**最后.** 你不需要八条都走. 挑一条, 走远一点, 比八条都走两步有用得多 —— 因为深度是没法伪装
的, 而广度可以.

而无论你挑哪一条, **下面那九成都是同一套**. 这就是脚手架这个词最实在的意思: 它不告诉你该往
哪儿走, 它只保证你往哪儿走都不用先修一遍路.

**关键洞见:**

- 一个方向的深挖成本, 大头往往不在那个方向本身, 而在把它展示出来那一段
- 一份数据能支撑什么, 是由它当初为什么被设计出来决定的; 为分析造的数据训不出可信的模型
- 好扩展的项目, 它的口子是空的和小的, 不是复杂的
- 八个方向的资深线是同一条: 从这次能不能成, 变成下次还成不成
- 知道门在哪和知道怎么走进去是两件事, 这一篇只负责前一件
- 挑一条走远, 比八条各走两步有用

主题 9 到这里讲完了, 而且这门课的全部内容也讲完了.

## 17. 速查

**这一篇一句话**: 代码那一侧九成可复用; 你要投入的是一份为你这个方向设计的数据, 加上你那
一层的深度.

**要不要先重新设计数据集:**

| 要 | 不用 |
| :--- | :--- |
| Business Analyst, Data Scientist, Data Engineer, ML Engineer, Finance Engineer | SDE, AI Engineer, UX Design |

**八条路的入口:**

| 方向 | 从这里开始读 |
| :--- | :--- |
| Business Analyst | [`dataset/`](../../dataset) 那份业务查询文档, [`data/system-prompt.md`](../../data/system-prompt.md) 的 `Derived Business Concepts` |
| Data Scientist | [`agent_app/one/one_04_agent.py`](../../agent_app/one/one_04_agent.py) 的 `@tool` 方法 |
| Data Engineer | [`vercel.json`](../../vercel.json) 里那个空的定时任务, [`agent_app/dataset.py`](../../agent_app/dataset.py) |
| ML Engineer | [`agent_app/quota.py`](../../agent_app/quota.py) 那道闸门的形状 |
