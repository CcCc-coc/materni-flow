# 挂上你自己的域名

## 1. 概览

上一篇结束时你有了一个地址, 长得像 `smb-lending-lens-a1b2c3.vercel.app`. 它能用, 但它有两个
问题.

**第一个问题是它不是你的.** 那个名字是平台分配的, 平台换个规则它就变. 你把它印在简历上,
两年后它可能已经指向别的地方, 或者干脆不在了.

**第二个问题更实际: 它只能装一个作品.** 而你接下来会做第二个, 第三个. 每一个都拿一个随机
后缀的地址去投, 别人看到的是一堆互不相干的链接, 而不是一个人.

**这一篇解决的就是这个.** 花二十美元买一个属于你的名字, 然后把这个项目挂在它下面的一个位置.
以后每多一个作品, 就多一个位置, 那个名字一直是同一个.

**这一篇不教怎么点.** 云平台的域名界面半年一变, 写死了就是一篇过期文档 —— 而且是那种最坑人
的过期文档, 因为它看起来还很详细. 它教的是**要发生什么**, 以及第 9 节那段可以照抄的提示词,
让你把会变的那一半交给 AI.

**买不买域名由你决定.** 下面两个练习都不需要花钱, 也不需要注册. 真要买的时候, 速查那一节
是完整的动作清单.

### 卡住了怎么办

这一篇最容易卡的地方是配完记录之后打不开, 或者浏览器报证书错误. 那通常不是你配错了, 而是
**还没生效**, 或者踩到了第 8 节说的那个最常见的冲突.
**这些都很正常** —— 两家平台的界面, 你买的后缀, 你所在网络的 DNS 缓存, 和写这一篇时的那一套
不可能完全一样.

**别自己硬猜, 也别只把报错扫一眼就跳过去.** 把下面三样东西一起给 AI, 一样都别少:

| 给什么 | 怎么给 |
| :--- | :--- |
| **你在读哪一篇** | 原样给路径: `examples/36-your-own-domain/README-cn.md` |
| **你敲了哪条命令** | 原样复制那一行, 不要凭记忆转述 |
| **终端打了什么** | **把终端里的文字整段复制粘贴给它**, 不要截图, 也不要只说了一句打不开 |

这一篇还多一样: **界面的截图**. 因为这一步的一半状态在网页上而不在终端里, 你现在在哪个页面,
那个开关是开是关, 截图比描述准得多.

一段可以照抄的开场白:

```text
我在读 examples/36-your-own-domain/README-cn.md 这一篇.
我敲的命令是:
(把命令粘在这里)
终端打出来的是:
(把完整输出粘在这里)
我另外附了一张当前页面的截图.
帮我判断是哪一步出了问题. 一步一步来, 每一步等我做完再往下.
```

**粘贴之前先打码.** 截图里可能带着账号邮箱, 账单信息, 或者别的项目的地址. 那些不该出现在
任何聊天窗口里.

## 5. 一个平台地址少了什么

先把这件事说透, 因为二十美元一年不是一笔可以随便花的钱.

**你买的不是一个网址, 是一个不会被别人改掉的名字.**

具体买到三样东西:

**一, 它跟着你走, 不跟着平台走.** 今天这个项目在 Vercel 上. 明年你可能搬到别的平台, 或者
搬到自己的服务器. 换平台的时候, 那个地址上所有的东西都要重发一遍 —— 除非那个地址是你的,
那你只要改一条记录, 别人手里的链接一个都不用变.

**二, 它把一堆作品收成一个人.** 这是最容易被低估的一条. 对比一下:

| 你发给别人的 | 别人看到的 |
| :--- | :--- |
| 三个随机后缀的平台地址 | 三个不相干的东西 |
| `a.yourname.me`, `b.yourname.me`, `c.yourname.me` | 一个持续在做东西的人 |

**三, 它是一个非常便宜的可信度信号.** 一个自己名字的域名说明你为这件事花过钱, 而且知道
DNS 是怎么回事. 这两样都不难, 但绝大多数人没做.

**它不值钱的地方也说清楚**: 它不会让你的项目变好, 不会让招聘的人多看一眼一个空网站. 它是
一个放大器, 前面得有东西可以放大 —— 而你在第 35 篇已经把那个东西送上去了.

### 没有域名会发生什么

上面三条讲的是有域名的好处. 反过来说一遍更有用, 因为反过来那一面是会真的发生在你身上的.

**一个随机后缀的平台地址, 在别人眼里天然带着一个标签: 练习作品.** 这不公平, 但它就是会发生 ——
对面在几十份简历里扫过去, 一个 `xxx-a1b2c3.vercel.app` 和一个 `smb-lending-lens.janesmith.me`
给他的第一印象完全不同, 而那个印象在他点开之前就已经形成了.

**这个印象会改变接下来对话的性质.** 一个被默认当成练习作品的东西, 你要花很多力气去证明它是
认真的: 数据是不是你自己造的, 部署是不是真的, 有没有人用过, 是不是照着教程抄的.
**这些问题一个接一个, 而且答对了也只是回到起点.**

**而一个挂在你自己名字下的东西, 默认假设是反过来的.** 对面看到的是一个持续在做东西的人的
其中一个作品, 于是问题会变成他更想问的那种: 你为什么选这几个业务问题, 这个 agent 答错的
时候会怎样.

**所以这二十美元买的其实是那个默认假设.** 前面说的三条好处是长期的, 这一条是立刻生效的.

**但也别把它说得太重.** 一个没有域名但做得很扎实的项目, 依然比一个挂在漂亮域名下的空壳强
得多. 顺序是先有东西, 再给它一个名字.

## 6. 为什么是 Cloudflare

注册商有几十家, 差别比你想的大. 三条判据:

**第一条, 续费价格.** 这是最大的坑. 很多注册商的玩法是**首年一美元, 第二年三十美元**. 你买
的时候看到的是那个一美元, 一年后账单来了才发现. 而域名是那种你一旦用了就很难换的东西 ——
换了名字, 之前所有发出去的链接就都死了 —— 所以他们知道你多半会续.

**Cloudflare 的注册服务按成本价卖, 首年和续费是同一个价.** 它不靠域名赚钱, 域名是它把你
带进它生态的入口. 对你来说这意味着你今天看到的价格就是明年的价格.

**第二条, 有没有暗默加价.** 隐私保护 (不把你的姓名地址电话公开在 WHOIS 数据库里) 在很多家
是一项每年十美元的增值服务. 在 Cloudflare 是默认包含的.

**第三条, 它会不会消失.** 域名是一个你希望持有很多年的东西. 小注册商被收购, 改政策, 或者
关门, 都会变成你的麻烦. 这一条上大厂有实打实的优势.

**代价也说一句**: Cloudflare 要求这个域名的 DNS 托管在它自己这里. 对我们要做的事这不是问题
(反而少一个环节), 但如果你有一天想把 DNS 放在别处, 那就要换注册商.

**另外, 不是所有后缀它都卖.** 常见的都有, 冷门的可能没有. 查得到就能买, 查不到就换一个后缀.

## 7. 买之前先想清楚买哪个名字

这一节比上一节重要, 因为**名字买错了是唯一不能撤销的一步**.

**首选是你的全名加一个后缀**, 比如 `janesmith.me`. `.me` 这个后缀的好处是它天然读作
**关于我**, 而且价格在二十美元上下, 不像 `.com` 那样好名字早就被抢光了.

被占了怎么办, 按这个顺序试:

| 试法 | 例子 | 行不行 |
| :--- | :--- | :--- |
| 换个后缀 | `janesmith.dev`, `janesmith.io` | 好. 名字还是你 |
| 加中间名或者缩写 | `janeksmith.me` | 好 |
| 加一个数字 | `janesmith7.me` | 可以, 但别加长串 |
| 加一个形容词 | `awesomejane.me` | **不好**, 一眼看不出是你 |
| 用一个昵称 | `codewizard99.me` | **不好**, 同上 |

**唯一的判据是: 别人扫一眼能不能把这个域名和你这个人对上.** 这个域名以后要印在简历上, 出现
在邮件签名里, 被人念出来. 一个念不出来或者听不出是谁的名字, 就把上一节说的第三样好处丢掉了.

**然后规划子域名.** 这是很多人第一次买域名时会想漏的一步. 一个域名底下可以挂无数个位置, 每个
位置一个作品:

| 位置 | 放什么 |
| :--- | :--- |
| `smb-lending-lens.janesmith.me` | 这个项目 |
| `<下一个项目>.janesmith.me` | 你换完数据集之后的那个 |
| `janesmith.me` 本身 | 以后可以放一个很简单的落地页, 把上面那些链过去. 现在可以空着 |

**这门课建议你把这个项目挂在一个子域名上, 不要挂在根域名上.** 两个理由: 一是根域名留给以后
那个入口页, 二是子域名的配置方式简单一格, 见下一节.

## 8. 从买到能打开, 会发生什么

这一节是这一篇的核心, 因为**这个形状不会过期, 而下一节那些按钮会**.

**先把这个分法记住**, 后面每读一份操作教程都用得上:

| 类型 | 长什么样 | 保质期 |
| :--- | :--- | :--- |
| **机制** | 要发生什么, 以及为什么是这个顺序 | 很长. 换个平台换个年份还是这样 |
| **界面** | 某个按钮叫什么, 在哪个菜单里 | 很短. 半年就可能不对 |

**危险的地方在于, 界面那一类读起来更具体, 更让人放心.** 一篇写满了点哪里的教程读起来最顺,
也最快过期. 所以这一节讲的全是机制, 而按钮全部交给下一节的 AI.

整件事有四个环节:

**环节一: 你在注册商那里买下这个名字.** 付款成功之后, 世界上的 DNS 系统就认这个名字归你了.
此刻它还不指向任何地方.

**环节二: 你在 Vercel 那边说, 这个名字我要用在这个项目上.** 这一步是在你的项目设置里加一条
域名. 加完之后 Vercel 会**告诉你一条它要你配的记录** —— 通常是一条 CNAME, 内容是一个
Vercel 自己的地址.

这一步的意义是**授权**: 世界上任何人都可以在 Vercel 上说我要用 `janesmith.me`, 所以 Vercel
必须确认你真的控制这个名字. 而控制的证明就是你能改它的 DNS.

**环节三: 你在 Cloudflare 的 DNS 页面上把那条记录加进去.** 加完之后, 有人访问
`smb-lending-lens.janesmith.me` 的时候, DNS 会把他指到 Vercel.

**环节四: 等.** 两件事在等: DNS 记录传播到各地的缓存, 和 Vercel 给这个名字签发一张 HTTPS
证书. 通常几分钟, 偶尔更久.
**这一步没做完就打开, 看到的是打不开或者证书错误, 那不是你配错了.**

### 一个几乎人人都会踩的冲突

Cloudflare 的 DNS 页面上每条记录旁边有一个云朵图标, 可以在两种状态之间切: **代理** 和
**仅 DNS**. 代理是 Cloudflare 的招牌功能, 它会把流量先绕到自己这里.

**指向 Vercel 的记录通常需要设成仅 DNS.** 因为 Vercel 要自己给这个名字签证书, 而流量被
Cloudflare 代理之后, 两边各有一层证书和跳转, 很容易转出一个死循环, 或者报一个看不懂的证书
错误.

记住这一条就够了: **配完打不开而且报证书相关的错, 第一个要检查的就是那个云朵.**

### 根域名为什么麻烦一格

如果你把项目挂在根域名 (`janesmith.me` 而不是它下面的一个位置) 上, 会多一层麻烦: DNS 的
规矩不允许根域名用 CNAME. 各家注册商用不同的手段绕过去 (Cloudflare 的做法叫扁平化), 能用,
但你要多懂一件事.

**用子域名就没有这个问题.** 这也是上一节那个建议的另一半理由.

## 9. 把界面那一半交给 AI

到这里为止, 你知道要发生什么了. 剩下的是**在两个网站上找到对的那几个按钮**, 而这正是最会
过期, 也最不值得背下来的部分.

这一步是第 4 篇那套方法的一次真实应用, 而且比在仓库里派活更能说明问题:
**你面对的是一件你没做过的事, 而 AI 的知识可能也是旧的.**
所以问法要变: 不是让它一次给完, 而是让它一步一步
带, 你用截图告诉它你现在在哪.

**先加载这个仓库的事实标准**, 让它知道这个项目是什么形态:

```text
/about-bi-agent-app-scaffold-cn
```

**然后把下面这段整个复制过去**, 把三个尖括号的地方换成你自己的:

```text
我要给一个已经部署在 Vercel 上的项目挂一个自己的域名. 背景如下.

项目: 一个 Next.js 前端加一组 Python serverless 函数, 部署在 Vercel 上,
当前地址是 <你的 vercel.app 地址>. 它已经能正常打开和使用.

域名: 我在 Cloudflare Registrar 买了 <你的域名>, 这个域名的 DNS 也托管在
Cloudflare. 我要让 <你想用的子域名> 指向上面那个 Vercel 项目.
根域名暂时不用动.

我知道大概会发生什么: 在 Vercel 项目里加这个域名, 它会给我一条要配的记录,
我到 Cloudflare 的 DNS 页面把它加上, 然后等生效和签证书. 我也知道指向
Vercel 的记录通常要设成仅 DNS 而不是代理.

我不知道的是这两个网站现在的界面长什么样, 而且我怀疑你记的界面也可能是旧的.
所以请这样带我:

1. 一次只给一步, 说清我要去哪个网站的哪个位置, 以及我应该看到什么
2. 每一步结束等我回复. 我会截图告诉你我看到的实际画面
3. 如果我截图里的界面和你说的对不上, 以截图为准, 别让我去找一个不存在的按钮
4. 每一步都告诉我这一步是在干什么, 不要只说点哪里
5. 全部配完之后, 给我一条可以在终端里验证的命令

先从第一步开始.
```

**这段提示词里每一句都在干活**, 值得逐条看一眼:

| 那一句 | 它防住了什么 |
| :--- | :--- |
| 说清项目形态和当前地址 | 防止它假设一个纯静态站, 给出不适用的方案 |
| 说清域名在哪买的, DNS 在哪 | 这两件事分开时步骤完全不同, 不说它就得猜 |
| 说清我知道大概会发生什么 | 它不会再从头科普 DNS, 直接进操作 |
| 主动提那个仅 DNS 的坑 | 把最常见的失败提前挡掉 |
| **我怀疑你记的界面可能是旧的** | 这一句最关键. 它把模型从背诵切换到跟着你看 |
| 一次一步, 等我回复 | 防止它一口气给二十步, 而第三步就已经对不上了 |
| 以截图为准 | 给了它一个冲突时的裁决规则 |
| 每一步说在干什么 | 让你能判断它有没有跑偏, 而不是盲从 |
| 最后给一条可验证的命令 | 让这件事有一个不依赖界面的验收 |

**最后那一条自己也可以先准备好.** 配完之后, 这条命令应该能返回一个地址:

```bash
dig +short smb-lending-lens.yourname.me
```

以及这一条应该返回一个 2 开头或者 3 开头的状态码:

```bash
curl -sI https://smb-lending-lens.yourname.me | head -1
```

## 10. 练习

**这两个练习可做可不做**, 而且都不花钱 —— 加起来二十分钟.

**但值得说清楚跳过的代价.** 如果你决定就用那个平台地址, 那你要做好第 5 节说的那种准备:
对面默认把它当练习作品, 于是你得花额外的力气一个一个回答那些拷问, 而答对了也只是回到起点.
**做完这两个练习不等于你要买**, 但至少你会知道那二十美元换的是什么.

### 练习 1: 把名字定下来

**目标:** 十分钟, 从没想过到有一个具体的名字和一套位置规划.

**怎么做:**

1. 打开 Cloudflare 的域名查询页面 (`cloudflare.com/products/registrar/`)
2. 查三个候选: 你的全名加 `.me`, 加 `.dev`, 以及按第 7 节那张表变形出来的一个
3. 对每一个, 记下**能不能注册**, 以及**首年价和续费价是不是同一个数**
4. 按第 7 节那条唯一判据选出一个
5. 写下你的位置规划: 这个项目用哪个子域名, 根域名留着干什么

**你会观察到:**

Cloudflare 那两个价格是同一个数. 顺手拿一个候选去别家查一下, 你会看到第 6 节说的那种首年
一美元的定价长什么样 —— 那个差别就是这一篇让你在这里买的全部理由.

**买不买现在不用决定.** 名字定下来这件事本身就有价值, 因为它是唯一不能撤销的一步.

> **关键洞见:** 域名的定价陷阱不在你买的那一天, 在续费那一年. 而查这件事只要三十秒.

### 练习 2: 让 AI 带你走第一步

**目标:** 把第 9 节那段提示词真的用一次, 确认它带出来的第一步是对的.

**怎么做:**

1. 加载 `/about-bi-agent-app-scaffold-cn`
2. 把第 9 节那段提示词复制过去, 三个尖括号按练习 1 的答案和你的 Vercel 地址填
3. **只走到它给出第一步为止**, 不用真的去点
4. 对着第 8 节那四个环节, 判断它给的第一步落在哪一个环节上

**你会观察到:**

它给的第一步应该是**去 Vercel 项目的域名设置**, 而不是去 Cloudflare —— 因为要先拿到那条它
让你配的记录, 也就是第 8 节的环节二.

如果它一上来让你去 Cloudflare 加记录, 说明它没读懂顺序. 这时候把那四个环节整段贴给它, 它
会自己纠正过来. **这个纠正动作本身就是这个练习最值钱的部分**: 你能纠正它, 是因为你知道机制;
如果你只背了步骤, 你根本看不出它错了.

> **关键洞见:** 一件你没做过的事, 最有价值的准备不是背步骤, 是先弄清顺序为什么是这个顺序.
> 知道了顺序, 你就能判断 AI 给的步骤对不对.

## 12. 导师寄语

**为什么这一篇值得认真读:**

因为它是这门课里唯一一件**完全在仓库之外** 的事, 而它教的方法恰恰最通用.

前面三十几篇, 你要找的东西都在磁盘上: 打开文件就能看到, 跑一条命令就能验证. 这一篇不是.
这一篇你要在两个别人家的网站上, 找到两个会挪位置的按钮, 而且没有任何一份文档能保证明年
还对.

**这种事你以后会遇到很多次**: 配一个云服务, 接一个第三方登录, 申请一个开发者账号. 它们的
共同点是流程不难, 但每一份教程都在过期.

**所以这一篇真正教的是那个分法.** 把一件事拆成不会变的机制和会变的界面, 自己把机制吃透,
把界面交出去 —— 交给 AI, 或者交给当时的官方文档. 这个分法用在这里是省二十分钟, 用在你的
工作里能省下几年.

**还有一句想说.** 二十美元一年, 这大概是你在这门课里花得最值的一笔. 不是因为域名本身多有用,
而是因为**它会一直在那儿**. 三年后你换过两次工作, 做过五个项目, 那些平台地址早就换了一轮,
而那个名字还是那个名字.

**关键洞见:**

- 一个自己的名字是少数越放越值钱的东西, 而它的价格几乎不变
- 域名的定价陷阱在续费那一年, 不在你买的那一天
- 名字要能被念出来并对上你这个人, 不然它就只是一个更贵的随机字符串
- 一件没做过的事, 先搞清顺序为什么是这个顺序, 再去找按钮
- 给 AI 的背景里最值钱的一句是承认它可能记的是旧界面

## 13. 速查

**真要买的时候, 完整动作清单:**

1. 在 `cloudflare.com/products/registrar/` 查名字, 确认首年价等于续费价
2. 注册 Cloudflare 账号, 绑卡, 买下来
3. 到 Vercel 项目的域名设置里加上你的子域名, 记下它要你配的那条记录
4. 到 Cloudflare 的 DNS 页面加那条记录, **把云朵设成仅 DNS**
5. 等几分钟, 用下面两条命令验

**验生效:**

```bash
dig +short smb-lending-lens.yourname.me
```

**验能打开:**

```bash
curl -sI https://smb-lending-lens.yourname.me | head -1
```

**卡住的时候, 按这个顺序怀疑:**

| 现象 | 第一嫌疑 |
| :--- | :--- |
| `dig` 什么都不返回 | 记录没加成, 或者还没生效 |
| `dig` 有返回但浏览器打不开 | 证书还没签发, 再等一会 |
| 报证书错误或者一直跳转 | 那个云朵还开着代理 |
| Vercel 那边显示未验证 | 记录的内容抄错了, 回去对一遍 |
