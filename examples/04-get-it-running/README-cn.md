# 把它跑起来: 装依赖, 配密钥, 灌数据, 起服务

> 四步, 顺序不能换. 每一步跳过之后的失败方式都不一样, 而最阴的那一种根本不报错.

## 1. 概览

这一篇是这门课第一次动手. 目标很朴素, 而且**故意定得比你以为的低**: 浏览器里打开
`localhost:3000` 看到首页, 点得动, 页面正常渲染.

达到这个状态要走三步:

| 步 | 干什么 | 一条命令 |
| :--- | :--- | :--- |
| 1 | 装依赖 | `mise run inst` |
| 2 | 配密钥 | `cp .env.example .env`, 然后填 |
| 3 | 起服务 | `mise run dev` |

### 说清楚这一篇的终点在哪

走完这三步, **agent 页还不能用**. 你点 kickstart 按钮, 大概率会拿到一条报错, 因为数据库
里现在一行数据都没有.

**这是正常的, 不是你哪儿做错了.** 把数据造出来再发布进数据库是一整摊事, 它有自己的四篇:
第 17 篇 ([一个数据集里装着什么](../17-what-a-dataset-is/README-cn.md)) 到第 20 篇
([把种子发布到 PostgreSQL](../20-seed-to-postgres/README-cn.md)).

为什么要这么切? 因为**第一次动手最重要的事情是尽快看到东西动起来**. 一口气把数据也搞完,
你要等的时间长一倍, 中间任何一步卡住都会让你搞不清是环境的问题还是数据的问题.

先让前端亮起来, 你就有了一个能回头对照的正常状态.

### 读不懂的地方, 别跳过去

先说一条贯穿整个系列的读法, 因为从这一篇开始正文会变密.

这门课很长, 而且它的第一优先级是**让你先跑通**. 所以正文里很多东西只讲到你现在需要知道的
那个程度, 不会一路展开到底. 这是刻意的取舍: 每个点都写细一遍, 篇幅会长到没人读得完, 而且
每个人卡住的地方本来就不一样, 提前猜也猜不准.

补这个深度的办法是把 AI 拉进来:

1. 敲 `/showcase-learn-cn` 把这门课的助教加载起来
2. **把你没看懂的那段原样复制粘贴给它**, 不用自己转述
3. 追问到懂为止. 这句话什么意思, 为什么不能反过来做, 给我举个例子, 换个说法再讲一遍, 都行

**不要装作看懂了往下翻.** 这门课后面每一篇都长在前一篇之上, 一个含糊的地方会一路含糊下去,
而且通常要到很后面才以你说不清哪里不对的形式暴露出来.

这个 skill 具体怎么加载, 该配什么档次的模型, 见下面第 8 节.

### 还有一条: 要改代码就先开一个 branch

从这一篇开始, **凡是练习让你改仓库里的文件, 都先从这门课那个基线 branch 分一个出来**:

## 2. 学习目标

三步里有两步是配置, 只有最后一步在跑代码. 这个比例本身就是这一篇要讲的事.

而配置这件事在这个项目里有个特点, 现在就值得记住: **它的错误几乎都不报错.**

一个报错的系统其实是好系统, 你至少知道该修哪儿. 而配错了还能跑的系统才是麻烦: 你从
`.env.example` 抄了一行忘了注释掉, 于是一个变量已设置, 非空, 但完全没用; 或者你把一个值
填进了错的那个文件, 程序照跑, 只是读到的不是你以为的那个值.

这门课后面会反复撞见这个模式, 最典型的一次在第 20 篇
([把种子发布到 PostgreSQL](../20-seed-to-postgres/README-cn.md)): 一个连着空数据库的 agent
不会崩, 它会自信地把表名编出来回答你.

学完这个 Task, 你将能够:

1. 用 mise 一条命令装齐 Python 和 Node 两套工具链, 并说清 mise, uv, pnpm 三者谁调谁
2. 分清哪些配置该进 `.env`, 哪些该进 `.env.defaults`, 判据是什么
3. 在三家 LLM 厂商里选一家拿到 API key, 给它设上花费上限, 并妥善保管
4. 把这门课的 AI skill 叫起来当助教, 而且知道怎么让它一步一步来
5. 走完造种子, 同步, 逐表核对这三条命令, 并说清它们为什么不是 mise 任务
6. 解释空 schema 和不存在的 schema 为什么在程序看来一模一样, 以及后果是什么

## 5. 一个入口: mise

打开 [`mise.toml`](../../mise.toml), 它同时管两件事.

**第一件是钉住工具版本.** 顶上那个 `[tools]` 段声明这个项目要 Python 3.12, Node 24, 加上
uv, pnpm, ruff. 所以 clone 下来之后你不需要自己去装 Python 和 Node, mise 会按这张表准备好.
这也意味着你机器上装的是哪个版本的 Python 不重要.

**第二件是定义任务.** 剩下那一大堆 `[tasks.xxx]` 就是这个项目所有能敲的命令. 常用的是这些:

| 命令 | 干什么 |
| :--- | :--- |
| `mise run inst` | 装依赖 (Python 和 Node 一起) |
| `mise run dev` | 起两个开发服务器 (会先杀掉本 checkout 的旧进程) |
| `mise run kill` | 停掉本 checkout 的服务器 |
| `mise run test` | 内容检查加 Python 测试加 Node 测试 |
| `mise run check-content` | 只查 [`data/`](../../data) 里的内容一致性 |
| `mise run build-web` | 构建前端, 也是唯一会查 `site.toml` 必填 key 和图标名的地方 |

`mise run inst` 底下调的是两个包管理器: `uv sync --all-extras` 读 [`pyproject.toml`](../../pyproject.toml) 和
`uv.lock`, `pnpm install` 读 [`package.json`](../../package.json) 和 `pnpm-lock.yaml`. 你不需要分别记住它们的写法,
这正是 mise 存在的理由.

**任务名点的是它碰什么, 不是它属于哪一类.** 一个叫 `check` 的任务说不清它是这个仓库好几种
检查里的哪一种; `check-content` 和 `build-web` 摆在一起, 就看得出它们分管两边.

现在敲第一条:

```bash
mise run inst
```

## 6. 两个配置文件, 按是不是密钥切

第 2 步是配置. 这个项目有两个配置文件, 它们之间的那条线值得单独讲, 因为它决定的不只是
值放哪儿, 而是**谁能打开这个文件**.

| | `.env` | `.env.defaults` |
| :--- | :--- | :--- |
| 装什么 | API key, AWS 密钥, 数据库 host, user, password, name | `SCHEMA_NAME`, `LLM_PROVIDER`, `AWS_REGION`, `DB_PORT`, 整块配额设置 |
| 是密钥吗 | 是 | 不是 |
| 进 Git 吗 | 不进 | **进** |
| AI 能打开吗 | **不能**, `.claude/settings.json` 里 deny 了读和写 | 能 |
| 加载顺序 | **先读, 所以它赢** | 后读, 补空缺 |

**判据只有一句: 它是密钥吗?** 另一条看起来也讲得通的切法是会不会因为换台机器而不同,
但那条线会把数据集的身份 (一个字符串) 切成第三个配置文件, 于是你要为它养一个格式和一个
读取模块. 按密钥切的这条线能挣回成本, 因为它管的是访问权限.

这条线带来的两个具体好处: 轮换一个 API key 不该碰到 schema 名; 把仓库指向一个新数据集不该
碰到任何人的凭据.

**注意 `.env.defaults` 是进 Git 的, 而且没有 `.env.defaults.example`.** 这是故意的: 那个
文件本身就是参考. 搞成 gitignore 加模板那一套的话, `SCHEMA_NAME` 就跑到版本控制外面去了, 每次
clone 都要重填一遍.

现在动手:

```bash
cp .env.example .env
```

然后在 `.env` 里填两样东西, 别的都留着注释:

- `DB_HOST`, `DB_USER`, `DB_PASS`, `DB_NAME`. 用 Neon 那个带 `-pooler` 的主机名
- **一个** LLM 凭据, 就是 `.env.defaults` 里 `LLM_PROVIDER` 指的那一家

### 三个填的时候会咬人的地方

**一, `"..."` 等于没设.** `.env.example` 里的占位符是 `"..."`, 而代码把这个值当成未设置.
所以从模板抄过来忘了注释掉的那一行, 不会变成一个已设置, 非空, 但没用的变量.

**二, 用 bedrock 的话本地不要设 AWS 那两个 key.** boto3 查环境变量**早于**
`~/.aws/credentials`, 所以 `.env` 里一个占位符就能遮蔽掉一个好好的本地 profile. 报出来的
错是 `UnrecognizedClientException`, 一条完全指不到原因的话.

**三, 换 `LLM_PROVIDER` 时记得 `LLM_MODEL_ID`.** 各家的 model ID 格式不通用. 要么一起改,
要么把它注释掉让它回退到那家的默认值.

## 7. 一把 LLM 的 API key

这个 app 的核心是一个大模型, 所以你得给它一把钥匙. 这一节讲的是**你需要做什么判断**, 不是
点哪个按钮, 因为三家厂商的控制台每隔几个月就改一次版, 写死步骤只会过期.

### 三选一

| 厂商 | 环境变量 | 说明 |
| :--- | :--- | :--- |
| OpenAI | `OPENAI_API_KEY` | **推荐**, 注册和拿 key 这条路最顺 |
| Anthropic | `ANTHROPIC_API_KEY` | Claude 系列 |
| Google | `GOOGLE_API_KEY` | Gemini 系列 |

**只填一家.** 每个进程只跟一个 LLM 后端说话, 由 `.env.defaults` 里的 `LLM_PROVIDER` 决定,
而只有被选中那家的凭证是必需的. 三把 key 都填不会更好, 只是多两个要保管的东西.

选好之后, 把 `.env.defaults` 里那行改成对应的值, 或者在自己的 `.env` 里写一行同名的盖掉它.
`.env` 先读, 所以它赢.

还有第四家 AWS Bedrock, 它不走 API key 而走 AWS 凭据, 配起来多几道手续. 第一次跑先别选它.

### 订阅和 API key 是两回事

这一点每年都要坑掉一批人.
**ChatGPT Plus, Claude Pro 这类月费订阅买的是网页版和客户端的使用权, 不带 API 额度.**
你已经付过订阅费, 不代表你的 API key 能用. API 是单独计费的另一条路, 在各家的开发者控制台
里, 通常叫 API keys 或者 Developer platform.

### 给它设一个花费上限

拿到 key 之后, **在控制台里给这个账号设一个消费上限, 5 美元或者 10 美元**. 这门课大概率
用不完, 一次对话的成本是零点几美分的量级.

这一步不是为了省那几美元, 是**防呆**:

- 一把不小心提交进公开仓库的 key, 会在几小时内被爬到并跑满
- 一段写错的循环可能在你去泡咖啡的时候调用几千次

设了上限, 这两件事的代价就是上限本身, 用完为止. 不设上限, 它是一张空白支票.

### 安全保管

- **存进密码管理器** (LastPass, 1Password, Bitwarden 这类), 不要存在便签或者聊天记录里
- **不要贴进任何聊天窗口**, 包括跟 AI 的对话
- **不要提交进 Git.** 这个仓库把它放在 `.env` 里, 那个文件被 `.gitignore` 排除, 而且
  `.claude/settings.json` 里 deny 了 AI 对它的读和写, 所以你让 AI 帮忙改配置时它碰不到这
  个文件
- **发现泄漏就当场吊销重发一把.** 不要试图评估影响, 吊销是几秒钟的事

### 一步一步, 这条最重要

现在的模型强到可以一口气把整套环境替你配好: 装依赖, 生成 `.env`, 跑完所有命令, 最后告诉

它跑偏了就打断它, 重申一遍这句话. 这不是跟 AI 客气, 这是这门课的学习方式:
**让它解释和验证, 让你动手.**

## 9. 起服务

```bash
mise run dev
```

这一条底下绕了一圈: mise 先跑 `mise run kill` 清掉本 checkout 的旧进程, 然后调 pnpm 的
`concurrently`, 再由它调回 mise 去起两个子任务, 一个 `next dev --port 3000`, 一个
`uvicorn api.index:app --reload --port 8000`.

**mise 调 pnpm 再调回 mise**, 是因为并发跑两个进程这件事用 `concurrently` 最省事, 而它是
一个 node 包.

两件值得知道的事:

**前端端口钉死在 3000.** Next.js 默认在 3000 被占时会跳到 3001, 而 [`next.config.js`](../../next.config.js) 把
`/api/*` rewrite 到写死的 `127.0.0.1:8000`. 于是那个跳过去的前端仍然指着 8000, 而坐在那里的
可能是另一个 checkout 的后端. **起不来比静默接错好.**

**[`package.json`](../../package.json) 里那几个同名 script 不要用.** 它跑起来的东西看着一样, 但少了两件事: 没有
那个用来认出哪些进程是我的的环境变量标记, 也没有先 kill 那一步. 它留着是因为 Vercel 构建
要读 [`package.json`](../../package.json), 日常一律用 `mise run dev`.

两个服务器都起来之后, 打开 `http://localhost:3000`, 你会看到首页. 上下滚一遍, 点一点那
四张能力卡, 看看那个解释气泡.

然后点右上角进 agent 页. 界面会正常显示, 但**点 kickstart 按钮会失败** —— 库里还没有数据.
到这里这一篇就算走完了, 剩下那一半在第 17 到 20 篇.

## 10. 练习

### 练习 1: 走完三步, 停在首页

**目标:** 在自己机器上把前端跑起来.

**怎么做:**

1. `mise run inst`
2. `cp .env.example .env`, 填 `DB_*` 和一个 LLM 凭据
3. `mise run dev`, 等两个服务器都打出就绪日志 (Next.js 打 `Ready in`, uvicorn 打
   `Application startup complete.`, **两条都出现才算起来了**)
4. 打开 `http://localhost:3000`, 首页应该完整渲染
5. 点右上角进 agent 页, 点一个 kickstart 按钮, **看它怎么失败**
6. 读那条失败信息, 想一想它在说什么

**你会观察到:**

第 3 步要等一会儿, 两个服务器的日志会交错着打出来, 顺序每次都可能不一样. 第 5 步会失败,
而失败信息大概率会提到 schema 或者表.

> **关键洞见:** 一个说得清自己缺什么的失败, 比一个含糊的失败值钱得多. 你在第 20 篇会看到
> 这条信息是被人特意写出来的, 不是碰巧.

### 练习 2: 让助教一步一步带你走一段

**目标:** 第一次用这门课的 AI 助教, 并且当场看清一步一步这条纪律为什么重要.

**怎么做:**

1. 敲 `/showcase-learn-cn` 或者 `/about-bi-agent-app-scaffold-cn` 把 skill 加载起来
2. 挑一件你刚才没完全看懂的事, 比如两个配置文件为什么这么切
3. 用这个开场白问它:

```text
请一步一步给我讲清楚这个项目为什么有 .env 和 .env.defaults 两个配置文件.
每讲完一点先停下来, 等我说继续, 再讲下一点. 不要一次性讲完.
```

4. **注意它第一次回答的长度.** 如果它一口气讲完了, 打断它, 把不要一次性讲完再说一遍
5. 然后换一个动手类的请求, 比如让它带你检查 `.env` 里该填的值有没有填全, 同样要求一步一步

**你会观察到:**

AI 的默认倾向是一次性把事情做完 —— 它很强, 而且它以为你要的是结果. 你要反复把它拉回来.

> **关键洞见:** 让它一次做完, 学到东西的是它, 不是你. 这条纪律在这门课里会反复用到, 而且
> 越到后面代码越复杂时越重要.

## 12. 导师寄语

**为什么这一篇的终点定得这么低:**

装依赖, 配密钥, 起服务, 看到首页. 就这么多. 你可能会觉得不过瘾 —— 最有意思的那个 agent
还不能用.

这是有意的. **第一次在一个陌生项目上动手, 最重要的事情是尽快拿到一个正常状态**, 一个你
以后每次出问题都能回头对照的基准. 一口气把所有东西都配完, 中间卡在哪一步都很难判断,
而且你会花两个小时却说不出自己到底走到了哪里.

先让一半亮起来, 剩下一半就变成一件有把握的事了.

**关键洞见:**

- 这个项目里最贵的错误都不报错. 你的第一直觉应该从哪里崩了改成哪里悄悄错了
- 一个配置值该放哪个文件, 只问它是不是密钥. 不要用会不会因机器而异那条线
- 一个能机械判断的坏状态, 应该在启动时抛异常, 而不是写进 README 等人记住
- 让 AI 一步一步来, 是这门课里你要反复用到的一条纪律. 它一次做完, 学到东西的是它不是你
- 把一件大事切成两半分别验收, 比一次做完更容易做对, 也更容易看出自己卡在哪儿

**下一步:**

环境跑起来了, 但你现在对这个仓库的了解还停留在目录名. 第 5 篇
([读一遍这个仓库](../05-read-the-codebase/README-cn.md)) 会带你从上往下读一遍: 两个页面,
一个后端包, 以及一次提问从浏览器出发到底走过了哪些文件.

至于那个还不能用的 agent, 数据那一组 (第 17 到 20 篇) 会把它补上.
