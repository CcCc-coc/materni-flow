# 系统提示词: 把领域知识灌进去

## 1. 目标

拆开 agent 的最后一篇, 讲**脑子**. 前三篇讲的是它能看到什么和能做什么, 这一篇讲它
**应该知道什么** —— 而这是唯一一件框架帮不了你的事.

这份提示词五百多行, **每问一句话就完整重发一次**. 它凭什么值这个钱? 因为它装着别处都没有的
东西: **这门生意的知识**.

**核心是一条取舍.** 提示词里没有一句在教模型写 SQL, 因为模型比你熟. 要写的是它不可能知道的
那一半: 你们的命名, 你们的口径, 你们的阈值, 你们的业务解释. 自查用这一句:

> 一个刚入职, 很聪明, 但完全不了解你们公司的人, 会不会问这个问题?

**练习 1 会让你有点不舒服, 但那是这一篇最真的部分.** 这份提示词里有一个数字和数据库对不上
(风险等级表里 D 级那一行), 而 `mise run cli-check-content` **全绿** —— 它只查表名存不存在,
不看数字. 你会亲手撞一次, 然后看到同一个 agent 用两种问法给出两个不同的答案.

带走的判据是: **散文没有编译器.** 一个事实同时活在散文和数据里, 它就会漂, 问题只是你会不会
发现.

## 2. 要做的事情

1. 读完 README, 重点是第 6 节那条判据, 第 7 节的三段式, 和第 9 节.
2. 开一个叫 `24-the-system-prompt` 的 branch.
3. 打开 `data/system-prompt.md`, 对着第 5 节那张表认一遍它的骨架.
4. 挑三条提示词里的句子, 各判断一次它属于必须写还是该相信模型, 说得出理由.
5. 找到派生指标那一大块, 挑两条对照三段式看: 公式, 怎么解读, SQL 例子, 三段齐不齐.
6. 在那些 SQL 例子里找出 `LEFT JOIN` 和 `100.0`, 想清楚它们在替模型挡什么.
7. 翻到 SQL 方言那一节, 把它和第 19 到 20 篇那条线接起来.
8. 抄下风险等级表里五个等级的假设违约率.
9. 起开发服务器, 在 agent 页问每个风险等级的假设违约率是多少, 要求它查表.
10. 和第 8 步抄的对一遍, 找出对不上的那一行.
11. 换个问法, 让它只根据系统提示词回答, 对比两次结果.
12. 跑 `mise run cli-check-content`, 确认它全绿.
13. 拿出 `tmp/my-target-domain.md`, 为其中一个业务问题写一条三段式的派生指标.
14. 把它贴给 AI, 让它当读者指出哪里要猜, 以及哪句话其实是在教 SQL.

**预计用时:** 70 到 110 分钟

## 3. 检查清单

- [ ] **那条判据会用**: 你能对三条具体内容判断写还是不写, 理由落在那个刚入职的聪明人上.
- [ ] **骨架说得出**: 你能说出提示词由哪几块组成, 并指出哪一块最大.
- [ ] **三段式**: 你能说出派生指标的三段, 并说清中间那段为什么最容易漏而且最值钱.
- [ ] **SQL 例子的作用**: 你能指出例子里的 `LEFT JOIN` 和 `100.0`, 并说清示范优于说明的意思.
- [ ] **方言那一节接上了**: 你能把它和第 19 篇那二十个 SQLite 查询, 第 20 篇那个一份提示词的
      决定连成一条线.
- [ ] **亲手撞到了漂移**: 你找出了那个对不上的数字, 也见过同一个 agent 两种问法两个答案.
- [ ] **检查是全绿的**: 你跑过内容检查确认它没报, 并能说清它查的是表名不是数字.
- [ ] **写过一条自己的**: 你为自己那个行业写了一条三段式的派生指标, 并删掉了其中在教 SQL 的
      部分.
- [ ] **渲染那几节的归属**: 你知道提示词里那一百多行渲染内容属于渲染契约, 不在这一篇讲.
