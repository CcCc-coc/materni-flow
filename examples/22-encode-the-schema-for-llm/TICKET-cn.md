# 把库结构压给模型看

## 1. 目标

拆开 agent 的四篇, 这是第一篇, 讲**眼睛**: 它写任何一句 SQL 之前, 看到的只有一段被压缩过的
字符串, 而那就是它对这个数据库的全部认识.

先跑 `mise run cli-print-db-schema` 看一眼, 再往下读.

这一篇的记号本身十分钟就学得会, **真正的问题在后面**: 那是一次**有损** 压缩, 注释, 默认值,
约束名全被扔了. 所以要问的是 —— **什么必须留, 什么可以扔?** 判据是这一条: 影响模型写 SQL
的留下, 不影响的扔掉.

**练习 2 是这一篇最想让你带走的东西, 而它跟编码没关系.** 那个取库结构的工具, 说明里写着
压缩省了大约 70% 的 token. 你会亲手量一次, 得到一个不一样的数字, 然后想清楚为什么两个都
可能是对的 —— 因为那句话**没有交代跟什么比**.

这条对你以后写代码注释, 设计文档, 甚至简历都成立: **没有基准的百分比不是事实, 是广告词.**
而写给模型看的文字尤其要小心, 因为**同事会怀疑你, 模型不会**.

---

## 2. 要做的事情

1. 读完 README, 重点是为什么结构也不能原样给, 和最后那一节关于百分比的.
2. 开一个叫 `22-encode-the-schema-for-llm` 的 branch.
3. 跑 `mise run cli-print-db-schema`, 把输出存下来.
4. 在输出里各找一个例子: 一个主键, 一个外键 (说出它指向哪张表的哪一列), 一个 `dec` 列,
   一个既非主键也非外键但标了 `*NN` 的列.
5. 想清楚那个 `dec` 列为什么不是 `float`.
6. 数一数一共几张表, 和第 18 篇你画的主线图对一遍.
7. 挑一张表, **不看 ER 文档**, 只根据这段编码用中文写出它是干什么的.
8. 再打开 ER 文档对一下, 记下你漏掉的是哪一类东西.
9. 打开 `agent_app/db_schema/` 三个文件, 各花两分钟确认它们的分工: 谁碰数据库, 谁纯格式化.
10. 打开 `model.py` 开头那段说明, 读那条每个字段都要有读者的规矩.
11. 跑 `01_measure_the_encoding.py`, 记下它给的百分比.
12. 在 `agent_app/one/one_04_agent.py` 里找到那句 `~70%`, 和第 11 步的数字对比.
13. 让 AI 找出这个仓库里其它没交代基准的数字, 逐条判断哪些是真问题.

**预计用时:** 60 到 90 分钟

---

## 3. 检查清单

- [ ] **记号认全了**: 你能读出一行编码里的列名, 类型和每一个标记, 并能指出一个外键指向哪张
      表的哪一列.
- [ ] **`float` 和 `dec` 的区别**: 你能说清它们为什么没有被压成同一个词.
- [ ] **最外层那个方言词**: 你能说清 `postgresql` 这个词在那里干什么, 并把它和第 19 到 20 篇
      那条方言线连起来.
- [ ] **冗余标记**: 你能说出有 `*PK` 就不写 `*NN` 和 `*IDX` 的两条规则, 并说清真正的理由不是
      省字符.
- [ ] **反向翻译做过**: 你只看编码写过一张表的用途, 也知道自己漏掉的是哪一类东西, 以及为什么
      那一类只能靠系统提示词补.
- [ ] **三步单向**: 你能说出三个文件各自干什么不干什么, 并说清中间隔一层换来了什么.
- [ ] **每个字段要有读者**: 你能说清提取一个没人输出的字段, 深一层的代价是什么.
- [ ] **量过压缩率**: 你跑过那个脚本, 记得它给的数字, 也能说清它和 `~70%` 为什么不一样.
- [ ] **那条判据**: 你能复述没有交代基准的百分比不算事实, 并能说出写给模型看时它为什么更要紧.
