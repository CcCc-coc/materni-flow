# 完成核心作品脚手架全部课程

## 1. 目标

走完这门课, 你要建立起的不是**我会写 AI 应用** 这种笼统的感觉, 而是三样具体的东西: 一个真的部署在公网上, 别人点开就能用的应用; 一套你说得清每条边界为什么在那儿的脚手架; 以及一段你能对着别人讲出口, 并且接得住追问的经历.

**它是一个多领域交叉的东西**, 所以你一定会在里面撞见自己没碰过的领域: 数据库设计, agent 的工具与提示词, 前后端接线, 云上部署, 视觉与业务表达. 这门课只带你把每一块做到能跑, 不做到底 —— 但每一块都留着口子. **什么都会一点, 然后按你的目标岗位挑一个往深里挖**, 这是验收的一部分: 你要说得出自己那个方向的口子在哪.

这门课反复出现的那个句式是**坏了不报错**. 走完之后, 你面对任何一个改动时应该会多问一句**它坏的时候我会怎么知道** —— 那比记住任何一处具体实现都耐用.

**最后一件事不能省**: 这个仓库最终是给别人看的. 学完之后要把它排练成一段能讲的故事, 再抹去教学痕迹发布出去. 只学不发布, 等于做完了一个只有你自己见过的项目.

---

## 2. 要做的事情

1. 先读根目录的 README, 明白这门课怎么学, 学完怎么展示.
2. 进 examples, 从 01 开始按编号往下刷, 第一篇会给你整门课的地图.
3. 每个 Task 都照它自己的 TICKET 逐项确认再往下.
4. 走到接上真数据和真模型那一篇时, 注册供应商并在控制台设好消费上限, 注册 Neon, 把 agent 真的点亮一次.
5. 走到换一个行业那两篇时, 真的换一次, 然后数一数后端被改了几个文件.
6. 换完之后写那份 root README, 一千词以内, 作品口吻.
7. 全部刷完后, 用 `/showcase-quiz-cn` 自测, 测到 70% 的题都能思路清晰地答出来.
8. 用 `/showcase-demo-cn` 排练**我是怎么做出这个项目的** 这段故事, 练到能流畅讲完并接住常见追问.
9. 用 `/showcase-publish-cn` 把 repo 抹去教学痕迹, 发布成自己 GitHub 上的 portfolio repo.

**预计用时:** 2200 到 3500 分钟 (也就是 37 到 58 小时, 含注册账号, 造数据与部署的等待时间)

## 4. 关键能力

- 从零把一个前后端同仓库的应用送上公网, 并说清三层配置在云上各走哪条路.
- 把一个陌生数据库读懂: 先分三类找主角, 再顺外键串主线, 最后找出数据库管不了的那些业务规则.
- 把一个行业的业务知识蒸馏成 agent 的系统提示词, 并判断什么必须写, 什么该相信模型自己会.
- 给 agent 定工具边界: 说明就是接口, 而只读该建立在机制上而不是规则清单上.
- 认出那一整类不报错的失败, 判断一个坏状态该当场抛异常还是返回一句话给模型, 以及一件事该做成自动检查还是该改变产生它的顺序.
- 守住跨语言的约定: 编译器管不着的地方, 要么自己造检查, 要么自己造顺序.
- 在几个小时之内把整套东西换成另一个行业, 并说得清那个换得成立是靠哪些边界撑住的.
- 把方向和验收交给 AI 去执行, 自己做那个给判据和验收的人.
- 把这段经历讲成一个别人听得懂的故事, 并在被追问时说得出你为什么没有采纳另一种做法.
- 指出这八个方向里你那一条的口子具体落在哪个文件上, 以及往下深挖要动什么, 什么完全不用动.
