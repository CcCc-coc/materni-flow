# 换行业的 AI 数据分析脚手架 讲故事

> showcase-demo-cn skill 靠这份文档找到讲故事底稿, 并知道你想怎么排练. 底稿本身 (七幕, 常见追问, 按听众裁剪) 不在这里, 在它指向的那个 Task 里.

## 1. 底稿位置

底稿就是 demo 那个 Task 的 README: [examples/42-how-i-build-this](../../examples/42-how-i-build-this/README-cn.md). 它用第一人称讲这个 repo 是怎么学出来又做出来的.

注意它**不是 `examples/` 的最后一个** —— 后面还有一个收尾 Task (examples/43).

## 2. 默认主线

**这个 repo 的底稿偏离了默认七幕, 而且是整条主线都换了.**

默认那七幕讲的是"我如何用 AI 快速把一个技能学会并投入实战" (发现技能值得学, 让 AI 翻资料, 蒸馏成 skill, 设计大纲, 大纲变例子, 刷完, 用到真实问题).

**这份底稿讲的是这个产品本身怎么被造出来的**, 七幕是:

1. 学业务 —— 先把这门生意搞明白
2. 探数据库 —— 把库摸一遍
3. 梳理 data dictionary —— 整理成一份数据字典
4. 蒸馏提示词 —— 把字典蒸馏成 agent 的系统提示词
5. 搭 agent —— 工具, 循环, 只读边界
6. 定数据协议 —— 前后端那份渲染契约
7. 上线并换行业验证 —— 部署, 然后真的换一个行业证明它可复用

排练的时候按这七幕走, **不要套默认那一套**.

底稿里还有三样默认七幕没有的东西, 都要一起练:

- **开场五分钟是一条固定路线, 要背下来**: 首页 -> 点业务背景入口 -> 四张能力卡 -> 进 chat 先点一个出图的 -> 回代码看 agent -> 引出 `db_schema` -> 落到 `data/` 收尾. 判据是**先让对方看见结果, 再回头看它为什么成立**. 第二步最容易被跳过, 而跳过它对方就只能看见一个会画图的聊天框
- **开场之前有一段清场默念**: 确认你打开的是哪个 repo (你有两个, 对着人只开 demo 那个), 教学目录清没清掉, 根 README 讲的是项目还是课
- **权属那一类的说法一律给两个版本加一条自己能验的判据**, 不给含糊版. 开场那一句 (实习做的还是自己课余做的) 是这样, 架构设计那一句更是 —— 判据是你能不能把每一个设计说清楚, 并且说得出你为什么没有采纳另一种做法

## 3. 排练自定义

没有特殊要求, 按 showcase-demo-cn skill 默认来.

两条这份底稿自带的约定, 排练时照着办:

- **领域词是可替换的.** 底稿的例子用当前这份小微企业放贷数据集, 而学生大概率已经换过行业了. 换过就把所有领域词换成自己那个行业的, **讲法一模一样, 只是名词不同**
- **数据从哪来这个问题一定会被问到**, 而且答案要主动给: 这份数据是我按这个行业的业务逻辑自己造的. 主动说明合成数据是加分项, 支支吾吾才扣分
