# 这是什么项目

## 一句话

一个**可以一键换掉整个业务领域**的 AI Agent 应用脚手架: 一个多表数据库, 一个能用自然
语言操作它的 agent, 一个把"这在解决什么问题"讲清楚的网站. 三样东西一起换, 换完就能发布.

## 技术形态

| 层 | 用什么 |
| :--- | :--- |
| 后端 | Python + FastAPI, Strands Agents SDK |
| 前端 | TypeScript + Next.js, 部署在 Vercel |
| 数据库 | PostgreSQL (Neon), 多表, 带真实外键关系 |
| 模型 | 四家可切 (OpenAI 默认, Anthropic, Google, AWS Bedrock), 换一个环境变量的事 |
| 云 | Vercel 部署, AWS DynamoDB 记账 (LLM 花费配额), Bedrock 可选 |

它**一定连着一个表很多的数据库**. 这不是可选项, 是这个脚手架的前提: agent 的价值来自
"人问不出来的跨表关联", 单表的东西用不着 agent.

## 默认就有的能力

用户在聊天框里问业务问题, agent 读库结构, 写 SQL, 跑, 然后用业务语言解释结果. 具体能
产出四种东西:

- **业务问答**: 写查询回答"哪个风险等级定价错了", 而不是把一堆数字丢回去
- **表格**: Markdown 表格, 需要时连 SQL 一起给, 让读者能验算
- **流程图**: Mermaid, 用来讲生命周期, 漏斗, 状态流转
- **图表**: 柱状图和折线图, 用来讲排名, 趋势, 两个量之间的差距

这四样在提示词和前端之间有一份**契约** (触发短语 -> 渲染块), 不是"模型看着办". 细节见
[04-rendering-contract.md](04-rendering-contract.md).

## 麻雀虽小, 五脏俱全

这句话是这个项目的定位. 它不是 demo, 也不是完整产品, 它是**一个所有关键器官都长齐了的
最小活体**: 真数据库, 真 agent, 真前端, 真部署, 真配额控制, 真校验脚本. 每一样都不深,
但每一样都在, 而且互相接得上.

这个性质决定了它的用法: **你往任何一个方向深挖, 都不用从零开始.**

## 六个深化方向

同一个脚手架, 看你是什么岗位, 往下挖的地方完全不同. 每个方向都能复用大约 80% 的现成
代码, 你的精力全部花在那 20% 的增量上.

| 你是 | 往哪深挖 |
| :--- | :--- |
| **Business Analyst** | 在商业分析上加硬货: 严肃的分析框架, 因果推断, 决策框架. 让 agent 不只是查数, 而是能回答"该不该做" |
| **Software Engineer** | 把模块搬上云, 补 Ops: CI/CD, 可观测性, 灰度, 容量. 把它从"能跑"做到"能被运维" |
| **Data Engineer** | 补 data wrangling 和 data pipeline, 做一套管理后台数据集的东西, 让数据是流进来的而不是种子文件 |
| **Data Scientist** | 深化机器学习模型, 或者加一整套 A/B test 实验设计 pipeline |
| **AI Engineer** | 把核心 AI 组件拆成 MCP, 上 AgentCore 之类的托管, 补 guardrail, evaluation, harness |
| **UX Designer** | 深化交互: 文件下载, 结果预览, 会话管理, 让它从"能用"变成"好用" |

## 为什么这件事值钱

**第一, 脚手架本身就够硬.** 它在简历上已经是一个说得出口的项目: 有真数据库, 有 agent,
有前端, 有线上地址. 而且它不绑定行业, 投什么岗位都能拿出来讲.

**第二, 也是更关键的一点: 换领域的成本被压到了极低.**

这个仓库配了一套**换数据集**的流程 (`swap-dataset-cn` skill). 因为整个项目是高度模块化
设计的, 改一个地方不会波及其他地方, 所以把现在这个 small business lending 示例, 换成
任何别的 use case ——**哪怕再冷门**—— 都是可行的. 前端文案, 后端提示词, 网站首页, 数据
本身, 业务说明, agent 的领域知识, 一次全部换掉, 换完直接发布.

这带来的是一个别人做不到的打法:

> **针对某个具体岗位, 做出那个岗位所在行业和公司真正会做的项目, 从做出来到部署上线到
> 进作品集到改简历, 1 到 2 小时走完.**

别人准备一个像样的作品集项目要三个月. 有这个脚手架, 你可以针对每一次投递做一个专属的.
这就是脚手架的威力, 也是这个项目存在的全部理由.

## 一句提醒

上面那个"1 到 2 小时"成立, 有个前提: **模块边界不能被破坏.** 每一次"就这一次, 先在组件
里写死一个字符串"或者"这个值先放这里以后再挪", 都是在把下一次替换的时间从 2 小时推向
2 天. 边界具体在哪, 见 [02-modular-design.md](02-modular-design.md).
