# 这个界面是什么, 必须做到什么

> 前端只有两个页面, 但它们服务两种完全不同的读者: 一个**没听说过这个行业的陌生人**, 和
> 一个**要真的拿它查数的人**. 这篇讲这两件事分别意味着什么要求, 后面几篇讲代码怎么满足它们.

**对应代码**: `app/`, `components/`, `lib/`, `data/`

---

## 两个页面, 两种读者

| 路由 | 给谁看 | 它要回答的问题 |
| :--- | :--- | :--- |
| `/` | **陌生人**: 面试官, 招聘方, 任何点开链接的人 | "这是干什么的? 这个行业有什么值得做的问题?" |
| `/chat` | **使用者** | "我能问什么? 问了会得到什么形状的答案?" |

这个划分不是网站惯例, 是这个项目的用途决定的. 它最终会被放进作品集里给人看
(见 [architecture/01](../architecture/01-what-this-project-is.md)), 而看它的人**大概率不懂
这个数据集所在的行业**. 一个直接把人扔进聊天框的产品, 对他们等于一个空白输入框.

所以首页的职责不是"介绍功能", 是**把一个外行带到能提出第一个问题的位置**.

---

## 首页必须做到的四件事

**一, 用一句话说清这是什么.** 大标题 + 副标题 + 一段介绍, 三层递进, 都是数据集的文案.

**二, 把四条业务主线讲成外行能懂的话.** 这是首页最难的部分, 因为业务主线的名字
("Risk Pricing", "Portfolio Concentration") **对内行精确, 对其他所有人等于没写**. 所以每条
主线是三层:

```
title     概念名           对内行精确
subtitle  一句白话         陌生人先读到的是这句
tooltip   两三句解释       hover / 键盘聚焦 / 手机点按时弹出
```

**三, 留一个入口讲完整的行业背景.** 一段话装不下一门生意. 但它也不值得占一个路由, 更不能
把行动召唤挤到折叠线以下 —— 所以是一个覆盖层.

**四, 让人知道背后是真数据.** 表数和行数写在页面底部. 这一句是读者判断"这个 demo 有多真"
的地方, 所以它必须是数出来的而不是估的.

---

## agent 页必须做到的四件事

**一, 空状态不能是空的.** 一个只有输入框的聊天页, 用户不知道能问什么. 所以未开始对话时
显示的是同样那四条业务主线 —— **和首页同一份数据, 同一个组件**.

**二, 给出 12 个可以直接点的问题.** 它们不是"常见问题列表", 是**橱窗**: 四类各三条, 分别
产出表格 / 流程图 / 图表 / 纯文字. 随手写 12 个问题的结果一定是 12 段纯文字, 于是流程图和
图表渲染器谁也看不见.

**三, 按下之前就告诉人会画出什么.** 每个按钮带一个小图标 (表格 / 流程 / 柱状), 因为十二个
按钮长得一模一样, 不给标记的话唯一的办法是**按一个然后等模型回答**.

**四, 把 agent 的一段纯文本变成表格, 流程图和图表.** 这是 chat 页真正的技术内容, 见
[07](07-markdown-and-blocks.md).

---

## 四条贯穿全部的硬要求

### 1. 换数据集时前端一行代码都不改

界面上说的每一句话都在 `data/site.toml` 里. 组件里**不许出现任何一句业务文案** —— 这条被
破坏过一次, 代价是聊天页的欢迎语在屏幕上印了两遍 (详见 [03](03-content-pipeline.md)).

### 2. 流式期间不能崩

agent 的回答是一个字一个字到达的, 所以在它写完之前, 页面上一定存在**没有闭合的围栏块**:
一段还没写完的 mermaid 语法, 一个还没闭合的 JSON. 这不是异常情况, 是**每一次回答的必经
状态**.

所以块渲染器的失败路径不是错误处理, 是**正常路径**: 解析不了就退回显示原始代码, 等收完了
再变成图. 见 [07](07-markdown-and-blocks.md).

### 3. 两个页面都是构建期静态生成的

`next build` 之后两个路由都是 `○ (Static)`. 文案和业务说明在**构建时**从磁盘读进来烘进
产物, 请求期不读盘. 这也是为什么读 `data/` 的代码必须是 server-only 的.

### 4. 陌生人看不到任何"这是一份作业"的痕迹

没有作者名, 没有头像, 没有课程或作业字样, 页面元数据里也没有 `author` / `creator`.
这个站点展示的是一个产品, 不是一个人.

---

## 这个界面**不做**什么

写清楚边界, 免得下一个人以为是漏了:

| 不做 | 为什么 |
| :--- | :--- |
| 登录 / 用户系统 | 谁都能打开. 花钱的控制在后端的月度配额上, 不在前端 |
| 会话持久化 | 刷新就没了. 对话状态由 AI SDK 存在浏览器内存里, 后端无状态 (见 [backend/09](../backend/09-http-entry-point.md)). `localStorage` 只存输入框里没发出去的草稿 |
| 暗色模式 | 没有切换开关, 所以也没有 `dark:` 变体. 详见 [08](08-design-tokens.md) |
| 多语言 | 界面是英文的. 中文只出现在这些文档里 |
| 上传文件 / 多模态 | 输入框组件叫 `MultimodalInput` 是上游模板的名字, 它只收文本 |

最后一条值得单独记一笔: **名字来自模板, 不是承诺.** 这个前端是从一个个人作品集模板改出来
的, 类似的残留清理过一轮 (见 [08](08-design-tokens.md) 末尾), 但组件名保留了.
