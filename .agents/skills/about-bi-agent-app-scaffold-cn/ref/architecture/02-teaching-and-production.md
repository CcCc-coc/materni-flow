# 教学层和生产层

> 这个仓库同时是一个**可以拿出去展示的应用**和一门**教怎么造出它的课**. 这篇讲两者
> 在目录上怎么分开, 以及"擦掉教学痕迹"为什么必须退化成"删几个目录".

## 为什么要分

[01](01-what-this-project-is.md) 说了这个脚手架的最终用途: 学生学完之后, 把它换成自己
目标岗位的领域, 部署上线, 放进作品集, 写进简历. 那一刻这个仓库的读者不再是学生本人, 是
**面试官**.

面试官打开它, 期待读到的是一个工程师写的生产代码库. 如果他读到的是一份带练习题的课件 ——
docstring 里在讲"什么是 mixin", 目录里躺着 `TICKET.md` 和验收清单, 测试文件里写着"这一课
的 TDD 练习" —— 那这个项目立刻从"我做的产品"降级成"我上过的课".

所以这个仓库需要一个动作: **擦掉教学痕迹.** 而这个动作的质量, 完全取决于两层分得有多干净.

## 两种分法, 只有一种能用

**混在一起的分法**: 教学内容散在 docstring 和注释里, 教学脚本混在 `mise.toml` 里, 教学
依赖混在 `pyproject.toml` 里, 造数据的代码混在业务模块里. 擦除的动作是"逐个文件去看哪句
话是教学的然后删掉". 这件事**改代码**, 所以有风险; 而且一定删漏, 因为没人能证明自己删干净了.

**分层的分法**: 教学的东西整块住在自己的目录里. 擦除的动作是 `rm -rf` 几个路径, 剩下的
仍然是一个能跑的 app. 这件事**不改一行代码**, 所以零风险, 而且可验证 —— 删完跑一遍测试和
`mise run check-content` 就知道.

这个仓库选第二种, 而这个选择反过来对代码提了一堆约束. 下面就是那些约束.

## 哪些是教学层

| 路径 | 是什么 |
| :--- | :--- |
| `README.md` / `README-cn.md` / `TICKET.md` | 这一课教什么, 任务和验收清单 |
| `docs/` | 教学正文和开发者走读 |
| `.agents/skills/` | 给 AI 和维护者看的规范 (就是你正在读的这些) |
| `dataset/` | 数据集的源材料和生成器, 见 [03](03-the-dataset.md) |
| `agent_app/dataset.py` | 造数据 + 同步到 PostgreSQL 的代码 |
| `tests_python/test_dataset.py` | 上面那个模块的测试 |
| `scripts/` | 编号的安装与连通性验证脚本 (配置自检, 跑 SQL, 同步, 逐个 LLM 供应商探活) |

删掉它们之后剩下的是: `agent_app/` (除 `dataset.py`), `api/`, `app/`, `components/`,
`lib/`, `data/`, 以及 `.env.defaults` —— 一个连着 PostgreSQL 的 agent 应用.

**`mise.toml` 一行都不用动.** 每个任务要么跑的是应用本身, 要么跑的是
`agent_app/` 里的东西, 没有一个指向 `scripts/`.

`check-content` 值得单独说一句, 因为它看起来最像会被牵连的那个: 它检查的四项里有两项要读
SQLite 种子, 而种子属于教学层. 所以 `agent_app/content_check.py` 的 `seed_tables()` 把那个
import **放在函数体里**并接住 `ImportError`, 两项降级成 SKIP, 其余两项照常跑.

**这不是为了少改一行配置**, 是因为剩下那两项 (内容文件在不在, 12 条 kickstart 的渲染配额对
不对) 在一个交付出去的仓库里**仍然有意义**: 它们守的是 `data/` 和前端之间的契约, 和课程无关.
一个模块级的 import 会让整条命令在教学层消失的那一刻带着 traceback 死掉, 于是连那两项一起
陪葬.

## 支撑这条边界的四条约束

### 1. 生产路径不 import 教学层

`agent_app/one/*.py` 和 `ai_sdk_adapter.py` —— 也就是一个 HTTP 请求真正走过的代码 ——
一行都不 import `agent_app.dataset`. agent 通过 `one.engine` 读 PostgreSQL, **数据怎么进
去的不是它的事**.

这条有测试守着 (`TestNotOnTheProductionPath`), 它用 AST 扫这几个文件的 import. 靠人自觉
守不住: 有一天有人想"顺手在启动时检查一下数据库有没有数据吧", 那一行 import 就把整个应用
钉死在教学层上了.

### 2. 教学自动化不进 `mise.toml`

造数据集, 同步到 PostgreSQL, 逐表核对 —— 这三条命令在
`.agents/skills/about-bi-agent-app-scaffold-cn/scripts/teaching_cli.py`, 不在 `mise.toml`.

理由就是上面那条: `mise.toml` 跑的是**应用** (装依赖, 起服务, 跑测试). 教学层要能靠删目录
擦掉, 不该在一个共用配置文件里留下需要一行行挑出来删的残渣.

### 3. 教学依赖不进 `pyproject.toml`

生成器要 `polars` / `faker` / `pandas` / `pyarrow`, 这些写在 `dataset/requirements.txt`,
装进同一个 venv, 但**不出现在 `pyproject.toml` 里**. 同一个理由: 一个文件删掉, 而不是从
依赖列表里挑几行出来.

副作用是好的: 生产部署 (Vercel) 不会去装一个造假数据的库.

### 4. 代码里不出现指向教学材料的指针

**这条是单向的**: 教学文档可以随便引用代码路径, 代码**一律不引用教学文档**.

```python
# 不要: 擦掉 skill 之后, 这句话指向一个不存在的文件
"""...完整格式规范见 .agents/skills/xxx-cn/ref/backend/04-schema-encoding.md"""
```

这种指针擦除时既不报错也不失败, 只是变成一句死链躺在成品里 —— 而且它明明白白写着
"这个项目是从一门课里长出来的". 代码里只留很短的工程 why, 展开的部分放在文档里, **靠内容
自己站住, 不靠交叉引用**. 规矩本身见 [09](09-comments-and-docs.md).

例外是**功能性的命令提示**: `dataset.py` 里的 `GEN_HINT` 告诉你哪条命令能重建数据库, 那
是错误信息的一部分, 不是文档指针. 而且它住在教学模块自己里, 一起删.

## 一条落地的判断

要往仓库里加东西时, 问一句:

> **它是这个 app 的一部分, 还是教怎么造这个 app 的一部分?**

后者就找一个**整块能删掉的地方**放, 不要塞进任何一个前者要用的文件. 拿不准的时候, 想象
一下删除的那一刻: 你是 `rm -rf` 一个目录, 还是打开文件逐行看?
